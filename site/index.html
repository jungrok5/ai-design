글과 화면에 남는 AI 흔적을 수정 직후에 걸러 냅니다

AI가 쓴 글과 만든 화면은 내용이 정확해도 과장된 수식어, 번역투, 보라색 그라데이션 같은 흔적으로 드러납니다. ai-design은 이 흔적을 규칙으로 검사하고, 규칙으로 판단할 수 없는 부분은 두 스킬이 맡습니다. 어느 프로젝트에나 붙일 수 있습니다.

  • 스킬 2
  • 검사 규칙 57
  • Python 표준 라이브러리만 사용
  • MIT
Claude Code에 설치
claude plugin marketplace add jungrok5/ai-design
claude plugin install ai-design@ai-design
파일을 수정할 때마다 일어나는 일

  1. AI가 글이나 화면 파일을 수정

  2. 훅이 규칙 57개로 검사, 약 0.1초

  3. 위반 내용을 AI에게 반환, 차단하지 않음

  4. AI가 그 자리에서 수정

  5. 의도한 표현은 사람이 예외로 표시

    사람

  6. 커밋과 PR에서 pre-commit과 CI가 같은 규칙으로 재검사

01

구성

기계로 판별할 수 있는 것은 검사 규칙으로, 판단은 스킬로 나눴습니다. 규칙이 잡는 내용을 스킬에 다시 적지 않습니다.

  1. 1

    polish-writing 스킬

    한국어·영어 글을 다듬습니다. 문서는 합니다체 하나로 쓰고, 사실과 숫자를 지어내지 않으며, 내용에 맞는 형식(문단, 명령, 도식, 표)을 고릅니다.

    plugins/ai-design/skills/polish-writing/SKILL.md
  2. 2

    polish-ui 스킬

    화면 작업을 디자인 시스템에서 시작합니다. 프로젝트에 토큰이 있으면 그것을, 없으면 Clear를 씁니다. 접근성과 한글 타이포그래피 최소 기준을 지킵니다.

    plugins/ai-design/skills/polish-ui/SKILL.md
  3. 3

    디자인 시스템 Clear

    라이트와 다크 토큰, ds- 컴포넌트, 복사 버튼, 테마 전환입니다. 이 페이지도 Clear만으로 만들었습니다.

    plugins/ai-design/skills/polish-ui/design/
  4. 4

    스타일 검사

    스크립트 하나가 규칙 57개를 검사합니다. Claude Code 훅, pre-commit, 명령줄, CI에서 같은 규칙으로 동작합니다.

    plugins/ai-design/style/style_check.py · rules.toml
02

설치

쓰는 도구에 맞는 방법 하나를 고릅니다. 팀 프로젝트라면 Claude Code 등록과 pre-commit을 함께 쓰면 사람의 커밋과 다른 AI 도구의 변경도 같은 기준으로 검사됩니다.

Claude Code, 팀 전체에 자동 적용

프로젝트의 .claude/settings.json에 등록하면 팀원이 레포를 열 때 플러그인이 켜집니다.

{
  "extraKnownMarketplaces": {
    "ai-design": { "source": { "source": "github", "repo": "jungrok5/ai-design" } }
  },
  "enabledPlugins": { "ai-design@ai-design": true }
}

pre-commit

.pre-commit-config.yaml에 추가합니다. Python 3.11 이상이 필요하고, rev는 1.0.0 커밋입니다.

- repo: https://github.com/jungrok5/ai-design
  rev: d8c880fc9e08c0edc6c8850873009e22776c5200
  hooks:
    - id: ai-design-style

명령줄과 CI

error가 있으면 종료 코드 1을 돌려주므로 CI 단계로 그대로 씁니다.

git clone --depth 1 https://github.com/jungrok5/ai-design ~/.ai-design
python3 ~/.ai-design/plugins/ai-design/style/style_check.py README.md docs/*.md

Cursor, Copilot 등 다른 도구

도구복사할 파일위치
AGENTS.md를 읽는 도구adapters/AGENTS.snippet.md프로젝트 AGENTS.md에 붙여 넣기
Cursoradapters/cursor/ai-design.mdc.cursor/rules/
GitHub Copilotadapters/copilot/ai-design.instructions.md.github/instructions/
03

글 기준

문서는 합니다체 하나로, 목록과 표는 개조식으로 씁니다. 칭찬하는 형용사는 숫자, 조건, 동작으로 바꾸고, 바꿀 수 없으면 지웁니다.

전후걸리는 규칙
혁신적인 AI 기반 분석으로 브랜드 경쟁력을 강화하세요URL을 입력하면 AI 검색 답변에 해당 사이트가 몇 번 등장하는지 보여 줍니다ko-hype
이 API를 통해 결제 정보를 조회할 수 있습니다이 API로 결제 정보를 조회합니다ko-tonghae
결론적으로 Redis는 최적의 선택입니다Redis는 읽기 응답이 1 ms 이하이므로 세션 저장소로 사용합니다ko-closing-formula
라벨만 붙이면 일이 알아서 흘러가요라벨을 지정하면 워크플로가 상태를 변경하고 구현을 시작합니다ko-personify, ko-haeyo
걱정하지 마세요, 어렵지 않아요(삭제)ko-reader-talk

내용 형식

같은 사실을 문단, 표, 도식에 반복하지 않습니다. 내용의 종류가 형식을 정합니다.

내용형식
이유와 설명짧은 문단
독자가 실행할 것복사 버튼이 있는 명령 블록
3단계 이상의 순서, 행위자가 둘 이상인 흐름도식 먼저, 문단은 조건과 예외만
비교와 기준표
04

화면 기준

AI가 만든 화면이 서로 비슷해 보이는 이유는 매번 기본값에서 색과 모양을 새로 정하기 때문입니다. 그래서 화면은 토큰과 컴포넌트에서 시작합니다.

--bg
--fg
--accent
--accent-soft
--surface
--code-bg

위 색은 지금 테마의 값입니다. 상단의 다크 모드 버튼을 누르면 그래파이트 값으로 바뀝니다.

기본사람통과경고차단
메모놓치면 안 되는 한 가지만 적습니다. 그림자와 옆 색 띠 없이 바탕색으로 구분합니다.
하지 않는 것대신 하는 것
보라·남색 그라데이션, 글자에 그라데이션강조색 하나를 동작과 상태에만
모든 곳에 큰 모서리와 같은 그림자크기별 모서리 6·8·10 px, 1 px 선
카드 왼쪽의 색 세로 띠테두리, 바탕 단계, 제목으로 구분
이모지 아이콘, 모든 링크 끝의 화살표SVG 아이콘, 동작을 말하는 라벨
토큰 밖의 색상값과 글꼴 지정var(--accent), var(--font-sans)
05

검사 규칙

error는 거의 항상 잘못된 표현이라 실패로 처리하고, warning은 맥락을 보고 판단하도록 알림만 표시합니다.

대상errorwarning예
한국어 글1313과장 수식어, 번역투, 해요체 혼용, 의인화, 독자에게 말 걸기
영어 글84sales language, AI vocabulary, stock closers
언어 공통11목록·제목 앞 이모지, 대시 남용
UI 마크업512보라 그라데이션, 그라데이션 글자, 확대 차단, 토큰 밖 색상값

프로젝트별 조정

프로젝트 루트의 .style/rules.toml에 같은 형식으로 규칙을 추가하거나 끕니다. 해요체를 쓰기로 한 제품 화면은 다음처럼 해요체 규칙만 끄고, 한 문서 안의 문체 혼용 검사는 유지합니다.

[[rule]]
id = "ko-haeyo"
severity = "off"

전체 목록은 style_check.py --list-rules로 확인합니다. 기준 전문은 docs/standard.md에 있습니다.
