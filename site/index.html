AI 티 나는 표현을 찾아 줄 번호와 함께 알립니다

AI 도구가 쓴 글과 화면 코드에서 과장 수식어나 보라색 그라데이션 같은 표현을 정규식 규칙으로 찾고, 파일과 줄 번호, 고칠 방향을 출력합니다. 규칙으로 판단할 수 없는 문맥은 Claude Code 스킬 두 개(polish-writing, polish-ui)에 지침으로 적었습니다.

필요한 것: Python 3.11 이상. 검사 대상: Markdown, HTML, CSS, JSX/TSX, Vue, Svelte. 라이선스: MIT.

Claude Code에 설치
claude plugin marketplace add jungrok5/ai-design
claude plugin install ai-design@ai-design
입력: draft.md
실제 출력
$ python3 style_check.py draft.md

Claude Code 안에서의 순서

훅은 수정을 막지 않으므로 일부러 인용한 나쁜 예시도 그대로 저장됩니다. 그런 줄에는 style-ignore를 표시해 다음 검사에서 빠지게 합니다.

파일마다 5회씩 실행한 중앙값은 5–18 KB 파일에서 0.07–0.11초였습니다(4코어 클라우드 VM, Python 3.13).

  1. Claude가 글이나 화면 파일을 수정
  2. PostToolUse 훅이 style_check.py 실행
  3. 검사 결과를 Claude에게 전달
  4. Claude가 같은 턴에서 수정
  5. 의도한 표현이면 사람이 style-ignore 표시사람

사용 전후

같은 사실을 고치기 전과 후로 나란히 놓고 둘 다 검사했습니다. "후"는 polish-writing과 polish-ui의 지침대로 다시 쓴 것이며, 원문에 주어진 제품 사실만 썼습니다.

글: 랜딩 페이지 소개 문단

주어진 제품 사실: URL을 입력하면 ChatGPT, Perplexity, Gemini 답변에 사이트가 인용되는지 검사하고 고칠 항목을 알려 줌.

전: landing-before.md
$ python3 style_check.py landing-before.md
후: landing-after.md
$ python3 style_check.py landing-after.md

화면 코드: 제품 첫 화면

주어진 제품 사실: 읽기 지연 1 ms 미만(p99, 단일 노드 벤치마크), 명령 예시 SET user:1 "kim".

전: card-before.html
$ python3 style_check.py card-before.html
후: card-after.html
$ python3 style_check.py card-after.html
후 화면을 Clear로 그린 모습

검사기는 표현을 찾을 뿐 색과 모양을 고르지 않습니다. 색과 모양은 polish-ui 스킬이 프로젝트의 디자인 토큰에서 고르고, 토큰이 없으면 기본 디자인 시스템 Clear를 씁니다. 이 페이지의 색, 글꼴, 간격도 Clear 토큰입니다(소스).

설치

팀 프로젝트라면 Claude Code 등록과 pre-commit을 같이 씁니다. pre-commit은 사람이 한 커밋과 다른 AI 도구가 만든 변경도 검사합니다.

Claude Code, 팀 전체
프로젝트의 .claude/settings.json에 등록하면 팀원이 레포를 열 때 플러그인이 켜집니다. 
{
  "extraKnownMarketplaces": {
    "ai-design": { "source": { "source": "github", "repo": "jungrok5/ai-design" } }
  },
  "enabledPlugins": { "ai-design@ai-design": true }
}
pre-commit
.pre-commit-config.yaml에 추가합니다. rev는 고정할 커밋 SHA입니다. 최신 값은 pre-commit autoupdate로 받습니다. 
- repo: https://github.com/jungrok5/ai-design
  rev: 
  hooks:
    - id: ai-design-style
명령줄, CI
error가 하나라도 있으면 종료 코드 1을 돌려줍니다. 
git clone --depth 1 https://github.com/jungrok5/ai-design ~/.ai-design
python3 ~/.ai-design/plugins/ai-design/style/style_check.py README.md docs/*.md
Cursor, Copilot, AGENTS.md
adapters/의 규칙 파일을 각 도구의 규칙 폴더에 복사합니다. 이 도구들에는 수정 직후 검사가 없습니다.

한계

  • 정규식이라 문맥을 모릅니다. "~을 통해"가 자연스러운 문장도 있어서 이런 규칙은 경고로만 둡니다.
  • 일부 규칙은 한 파일에 여러 번 나올 때만 알립니다(max_per_file). 예를 들어 "~을 통해"는 세 번째부터 경고합니다.
  • 문장만 검사합니다. 페이지 전체 구성(섹션 반복, 사실 중복)은 검사하지 않습니다.
  • 한국어 규칙은 합니다체 문서를 기준으로 합니다. 해요체를 쓰는 제품 화면은 ko-haeyo 규칙을 꺼야 합니다.
  • 영어 규칙은 개로 한국어 개보다 적어, 영어 문서만 있는 레포에서는 잡는 범위가 좁습니다.
  • 광고 문구처럼 의도적으로 수사를 쓰는 글에는 맞지 않습니다.

규칙을 끄거나 추가할 때는 프로젝트 루트의 .style/rules.toml에 플러그인의 rules.toml과 같은 형식으로 적습니다. 현재 규칙은 한국어 개, 영어 개, 언어 공통 개, 화면 코드 개로 모두 개이고, 전체 목록은 style_check.py --list-rules로 확인합니다.

[[rule]]
id = "ko-haeyo"
severity = "off"
