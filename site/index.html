AI 티 나는 표현을 찾아 줄 번호와 함께 알립니다

과장 수식어, 번역투, 보라색 그라데이션처럼 AI가 쓴 티를 내는 표현을 정규식 규칙으로 검사합니다. Claude Code에서는 파일을 고칠 때마다 결과가 AI에게 전달됩니다. AI는 출력을 보고 같은 턴에서 고칩니다. 규칙으로 판단할 수 없는 문맥은 스킬 두 개(polish-writing, polish-ui)가 맡습니다.

필요한 것: Python 3.11 이상. 검사 대상: Markdown, HTML, CSS, JSX/TSX, Vue, Svelte. 라이선스: MIT.

Claude Code에 설치
claude plugin marketplace add jungrok5/ai-design
claude plugin install ai-design@ai-design
입력: draft.md
실제 출력
$ python3 style_check.py draft.md

만든 이유

팀 템플릿 레포 ai-code-collaboration-best-practices의 문서와 해설 페이지를 AI 도구로 쓰다 보니, 리뷰 때마다 같은 지적이 반복됐습니다. 문서에 해요체와 합니다체가 섞이고, "일이 흘러가요" 같은 문장이 들어가고, 카드 왼쪽에 색 띠가 붙었습니다.

반복된 지적 가운데 정규식으로 잡히는 것은 규칙으로 옮겼습니다. 문맥을 봐야 하는 지적은 스킬 문서에 적었습니다. 다른 프로젝트에서도 쓰려고 2026년 10월 이 레포로 분리했습니다. 아직 첫 버전이고, 위 템플릿 레포에서만 써 봤습니다.

Claude Code 안에서의 순서

훅은 수정을 막지 않습니다. 결과를 AI에게 알리기만 하고, 고칠지는 AI와 사람이 정합니다. 일부러 인용한 나쁜 예시는 그 줄에 style-ignore를 표시합니다.

5–18 KB 파일 하나를 검사하는 데 0.07–0.11초가 걸렸습니다(4코어 클라우드 VM, Python 3.13, 5회 실행의 중앙값).

  1. AI가 글이나 화면 파일을 수정

  2. PostToolUse 훅이 style_check.py 실행

  3. 위반 위치와 고칠 방향을 AI에게 전달

  4. AI가 같은 턴에서 수정

  5. 의도한 표현이면 사람이 style-ignore 표시

    사람

화면 코드도 같은 방식으로 검사합니다

AI 코딩 도구가 자주 만드는 첫 화면을 그대로 넣은 결과입니다. 검사기는 색과 모양을 고르지 않습니다. 고를 때는 polish-ui 스킬이 프로젝트의 디자인 토큰을 먼저 찾고, 토큰이 없으면 이 레포의 기본 디자인 시스템 Clear를 씁니다. 이 페이지도 Clear의 토큰과 컴포넌트만 씁니다(소스).

입력: card.html
실제 출력
$ python3 style_check.py card.html

설치

팀 프로젝트라면 Claude Code 등록과 pre-commit을 같이 씁니다. pre-commit은 사람이 한 커밋과 다른 AI 도구가 만든 변경도 검사합니다.

Claude Code, 팀 전체
프로젝트의 .claude/settings.json에 등록하면 팀원이 레포를 열 때 플러그인이 켜집니다. 
{
  "extraKnownMarketplaces": {
    "ai-design": { "source": { "source": "github", "repo": "jungrok5/ai-design" } }
  },
  "enabledPlugins": { "ai-design@ai-design": true }
}
pre-commit
.pre-commit-config.yaml에 추가합니다. rev는 고정할 커밋 SHA입니다. 최신 값은 pre-commit autoupdate로 받습니다. 
- repo: https://github.com/jungrok5/ai-design
  rev: 
  hooks:
    - id: ai-design-style
명령줄, CI
error가 하나라도 있으면 종료 코드 1을 돌려줍니다. 
git clone --depth 1 https://github.com/jungrok5/ai-design ~/.ai-design
python3 ~/.ai-design/plugins/ai-design/style/style_check.py README.md docs/*.md
Cursor, Copilot, AGENTS.md
adapters/의 규칙 파일을 각 도구의 규칙 폴더에 복사합니다. 이 도구들에는 수정 직후 훅이 없으므로 pre-commit과 함께 씁니다.

한계

  • 정규식이라 문맥을 모릅니다. "~을 통해"가 자연스러운 문장도 있어서 이런 규칙은 경고로만 둡니다.
  • 일부 규칙은 한 파일에 여러 번 나올 때만 알립니다(max_per_file). 예를 들어 "~을 통해"는 세 번째부터 경고합니다.
  • 문장을 검사할 뿐 페이지 구성은 보지 않습니다. 모든 절이 같은 틀이거나 같은 사실을 반복하는 문제는 스킬 지침과 사람의 리뷰로 잡습니다.
  • 한국어 규칙은 합니다체 문서를 기준으로 합니다. 해요체를 쓰는 제품 화면은 ko-haeyo 규칙을 꺼야 합니다.
  • 영어 규칙은 개로 한국어(개)보다 적습니다. 영어 문서만 있는 레포에서는 잡는 범위가 좁습니다.
  • 광고 문구처럼 의도적으로 수사를 쓰는 글에는 맞지 않습니다.

규칙을 끄거나 추가할 때는 프로젝트 루트의 .style/rules.toml에 플러그인의 rules.toml과 같은 형식으로 적습니다. 현재 규칙은 개이고, 전체 목록은 style_check.py --list-rules로 확인합니다.

[[rule]]
id = "ko-haeyo"
severity = "off"
