## ⚛️ 프레임워크 & 라이브러리

### React Labs 3월 업데이트
React 팀은 3월 말 연구 현황 글을 통해 서버 컴포넌트(Server Components), 액션(Actions), 문서 메타데이터 관리, 에셋 로딩 최적화 등 진행 중인 작업을 공유했습니다. 특히 폼 제출과 데이터 변경을 하나의 추상화로 다룰 수 있는 **액션** 개념이 눈에 띕니다. 기존에는 `onSubmit` 핸들러, 로딩 상태, 에러 처리를 각각 직접 관리해야 했지만, 액션을 사용하면 비동기 전환(transition) 상태와 낙관적 업데이트(optimistic update)를 프레임워크 차원에서 함께 처리할 수 있는 방향으로 나아가고 있습니다.

또한 자동 메모이제이션을 수행하는 **React Compiler**도 실험 단계에서 점점 구체적인 모습을 드러내고 있습니다. 수동으로 `useMemo`나 `useCallback`을 남발하지 않아도 되는 날이 가까워지고 있다는 신호입니다.

### TypeScript 5.4
3월 초 공개된 TypeScript 5.4는 작지만 실용적인 변화가 많았습니다.

- **`NoInfer` 유틸리티 타입**: 제네릭 인자 추론에서 특정 위치의 타입을 추론 대상에서 제외할 수 있습니다.
- **클로저에서의 타입 좁히기 유지**: 변수가 마지막으로 할당된 이후의 클로저 내부에서도 좁혀진 타입이 유지되어, 불필요한 타입 단언을 줄여 줍니다.
- **ES2024 라이브러리 타입 지원**: `Object.groupBy`, `Map.groupBy`, `Promise.withResolvers` 등의 타입을 사용할 수 있습니다.

  initial: S,
  transitions: Record<S, NoInfer<S>[]>
) {

  // 첫 번째 인자(initial)로부터만 S가 결정됩니다.

createFSM("idle", {

### Angular 17.x 개선 흐름
Angular는 17 버전대 업데이트를 통해 새 제어 흐름 문법(`@if`, `@for`, `@switch`)을 안정화하고, 빌드 파이프라인과 개발 서버의 응답성을 꾸준히 개선하고 있습니다. 템플릿 문법이 자바스크립트 제어문에 가까워지면서 신규 입문자의 학습 곡선도 완만해졌다는 평가가 많았습니다.

## 🌐 브라우저 & 웹 플랫폼

3월에는 Chrome과 Firefox가 각각 새 안정 버전을 공개했습니다. 두 브라우저 모두 CSS와 DOM API 지원 범위를 넓히는 데 집중했으며, 릴리스 노트를 통해 기능 지원 여부를 확인하는 습관이 중요하다는 점을 다시 한번 보여 주었습니다.

웹 플랫폼 커뮤니티에서는 다음과 같은 주제가 활발히 논의되었습니다.

- **Popover API와 `<dialog>` 요소**: 모달과 툴팁을 접근성 있게 구현하는 표준 방식으로 주목받고 있습니다. 직접 포커스 트랩이나 ESC 키 처리를 구현하던 부담을 줄여 줍니다.
- **컨테이너 쿼리**: 뷰포트가 아닌 부모 요소의 크기에 따라 스타일을 바꾸는 방식이 실무에 빠르게 자리 잡고 있습니다. 재사용 가능한 컴포넌트 설계에 특히 유용합니다.
- **View Transitions API**: 페이지나 상태 전환에 부드러운 애니메이션을 적용하는 표준 기능으로, SPA와 MPA 모두에서 활용 사례가 늘고 있습니다.

## 🛠️ 개발 도구

빌드 도구 시장은 속도 경쟁이 한층 치열해졌습니다. Rust로 작성된 번들러와 린터, 포매터들이 기존 JavaScript 기반 도구의 대안으로 빠르게 채택되고 있으며, 대규모 모노레포에서 체감 차이가 크다는 후기가 많습니다.

테스트 분야에서는 Vite 기반 테스트 러너인 Vitest가 여전히 강세입니다. Jest와의 호환 API를 제공하면서도 설정이 가볍고, 같은 Vite 설정을 공유할 수 있다는 점이 장점으로 꼽힙니다. 컴포넌트 문서화 도구인 Storybook도 버전 업데이트를 통해 설정 간소화와 테스트 연동을 강화하고 있습니다.

## 💡 이달의 팁: 불필요한 `useMemo` 줄이기

메모이제이션은 비용이 있는 계산이나 자식 컴포넌트의 불필요한 리렌더링을 막을 때만 의미가 있습니다. 다음 순서로 점검해 보세요.

1. React DevTools의 Profiler로 실제로 느린 구간을 먼저 측정합니다.
2. 병목이 확인되지 않은 곳의 `useMemo`, `useCallback`은 제거합니다.
3. 상태를 필요한 컴포넌트 가까이로 끌어내리면(state colocation) 메모이제이션 없이도 리렌더링 범위가 자연스럽게 줄어듭니다.

측정 없이 최적화하면 코드만 복잡해집니다. "먼저 재고, 그다음 고친다"는 원칙을 기억해 두시면 좋겠습니다.
