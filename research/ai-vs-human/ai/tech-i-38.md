# PCB & Context Switching

## 1. 프로세스와 PCB

**프로세스**는 실행 중인 프로그램이다. 운영체제는 프로세스마다 **PCB(Process Control Block)**라는 자료구조를 만들어 커널 영역에 보관한다. PCB는 프로세스의 신분증이자 상태 기록부다. 프로세스가 생성되면 PCB도 함께 만들어지고, 종료되면 함께 제거된다.

### PCB에 담기는 정보
| 항목 | 설명 |
|---|---|
| PID | 프로세스 고유 식별자 |
| 프로세스 상태 | New, Ready, Running, Waiting, Terminated |
| 프로그램 카운터(PC) | 다음에 실행할 명령어의 주소 |
| CPU 레지스터 | 누산기, 스택 포인터 등 실행 중이던 값 |
| CPU 스케줄링 정보 | 우선순위, 스케줄링 큐 포인터 |
| 메모리 관리 정보 | 페이지 테이블, 세그먼트 테이블, 베이스/리밋 레지스터 |
| 입출력 상태 정보 | 열린 파일 목록, 할당된 I/O 장치 |
| 계정 정보 | CPU 사용 시간, 사용 제한 |

## 2. 컨텍스트(Context)와 컨텍스트 스위칭

**컨텍스트**는 프로세스가 CPU에서 실행되기 위해 필요한 모든 정보다. 구체적으로는 레지스터 값, 프로그램 카운터, 메모리 매핑 정보 등이며, 이 정보는 PCB에 저장된다.

**컨텍스트 스위칭**은 CPU가 실행하던 프로세스를 중단하고 다른 프로세스를 실행하도록 교체하는 작업이다.

### 동작 순서
1. 인터럽트나 시스템 콜이 발생한다. (타임 슬라이스 만료, I/O 요청 등)
2. 현재 프로세스의 컨텍스트를 **PCB_A에 저장**한다.
3. 스케줄러가 다음에 실행할 프로세스 B를 선택한다.
4. **PCB_B에서 컨텍스트를 복원**한다.
5. CPU가 프로세스 B를 실행한다.

이 과정을 거치기 때문에 프로세스 A는 나중에 중단된 지점부터 정확히 이어서 실행할 수 있다.

### 발생 시점
- 타임 슬라이스를 모두 사용했을 때 (선점형 스케줄링)
- I/O 요청으로 대기 상태가 될 때
- 더 높은 우선순위의 프로세스가 도착했을 때
- 인터럽트가 발생했을 때

## 3. 오버헤드

컨텍스트 스위칭 중에는 CPU가 **유용한 작업을 하지 못한다.** 이 시간은 순수한 오버헤드다.

- 레지스터 저장과 복원에 드는 시간
- **캐시 오염(Cache Pollution)**: 새 프로세스가 실행되면 기존 캐시 내용이 쓸모없어져 캐시 미스가 늘어난다.
- **TLB 플러시**: 주소 공간이 바뀌므로 TLB를 비워야 하고, 이후 주소 변환 비용이 늘어난다.
- 파이프라인 비우기 비용

타임 슬라이스를 너무 짧게 잡으면 스위칭이 잦아져 오버헤드가 커진다. 반대로 너무 길면 응답성이 떨어진다.

## 4. 프로세스 vs 스레드 컨텍스트 스위칭

| 구분 | 프로세스 | 스레드 |
|---|---|---|
| 주소 공간 | 교체 필요 | 같은 프로세스 내에서는 공유 |
| TLB 플러시 | 필요 | 대체로 불필요 |
| 캐시 활용 | 효율 낮음 | 상대적으로 높음 |
| 비용 | 큼 | 작음 |

스레드는 코드, 데이터, 힙을 공유하고 **스택과 레지스터만 별도로** 가진다. 그래서 전환 시 저장할 정보가 적고 메모리 맵을 바꾸지 않아도 된다. 이 점이 멀티스레드가 선호되는 주요 이유다. 스레드 정보는 보통 **TCB(Thread Control Block)**에 저장한다.

## 5. 면접 예상 질문

**Q1. PCB란 무엇이고 왜 필요한가요?**
운영체제가 프로세스를 관리하기 위해 프로세스별 정보를 저장하는 자료구조입니다. 컨텍스트 스위칭 때 상태를 저장하고 복원하려면 반드시 필요합니다.

**Q2. 컨텍스트 스위칭이 비용이 큰 이유는?**
전환 중에는 유용한 작업을 못 하고, 캐시 미스와 TLB 플러시로 전환 이후에도 성능이 떨어집니다. 직접 비용보다 이런 간접 비용이 더 큽니다.

**Q3. 스레드 전환이 프로세스 전환보다 가벼운 이유는?**
주소 공간을 공유해서 메모리 맵 교체와 TLB 플러시가 필요 없고, 저장할 레지스터와 스택 정보만 바꾸면 되기 때문입니다.

**Q4. 컨텍스트 스위칭 오버헤드를 줄이는 방법은?**
- 적절한 타임 슬라이스 설정
- 프로세스 대신 스레드 사용
- 사용자 수준 스레드나 코루틴 활용
- CPU 친화도(Affinity)로 같은 코어에서 계속 실행

**Q5. 모드 전환(Mode Switch)과 컨텍스트 스위칭은 같은가요?**
다릅니다. 시스템 콜로 사용자 모드에서 커널 모드로 바뀌는 것은 같은 프로세스 안에서의 모드 전환입니다. 프로세스가 바뀌지 않으므로 컨텍스트 스위칭보다 훨씬 가볍습니다.

## 6. 핵심 요약
- PCB는 프로세스의 모든 실행 정보를 담은 커널 자료구조다.
- 컨텍스트 스위칭은 PCB에 현재 상태를 저장하고 다음 프로세스의 상태를 복원하는 과정이다.
- 스위칭 중에는 유용한 일을 못 하므로 **순수 오버헤드**다.
- 스레드 전환이 프로세스 전환보다 저렴하다.
