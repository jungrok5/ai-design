## 1. Angular 10 출시

6월 24일 Angular 10이 나왔습니다. 이번 버전은 기능을 크게 늘리기보다 **생태계를 정리**하는 데 무게를 뒀습니다.

- **새 날짜 범위 선택기**: Angular Material에 날짜 범위 선택 컴포넌트가 추가됐습니다.
- **엄격 모드 옵션**: 새 프로젝트를 만들 때 `--strict` 플래그로 더 엄격한 타입 검사와 번들 예산 설정을 한 번에 켤 수 있습니다.
- **TSLint 지원 중단 예고**: ESLint로의 이전이 사실상 권장 방향이 됐습니다.
- **오래된 브라우저 정리**: IE9, IE10, IE Mobile 지원이 중단 대상이 됐습니다.
- **기본 browserslist 변경**: 빌드 대상 브라우저 설정이 갱신됐습니다.

기존 프로젝트라면 `ng update`로 올리기 전에 TSLint 설정과 서드파티 라이브러리의 호환 여부부터 확인하는 편이 안전합니다.

## 2. TypeScript 4.0 베타

6월 말 TypeScript 4.0 베타가 공개됐습니다. 메이저 버전이지만 기존 코드를 크게 깨뜨리는 변경은 적은 편입니다. 눈여겨볼 기능은 다음과 같습니다.

**가변 인자 튜플 타입(Variadic Tuple Types)**

튜플을 합치거나 나누는 함수의 타입을 훨씬 정확하게 표현할 수 있습니다.

```ts
type Concat<T extends unknown[], U extends unknown[]> = [...T, ...U];
```

**라벨이 붙은 튜플 요소**

튜플 각 자리에 이름을 붙여 에디터 힌트와 가독성이 좋아집니다.

```ts
type Range = [start: number, end: number];
```

**생성자 기반 클래스 속성 추론**

`noImplicitAny`를 켠 상태에서 생성자의 대입문을 보고 속성 타입을 추론합니다.

**단축 평가 대입 연산자**

`&&=`, `||=`, `??=` 문법을 지원합니다.

정식 출시 전에 CI에서 베타 버전으로 타입 검사를 한 번 돌려 보면 업그레이드 부담을 미리 가늠할 수 있습니다.

## 3. 브라우저 소식

### Safari 14 (WWDC 2020)

애플이 6월 22일 WWDC에서 Safari 14를 공개했습니다.

- **WebP 이미지 지원**: 그동안 이미지 포맷 폴백이 필요했던 가장 큰 이유가 사라질 전망입니다.
- **개인정보 보호 리포트**: 방문한 사이트에서 어떤 트래커가 차단됐는지 보여 줍니다.
- **웹 확장 프로그램 API 지원**: Chrome용으로 만든 확장 프로그램을 Safari로 옮기기 쉬워집니다.

### Chrome 84 베타

Chrome 84는 7월 정식 출시를 앞두고 6월에 베타 단계에 있었습니다. 웹 개발자에게 중요한 점은 레거시 기능의 정리가 계속 진행되고 있다는 것입니다. 특히 서드파티 쿠키 정책과 `SameSite` 속성 관련 변화는 로그인·결제 연동 서비스에 영향을 줄 수 있어 계속 지켜봐야 합니다.

### Firefox

Firefox 77이 6월 초, Firefox 78이 6월 말에 나왔습니다. 78은 장기 지원(ESR) 라인의 새 기준이 되는 버전이어서 기업 환경에서는 이쪽을 눈여겨봐야 합니다.

## 4. 성능: Core Web Vitals를 이해하기

5월 말 구글이 발표한 **Core Web Vitals**와 페이지 경험 신호가 6월 내내 커뮤니티의 주요 화제였습니다. 핵심 지표는 세 가지입니다.

| 지표 | 의미 | 좋은 기준(참고) |
|---|---|---|
| **LCP** (Largest Contentful Paint) | 가장 큰 콘텐츠가 보이기까지의 시간 | 2.5초 이내 |
| **FID** (First Input Delay) | 첫 입력에 반응하기까지의 지연 | 100ms 이내 |
| **CLS** (Cumulative Layout Shift) | 레이아웃이 예기치 않게 흔들린 정도 | 0.1 이하 |

바로 해볼 수 있는 개선은 다음과 같습니다.

1. 이미지와 광고 영역에 **`width`/`height`를 명시**해 CLS를 줄입니다.
2. 히어로 이미지를 **우선 로드**하고 이미지 포맷을 최신화합니다.
3. 긴 자바스크립트 작업을 **쪼개서** 메인 스레드 차단을 줄입니다.
4. Lighthouse와 Chrome UX Report를 함께 보며 **실제 사용자 데이터**를 기준으로 판단합니다.

## 5. 도구 생태계: 번들 없는 개발 서버

**Vite**(Vue 창시자 Evan You)와 **Snowpack**은 브라우저의 네이티브 ES 모듈을 활용해 개발 서버 기동과 핫 리로드를 크게 빠르게 만든다는 점으로 주목받았습니다. 프로젝트가 커질수록 느려지는 번들러 기반 개발 경험에 대한 대안으로, 6월에도 후기와 비교 글이 많이 올라왔습니다.

한편 **webpack 5**는 베타를 거치며 영구 캐시와 **모듈 페더레이션**(여러 앱이 런타임에 코드를 공유하는 방식)으로 마이크로 프론트엔드 논의에 불을 붙였습니다.

두 흐름의 요점은 이렇습니다.

- 개발 환경은 **빠른 피드백**을 우선하는 방향으로 이동하고 있습니다.
- 프로덕션 빌드는 여전히 **검증된 번들러**가 안정적인 선택입니다.
- 새 도구를 도입한다면 사이드 프로젝트나 사내 도구에서 먼저 시험해 보세요.
