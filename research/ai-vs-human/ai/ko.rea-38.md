# 팀 소개

React 팀은 사용자 인터페이스를 만드는 가장 효율적인 방법을 연구하고, React를 유지보수하며, 전 세계 개발자 커뮤니티와 함께 라이브러리를 발전시키는 사람들의 모임입니다. 이 페이지에서는 팀이 어떻게 구성되어 있고, 어떤 방식으로 일하며, 여러분이 어떻게 참여할 수 있는지 소개합니다.

## 이 페이지에서 배울 내용

- React 팀의 역할과 구성
- 중요한 결정이 이루어지는 방식
- 커뮤니티가 기여할 수 있는 경로
- 팀과 소통하는 방법

## 팀의 역할

React 팀은 크게 세 가지 일을 합니다.

1. **코어 개발**: 렌더러, 재조정(reconciliation) 알고리즘, 스케줄러, 서버 컴포넌트 등 핵심 기능을 설계하고 구현합니다.
2. **유지보수**: 이슈와 풀 리퀘스트를 검토하고, 버그를 수정하며, 보안 문제에 대응합니다.
3. **생태계 지원**: 공식 문서, 릴리스 노트, 마이그레이션 가이드를 작성하고 React Conf 같은 행사를 준비합니다.

React는 Meta의 엔지니어링 조직에서 시작되었지만, 오늘날에는 전 세계 수많은 기여자의 참여로 만들어지고 있습니다. 팀은 외부 기여자의 의견을 적극적으로 듣고, 중요한 변경은 공개 토론을 거쳐 결정합니다.

## 팀의 구성

React 팀은 다음과 같은 영역으로 나뉘어 일합니다.

### 코어 팀

렌더링 엔진, 상태 업데이트, 동시성 기능처럼 React의 근간을 이루는 영역을 담당합니다. 장기적인 설계 방향을 제시하고 주요 릴리스의 품질을 책임집니다.

### 문서 팀

react.dev의 콘텐츠를 작성하고 번역을 관리합니다. 개념 설명, 튜토리얼, 레퍼런스가 같은 용어와 같은 예제 스타일을 따르도록 조율합니다.

### 툴링 팀

React DevTools, ESLint 플러그인, 빌드 도구와의 통합을 담당합니다. 개발자가 실제로 코드를 작성하고 디버깅하는 환경을 개선하는 것이 목표입니다.

### 커뮤니티 및 릴리스 팀

이슈 분류, 릴리스 노트 작성, 커뮤니티 질문 응대를 맡습니다. 새로운 기여자가 처음 참여할 수 있도록 `good first issue` 라벨을 관리하는 것도 이 영역의 일입니다.

## 의사결정 방식

React의 중요한 변경은 공개 RFC(Request for Comments) 과정을 거칩니다. 누구나 `reactjs/rfcs` 저장소에 제안서를 올릴 수 있고, 팀과 커뮤니티가 함께 검토합니다. 제안서에는 다음 내용이 포함되어야 합니다.

- 해결하려는 문제와 제안의 동기
- 제안하는 API 또는 동작 방식
- 기존 코드에 미칠 영향
- 검토한 대안과 그것을 선택하지 않은 이유

RFC가 승인되면 구현은 보통 실험 채널(experimental)에서 먼저 제공됩니다. 충분한 피드백을 거쳐 안정 버전에 포함되며, 이 과정에서 팀은 하위 호환성을 최대한 지키고, 불가피한 변경에는 명확한 마이그레이션 경로를 제공하려고 합니다.

## 릴리스 방식

React는 의미 있는 버전 관리 원칙을 따릅니다. 하위 호환이 깨지는 변경은 메이저 버전에서만 도입하며, 새 기능은 마이너 버전으로, 버그 수정은 패치 버전으로 배포합니다. 실험적인 기능은 안정 버전과 분리된 채널에서 먼저 시험해 볼 수 있습니다.

릴리스 노트에는 변경 사항뿐 아니라 업그레이드 시 주의할 점도 함께 정리됩니다. 큰 변경이 있을 때는 단계별 마이그레이션 가이드를 제공하는 것을 원칙으로 합니다.

## 기여하는 방법

React 팀은 다양한 형태의 기여를 환영합니다.

- **버그 리포트**: 재현 가능한 예제와 함께 이슈를 등록해 주세요.
- **문서 개선**: 오타 수정, 설명 보완, 번역 참여 모두 가치가 있습니다.
- **코드 기여**: `CONTRIBUTING.md`를 먼저 읽고, 작은 범위의 수정부터 시작하는 것을 권장합니다.
- **토론 참여**: RFC 검토와 GitHub Discussions에서 사용 경험을 공유해 주세요.

풀 리퀘스트를 올릴 때는 변경 이유를 설명하고, 가능하면 테스트를 함께 제출해 주세요. 리뷰 과정에서 피드백을 받는 것은 자연스러운 일입니다. 팀은 모든 기여자가 존중받는 환경을 지향하며, 행동 강령(Code of Conduct)은 모든 공간에 동일하게 적용됩니다.

## 팀과 소통하기

- **질문**: 사용법에 관한 질문은 커뮤니티 포럼이나 Stack Overflow에 올리면 빠르게 답을 얻을 수 있습니다.
- **버그와 기능 제안**: 공식 GitHub 저장소의 이슈 트래커를 이용해 주세요.
- **보안 문제**: 공개 이슈로 올리지 말고, 저장소의 보안 정책에 따라 비공개로 신고해 주세요.

## 요약

React 팀은 소수의 핵심 개발자와 수많은 기여자가 함께 만들어 가는 공동체입니다. 여러분의 질문, 버그 리포트, 제안 하나하나가 React를 더 나은 도구로 만듭니다. 함께 참여해 주셔서 감사합니다.
