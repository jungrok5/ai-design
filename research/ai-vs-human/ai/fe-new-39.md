## 2. 프레임워크 동향

### React 19.2와 생태계

React 19.2는 `<Activity>` 컴포넌트와 `useEffectEvent` 같은 기능을 선보였습니다. `<Activity>`는 화면에서 숨긴 UI의 상태를 유지하면서 우선순위를 낮춰 렌더링할 수 있게 해 줍니다. 탭이나 단계형 화면처럼 "숨겼다가 다시 보여주는" UI에서 상태 손실과 불필요한 렌더링을 함께 줄일 수 있습니다.

`useEffectEvent`는 이펙트 안에서 최신 props와 state를 읽되, 그 값이 의존성 배열을 흔들지 않게 분리해 줍니다. 의존성 린트 경고와 씨름하던 분들께 반가운 소식입니다. React Compiler도 안정 단계로 접어들며 `useMemo`, `useCallback`을 손으로 쓰는 일이 줄고 있습니다.

### Next.js 16

Next.js 16은 Turbopack을 기본 번들러로 삼고, 캐싱을 명시적으로 선택하는 방향의 모델을 내세웠습니다. 기존에는 "어디까지 캐시되는가"를 추측해야 했다면, 이제는 필요한 곳에 캐시를 선언합니다. 업그레이드 전에는 마이그레이션 가이드에서 변경된 기본값을 꼭 확인하세요.

### 그 밖의 프레임워크

- **Angular**: 시그널 기반 반응성과 zoneless 변화동 감지로 가는 흐름이 뚜렷합니다. 새 프로젝트는 이 방향을 전제로 설계하는 편이 좋습니다.
- **Svelte·Vue**: 컴파일러 중심 접근을 유지하며 번들 크기와 런타임 비용을 줄이는 쪽으로 다듬어지고 있습니다.
- **Astro 등 콘텐츠 중심 도구**: 아일랜드 아키텍처가 "필요한 곳에만 JS를 보낸다"는 원칙을 다시 일깨워 줍니다.

## 3. 언어와 빌드 도구

### TypeScript

TypeScript 팀이 컴파일러를 네이티브 코드로 옮기는 작업을 진행 중입니다. 목표는 빌드와 에디터 응답 속도를 큰 폭으로 높이는 것입니다. 대형 모노레포에서 타입 체크 대기 시간이 줄어든다면 개발 경험이 크게 달라질 수 있습니다. 한편 Node.js의 타입 스트리핑 지원이 넓어지면서 별도 빌드 없이 `.ts` 파일을 실행하는 시나리오도 현실적인 선택지가 되었습니다.

### Vite와 번들러

Vite는 Rolldown(Rust 기반 번들러)으로의 전환을 차근차근 준비하고 있습니다. 개발 서버와 프로덕션 빌드의 동작 차이를 줄이는 것이 핵심 과제입니다. Node.js 24가 LTS 단계에 들어서면서 도구 체인의 최소 Node 버전을 올리는 프로젝트도 늘고 있으니, CI 이미지의 Node 버전을 점검해 두세요.

## 4. 웹 플랫폼 소식

### CSS의 약진

- **컨테이너 쿼리와 `:has()`**: 이제 실무에서 자연스럽게 쓰이는 기본기가 되었습니다.
- **앵커 포지셔닝**: 툴팁과 팝오버 위치를 JS 없이 선언적으로 잡는 방향이 자리를 잡아 갑니다.
- **View Transitions**: 페이지 전환 애니메이션을 표준 API로 구현하는 사례가 늘고 있습니다.
- **스크롤 기반 애니메이션**: 스크롤 위치에 연동된 효과를 CSS만으로 구현할 수 있습니다.

### 호환성 노력

Interop 프로젝트를 통해 브라우저 벤더들이 같은 기능을 같은 방식으로 구현하는 데 속도를 내고 있습니다. 신기능을 도입하기 전에는 MDN과 Baseline 표시로 지원 상태를 확인하고, `@supports`로 점진적 향상을 적용하는 습관을 들이면 안전합니다.

## 5. AI와 개발 경험

코딩 에이전트와 AI 보조 도구가 코드 작성, 리뷰, 테스트 생성까지 폭넓게 쓰이고 있습니다. 다만 몇 가지 원칙은 유효합니다.

1. **생성된 코드도 리뷰 대상**: 접근성과 보안은 사람이 직접 확인합니다.
2. **타입과 테스트가 안전망**: 엄격한 타입과 좋은 테스트가 있을수록 AI 도움을 안전하게 받을 수 있습니다.
3. **컨텍스트 문서화**: 프로젝트 규칙을 문서로 남겨 두면 사람과 도구 모두에게 도움이 됩니다.
