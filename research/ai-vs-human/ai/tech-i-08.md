# Array (배열) — 기술 면접 대비 정리 노트

## 1. 개념
배열은 **같은 타입의 데이터를 연속된 메모리 공간에 순서대로 저장**하는 자료구조입니다. 각 요소는 **인덱스(0부터 시작)**로 접근합니다.

- 시작 주소 + (인덱스 × 요소 크기)로 주소를 계산하므로 임의 접근이 빠릅니다.
- 크기가 고정된 **정적 배열**과, 크기가 자동으로 늘어나는 **동적 배열**(Java `ArrayList`, C++ `vector`, Python `list`, JS `Array`)이 있습니다.

## 2. 시간 복잡도

| 연산 | 시간 복잡도 | 설명 |
|---|---|---|
| 인덱스 접근 | O(1) | 주소 계산만으로 접근 |
| 탐색(비정렬) | O(n) | 선형 탐색 |
| 탐색(정렬) | O(log n) | 이진 탐색 |
| 끝에 삽입/삭제 | O(1) (분할 상환) | 용량 초과 시 재할당 |
| 중간/앞 삽입·삭제 | O(n) | 뒤 요소들을 이동해야 함 |

## 3. 동적 배열의 동작 원리
1. 내부적으로 고정 크기 배열(capacity)을 가지고 있습니다.
2. 가득 차면 **보통 1.5~2배 크기의 새 배열**을 할당하고 기존 요소를 복사합니다.
3. 복사 비용 O(n)이 가끔 발생하지만, 평균하면 `append`는 **분할 상환 O(1)**입니다.

> 면접 포인트: "왜 2배씩 늘리나요?" → 확장 횟수를 log n으로 줄여 총 복사 비용을 O(n)으로 유지하기 위해서입니다. 너무 크게 늘리면 메모리 낭비가 커지는 트레이드오프가 있습니다.

## 4. 장단점
**장점**
- 인덱스 접근이 O(1)로 빠름
- 연속 메모리라 **캐시 지역성(cache locality)**이 좋아 실제 성능이 우수
- 포인터가 필요 없어 메모리 오버헤드가 작음

**단점**
- 중간 삽입/삭제가 비쌈
- 정적 배열은 크기 변경 불가
- 연속된 큰 메모리 공간이 필요해 단편화 시 할당 실패 가능

## 5. 배열 vs 연결 리스트

| 항목 | 배열 | 연결 리스트 |
|---|---|---|
| 메모리 | 연속 | 비연속(노드+포인터) |
| 임의 접근 | O(1) | O(n) |
| 앞쪽 삽입/삭제 | O(n) | O(1) |
| 캐시 효율 | 높음 | 낮음 |
| 추가 메모리 | 거의 없음 | 포인터 저장 필요 |

> 실무에서는 캐시 효율 덕분에 대부분 배열 기반이 더 빠른 경우가 많습니다.

## 6. 자주 나오는 면접 질문
1. **배열이 임의 접근이 O(1)인 이유는?**
   연속 메모리에서 `base + index × size`로 주소를 바로 계산하기 때문입니다.
2. **ArrayList와 LinkedList 중 언제 무엇을 쓰나요?**
   조회가 많으면 ArrayList, 양 끝이 아닌 곳에서 삽입·삭제가 잦고 이미 노드 위치를 알고 있을 때 LinkedList를 고려합니다.
3. **배열 중간 요소를 삭제하는 방법은?**
   삭제 위치 뒤의 요소를 한 칸씩 앞으로 당기며, O(n)이 소요됩니다.
4. **JavaScript 배열은 진짜 배열인가요?**
   엔진 최적화로 연속 메모리를 쓰기도 하지만, 사실상 객체 기반이며 희소 배열이면 해시 형태로 동작할 수 있습니다.
5. **2차원 배열의 메모리 배치는?**
   C/C++/Java는 행 우선(row-major)입니다. 행 순서로 순회하면 캐시 적중률이 높아집니다.

## 7. 코딩 테스트 빈출 패턴
- **투 포인터**: 정렬된 배열에서 두 값의 합 찾기, 중복 제거
- **슬라이딩 윈도우**: 연속 부분 배열의 최대 합
- **누적 합(Prefix Sum)**: 구간 합을 O(1)로 계산
- **이진 탐색**: 정렬 배열에서 O(log n) 탐색
- **해시맵 병행 사용**: Two Sum 같은 문제를 O(n)으로 해결

## 8. 정리
- 배열 = 연속 메모리 + 인덱스 접근 O(1)
- 삽입/삭제는 O(n), 끝 추가는 분할 상환 O(1)
- 캐시 지역성이 가장 큰 실전 강점
- 문제에 따라 투 포인터, 슬라이딩 윈도우, 누적 합을 먼저 떠올릴 것
