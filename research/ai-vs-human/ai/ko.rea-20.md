# `<script>`

`<script>` 는 React DOM이 제공하는 내장 브라우저 컴포넌트입니다. 페이지에 외부 스크립트를 추가하거나, 스크립트 로딩 상태를 React 컴포넌트 안에서 관리할 때 사용합니다.

```jsx
<script src="https://example.com/widget.js" />
```

## 언제 사용하나요?

서드파티 분석 도구, 지도 위젯, 결제 모듈처럼 **외부에서 제공하는 스크립트**를 페이지에 불러와야 할 때 사용합니다. 스크립트가 필요한 컴포넌트 안에서 직접 선언하면, 해당 기능이 렌더링될 때만 스크립트가 로드되도록 구성할 수 있습니다.

React 애플리케이션 코드 자체를 번들링하는 용도로는 보통 빌드 도구가 생성한 번들 파일을 사용하므로, `<script>` 를 직접 선언할 일은 많지 않습니다.

## 레퍼런스

### 기본 사용법

`src` prop에 스크립트 URL을 지정하여 렌더링합니다.

```jsx
export default function Page() {
  return (
    <>
      <h1>내 페이지</h1>
      <script src="https://example.com/analytics.js" async={true} />
    </>
  );
}
```

### Props

- **`src`**: 로드할 스크립트의 URL입니다.
- **`async`**: `true`이면 스크립트를 비동기로 로드합니다. `async`와 `src`를 함께 사용하면 React가 스크립트 로딩을 추적합니다.
- **`type`**: 스크립트의 MIME 타입입니다. 예를 들어 ES 모듈은 `"module"`을 지정합니다.
- **`crossOrigin`**: CORS 요청 방식을 지정합니다. `"anonymous"` 또는 `"use-credentials"` 값을 사용할 수 있습니다.
- **`integrity`**: 서브리소스 무결성(SRI) 검사에 사용할 해시 값입니다.
- **`referrerPolicy`**: 스크립트 요청 시 전송할 Referrer 정책입니다.
- **`onLoad`**: 스크립트 로딩이 끝나면 호출되는 콜백입니다.
- **`onError`**: 스크립트 로딩에 실패하면 호출되는 콜백입니다.

위에 나열하지 않은 일반 DOM 속성도 함께 전달할 수 있습니다.

## 주요 동작

### 중복 로드 방지

같은 `src`를 가진 `<script>`를 여러 컴포넌트에서 렌더링하더라도 스크립트는 한 번만 로드됩니다. 따라서 공통 라이브러리가 필요한 컴포넌트마다 `<script>`를 선언해도 문제가 없습니다.

다만 `src` 값이 한 글자라도 다르면(예: 쿼리 문자열 차이) 다른 스크립트로 취급되어 각각 로드됩니다.

### 로딩 상태 추적

`onLoad`와 `onError`를 사용하면 스크립트의 로딩 결과에 따라 UI를 바꿀 수 있습니다. 예를 들어 로딩 중에는 안내 문구를 보여 주고, 실패하면 대체 UI를 보여 줄 수 있습니다.

## 주의사항

- **인라인 스크립트는 신중하게 사용하세요.** 자식 텍스트로 코드를 직접 넣는 방식은 사용자 입력이 섞일 경우 XSS 취약점으로 이어질 수 있습니다.
- **신뢰할 수 있는 출처만 사용하세요.** 외부 스크립트는 페이지의 모든 데이터에 접근할 수 있으므로, 가능하면 `integrity` 속성으로 내용을 검증하세요.
- **전역 변수에 의존하는 스크립트를 주의하세요.** 스크립트가 전역 객체를 만들어 두고 컴포넌트가 그것을 사용한다면, 스크립트 로딩이 끝난 뒤에만 접근하도록 `onLoad` 이후에 처리해야 합니다.
- **스크립트의 실행 순서는 브라우저가 결정합니다.** `async` 스크립트는 로드 완료 순서대로 실행되므로, 순서가 중요하다면 `async`를 사용하지 않거나 `onLoad`로 순서를 직접 제어하세요.

## 예제

### 1. 로딩 완료와 실패 처리

```jsx
export default function MapWidget() {
  return (
    <script
      src="https://example.com/map.js"
      async={true}
      onLoad={() => console.log('지도 스크립트 로딩 완료')}
      onError={() => console.error('지도 스크립트 로딩 실패')}
    />
  );
}
```

### 2. 무결성 검증

```jsx
<script
  src="https://cdn.example.com/lib.min.js"
  integrity="sha384-..."
  crossOrigin="anonymous"
/>
```

`integrity` 값이 실제 파일의 해시와 맞지 않으면 브라우저는 스크립트를 실행하지 않습니다.

### 3. 모듈 스크립트

```jsx
<script type="module" src="/app-entry.js" />
```

## 문제 해결

- **스크립트가 실행되지 않을 때**: 브라우저 개발자 도구의 Network 탭에서 요청이 성공했는지 확인하고, Console 탭에서 CORS 또는 무결성 오류 메시지가 있는지 확인하세요.
- **같은 스크립트가 두 번 로드되는 것처럼 보일 때**: `src` 값이 정확히 같은지 확인하세요. 쿼리 문자열이나 경로 표기가 다르면 별개의 스크립트로 처리됩니다.
- **`onLoad`가 호출되지 않을 때**: 이미 로드된 스크립트라면 이벤트가 다시 발생하지 않을 수 있습니다. 스크립트 로딩 상태를 전역에서 한 번만 관리하는 방법을 고려하세요.
