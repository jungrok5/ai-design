# 교차 브라우저 테스팅

이 문서는 교차 브라우저 테스팅이 무엇인지, 왜 필요한지, 웹 프로젝트에서 어떻게 진행하는지 소개합니다.

## 교차 브라우저 테스팅이란?

교차 브라우저 테스팅은 내가 만든 웹사이트나 웹 애플리케이션이 여러 웹 브라우저에서 제대로 동작하는지 확인하는 일입니다. 웹 개발자는 다음과 같은 다양한 사용 환경을 고려해야 합니다.

- Chrome, Firefox, Safari, Edge 같은 여러 브라우저와 그 이전 버전
- 데스크톱, 태블릿, 스마트폰, 스마트 TV처럼 화면 크기와 성능이 다른 기기
- 스크린 리더처럼 보조 기술을 사용하는 사람, 마우스 없이 키보드로만 탐색하는 사람

모든 브라우저에서 똑같이 보일 필요는 없다는 점을 기억하세요. 중요한 것은 **누구나 핵심 기능과 콘텐츠를 사용할 수 있어야 한다**는 것입니다. 오래된 브라우저에서 화려한 애니메이션이 나오지 않아도 괜찮지만, 글을 읽을 수 없거나 버튼이 동작하지 않는다면 문제입니다.

## 교차 브라우저 문제는 왜 생길까요?

교차 브라우저 문제가 생기는 이유는 여러 가지입니다.

- 브라우저마다 버그가 있거나 표준을 구현하는 방식이 조금씩 다릅니다.
- 브라우저마다 지원하는 기능이 다릅니다. 최신 CSS나 JavaScript 기능은 오래된 브라우저에서 동작하지 않을 수 있습니다.
- 기기마다 제약이 있습니다. 넓은 화면에 맞춘 레이아웃은 작은 화면에서 깨질 수 있고, 무거운 스크립트는 저사양 기기에서 느려질 수 있습니다.

## 테스팅 작업 흐름

교차 브라우저 테스팅은 프로젝트 마지막에 한꺼번에 몰아서 하는 일이 아닙니다. 개발 과정 내내 꾸준히 하는 것이 좋습니다. 일반적인 흐름은 다음과 같습니다.

### 1. 초기 계획

먼저 대상 사용자와 그들이 사용할 브라우저·기기를 파악합니다. 기존 사이트의 방문자 통계나 [Can I use](https://caniuse.com/) 같은 자료를 참고해 지원 브라우저 목록을 정합니다. 보통은 다음과 같이 등급을 나눕니다.

- **A등급**: 널리 쓰이는 최신 브라우저. 모든 기능이 완벽하게 동작해야 합니다.
- **C등급**: 오래되었거나 잘 쓰이지 않는 브라우저. 기본 기능만 동작하면 됩니다.

### 2. 개발

기능을 구현할 때 대체 수단을 함께 고려합니다. [점진적 향상](/ko/docs/Glossary/Progressive_Enhancement) 전략을 따르면 모든 브라우저에서 동작하는 기본 경험을 먼저 만들고, 이를 지원하는 브라우저에서는 더 나은 경험을 더할 수 있습니다.

```css
.container {
  display: block; /* 기본 레이아웃 */
}

@supports (display: grid) {
  .container {
    display: grid;
    grid-template-columns: repeat(3, 1fr);
  }
}
```

### 3. 테스트와 발견

기능 하나를 구현할 때마다 테스트합니다. 먼저 자주 쓰는 안정적인 브라우저에서 테스트한 뒤, 접근성 검사를 하고, 지원 목록에 있는 다른 브라우저로 넓혀 갑니다. 다음과 같은 방법을 사용할 수 있습니다.

- 실제 기기와 브라우저에서 직접 테스트하기
- 브라우저 개발자 도구의 반응형 디자인 모드 활용하기
- 가상 머신이나 에뮬레이터 사용하기
- 클라우드 기반 테스트 서비스 이용하기
- Playwright, Selenium 같은 도구로 테스트 자동화하기

### 4. 수정과 반복

문제를 찾았다면 원인이 특정 브라우저에만 있는지, 모든 브라우저에서 생기는지 확인합니다. 원인을 좁힌 뒤 고치고, 고친 내용이 다른 브라우저에서 새로운 문제를 일으키지 않는지 다시 테스트합니다.

## 요약

교차 브라우저 테스팅은 더 많은 사람이 웹사이트를 문제없이 사용하게 하는 데 꼭 필요한 과정입니다. 지원 대상을 미리 정하고, 점진적 향상으로 개발하며, 개발 과정 내내 꾸준히 테스트하면 브라우저 호환성 문제를 크게 줄일 수 있습니다.
