## 🚀 이달의 주요 릴리스

### Vue 3.5 정식 출시

9월 초 Vue 3.5가 정식 출시되었습니다. 이번 릴리스의 핵심은 반응형 시스템의 내부 구현을 다시 설계한 것입니다. 새 구현으로 메모리 사용량이 크게 줄었고, 업데이트 처리 성능도 개선되었습니다. 대규모 화면을 다루는 프로젝트라면 체감 차이가 클 수 있습니다.

사용자가 체감할 수 있는 변화도 여럿 포함되었습니다.

- **`useTemplateRef()`**: 템플릿의 `ref`를 문자열 키 대신 변수로 명시적으로 참조할 수 있습니다. 타입 추론이 좋아져 실수를 줄일 수 있습니다.
- **`useId()`**: 서버 렌더링과 클라이언트 렌더링에서 일관된 고유 ID를 만들어 줍니다. 접근성 속성을 다룰 때 유용합니다.
- **Reactive Props Destructure 안정화**: props를 구조 분해 할당해도 반응성이 유지됩니다. 기존 `toRefs`를 쓰던 코드를 단순화할 수 있습니다.
- **지연 하이드레이션(Lazy Hydration)**: 컴포넌트마다 하이드레이션 시점을 조절할 수 있어, 초기 로딩 비용을 줄이는 데 도움이 됩니다.

기존 프로젝트를 업그레이드할 때는 변경 사항 문서를 먼저 읽고, 테스트를 충분히 돌려 보는 것을 권장합니다.

### TypeScript 5.6

9월 말 TypeScript 5.6이 출시되었습니다. 이번 버전은 실수를 일찍 잡아내는 검사가 강화된 것이 특징입니다.

가장 눈에 띄는 변화는 **항상 참이거나 항상 거짓인 조건문에 대한 오류 표시**입니다. 예를 들어 정규식 리터럴을 그대로 `if`에 넣거나, 함수 자체를 조건으로 쓰는 코드는 이제 컴파일 단계에서 경고를 받습니다. 의도하지 않은 조건 검사를 찾아내기 좋습니다.

또한 이터레이터 관련 타입이 정비되었습니다. `--strictBuiltinIteratorReturn` 옵션을 켜면 내장 이터레이터의 반환 타입을 더 엄격하게 검사할 수 있습니다. `--noUncheckedSideEffectImports` 옵션도 추가되어, 타입 검사가 되지 않는 부수 효과 임포트를 찾는 데 도움이 됩니다.

## 🌐 브라우저 소식

9월에는 Safari 18(9월 중순)과 Chrome 129가 공개되었습니다. 두 브라우저 모두 새로운 웹 플랫폼 기능과 개발자 도구 개선이 포함되었습니다.

프론트엔드 개발자 입장에서 중요한 점은 **새 기능을 도입하기 전에 지원 범위를 확인하는 습관**입니다. MDN의 브라우저 호환성 표나 Can I use 같은 서비스를 참고하면 실무에서 필요한 기능이 어느 브라우저에서 지원되는지 빠르게 파악할 수 있습니다. 특히 사내 서비스처럼 브라우저 버전을 통제할 수 있는 환경이 아니라면, 점진적 향상(progressive enhancement) 방식으로 기능을 도입하는 것이 안전합니다.

## 🔐 보안 이슈: npm 패키지 탈취 사건

이달 초 npm에서 큰 보안 사고가 있었습니다. `chalk`, `debug`, `ansi-styles` 등 주간 다운로드 수가 매우 많은 패키지의 관리자 계정이 피싱으로 탈취되었고, 악성 코드가 포함된 새 버전이 배포되었습니다.

악성 코드는 브라우저에서 암호화폐 지갑 주소를 몰래 바꿔치기하는 기능을 가지고 있었습니다. 다행히 사고가 빠르게 감지되어 문제가 된 버전은 짧은 시간 안에 제거되었지만, 짧은 시간 동안이라도 설치된 프로젝트는 영향을 받았을 수 있습니다.

이 사건은 우리에게 다음과 같은 점을 알려 줍니다.

1. **잠금 파일(lockfile)을 커밋하고 `npm ci`로 설치하세요.** 설치 버전이 매번 바뀌는 것을 막아 줍니다.
2. **새로 배포된 버전을 바로 반영하지 않도록 설정하는 방법을 검토하세요.** 의존성 자동 업데이트 도구에서 최소 숙성 기간을 두는 설정을 사용할 수 있습니다.
3. **`npm audit signatures` 같은 명령으로 패키지 서명과 출처를 확인하세요.**
4. **계정 보안을 강화하세요.** 패키지를 배포하는 계정에는 반드시 2단계 인증을 적용해야 합니다.

의존성이 많은 프론트엔드 프로젝트일수록 공급망 보안은 더 이상 선택이 아닌 기본 점검 항목입니다.

## 🧰 도구와 생태계

### 프레임워크 동향

React 생태계에서는 React 19의 정식 출시를 기다리는 분위기가 이어졌습니다. 자동 메모이제이션을 해 주는 **React Compiler**에 대한 관심도 높아졌습니다. 수동으로 `useMemo`와 `useCallback`을 나열하던 코드를 줄일 수 있다는 기대가 큽니다. 다만 컴파일러가 모든 최적화를 대신해 주는 것은 아니므로, 도입 전에는 성능 측정을 함께 하는 것이 좋습니다.

### 빌드와 린트 도구

Rust로 작성된 도구가 빠르게 성장하고 있습니다. 린터와 포매터를 하나로 묶은 Biome, Oxc 프로젝트 등이 대표적입니다. 대규모 저장소에서 린트 시간이 길어져 고민이었다면, 이런 도구의 도입을 검토해 볼 만합니다. 기존 ESLint 설정을 모두 옮기기 어렵다면, 일부 규칙만 병행해서 검증하는 방식으로 시작해도 좋습니다.

### 테스트 환경

단위 테스트와 컴포넌트 테스트 도구도 계속 발전하고 있습니다. Vite 기반 프로젝트에서는 Vitest가 사실상 기본 선택지가 되었고, 브라우저에서 실제로 실행되는 컴포넌트 테스트에 대한 관심도 커졌습니다. 테스트를 어떤 계층에서 얼마나 작성할지 팀 차원의 기준을 세워 두면 도구가 바뀌어도 흔들리지 않습니다.
