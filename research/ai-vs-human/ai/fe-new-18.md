## 1. 언어와 빌드 도구: "더 빠르게"가 표준이 된다

### TypeScript의 네이티브 전환
TypeScript 컴파일러를 네이티브 코드로 옮기는 작업은 이제 "실험"이 아니라 "도입 시점을 고민하는 단계"에 들어왔습니다. 대형 모노레포에서 타입 체크 시간이 크게 줄어든다는 보고가 이어지고 있습니다. 에디터 응답성도 함께 좋아지고 있습니다.

**이번 달 체크포인트**
- CI의 `tsc` 단계 소요 시간을 먼저 측정해 두세요. 전환 효과를 숫자로 비교할 수 있습니다.
- 커스텀 컴파일러 API나 트랜스포머 플러그인에 의존한다면 호환성부터 확인하세요.

### Rust 기반 번들러의 부상
Vite 생태계는 Rolldown 중심으로 번들러를 통합하는 방향으로 움직이고 있습니다. 개발 서버와 프로덕션 빌드의 동작 차이를 줄이는 것이 핵심 목표입니다. 기존 Rollup 플러그인과의 호환 범위가 도입 여부를 가르는 기준이 되고 있습니다.

### Node.js의 TypeScript 지원
Node.js가 타입 어노테이션을 제거해 실행하는 기능을 점차 안정화하고 있습니다. 스크립트나 도구용 코드는 별도 빌드 없이 `.ts` 파일을 바로 실행하는 방식이 자리 잡는 중입니다. 다만 `enum`처럼 런타임 코드가 필요한 문법은 제약이 있으니 주의하세요.

## 2. 프레임워크: 컴파일러가 일을 대신한다

### React
- **React Compiler**를 실제 서비스에 적용한 사례가 늘고 있습니다. `useMemo`, `useCallback`을 손으로 다는 일이 줄어드는 대신, **"컴파일러가 최적화할 수 있는 코드"를 쓰는 습관**이 중요해졌습니다. 렌더링 중 부수 효과를 일으키는 코드나 props를 직접 변경하는 코드가 대표적인 방해 요소입니다.
- 서버 컴포넌트는 Next.js 외의 환경에서도 쓰려는 시도가 이어지고 있습니다. 라우터와 번들러가 각자 해석하던 부분을 표준화하려는 논의도 진행 중입니다.

### Vue, Svelte, Angular
- **Vue**는 Vapor 모드(가상 DOM 없는 컴파일 전략)의 완성도를 높이는 중입니다. 기존 컴포넌트와 섞어 쓸 수 있는지가 관건입니다.
- **Svelte**는 Runes 기반 반응성이 안정되면서 생태계 라이브러리들이 빠르게 맞춰 가고 있습니다.
- **Angular**는 Signals 중심 구조로 Zone.js 의존을 줄이는 방향이 이제 기본 권장 경로가 되었습니다.

네 프레임워크가 공통으로 가는 방향은 **세밀한 반응성(fine-grained reactivity)과 컴파일 타임 최적화**입니다. 어떤 프레임워크를 쓰든 이 개념을 이해해 두면 이직이나 마이그레이션 때 도움이 됩니다.

## 3. 웹 플랫폼: CSS가 JS의 일을 가져간다

### 이제 써도 되는 CSS 기능들
| 기능 | 대체하는 것 | 비고 |
|---|---|---|
| Container Queries | 뷰포트 기반 미디어 쿼리 | 컴포넌트 단위 반응형 |
| `:has()` | 부모 상태 제어용 JS | 폼 검증 스타일에 유용 |
| Anchor Positioning | Popper 류 라이브러리 | 툴팁·팝오버 배치 |
| View Transitions | 페이지 전환 애니메이션 JS | MPA에서도 사용 가능 |
| Scroll-driven Animations | 스크롤 이벤트 리스너 | 성능상 이점이 큼 |

모든 브라우저에서 같은 수준으로 동작하는 것은 아니므로, 도입 전에 **Baseline 상태**를 확인하는 습관을 권합니다. MDN이나 web.dev에서 해당 기능이 Baseline인지 보면 됩니다.

### Interop과 브라우저 호환성
브라우저 벤더들이 해마다 호환성 목표를 공동으로 정하는 Interop 프로젝트 덕분에 엔진 간 차이가 눈에 띄게 줄었습니다. 올해 목표 항목들의 진척도는 공개 대시보드에서 확인할 수 있습니다.

### Temporal API
오랫동안 기다려 온 `Temporal`이 브라우저와 런타임에 하나둘 들어오고 있습니다. `Date`의 시간대와 불변성 문제를 해결하므로, 날짜 라이브러리 의존을 줄일 수 있는지 검토해 볼 시점입니다.

## 4. AI와 프론트엔드 개발

### 코딩 에이전트가 일상이 되었다
컴포넌트 초안 작성, 테스트 생성, 마이그레이션 같은 반복 작업을 에이전트에 맡기는 팀이 늘고 있습니다. 현업에서 효과를 본 방식은 대체로 비슷합니다.

1. **작은 단위로 위임하기**: "페이지 전체"보다 "이 컴포넌트를 Container Query로 바꿔 줘"가 결과가 좋습니다.
2. **검증 수단을 먼저 준비하기**: 타입 체크, 린트, 시각적 회귀 테스트가 있어야 결과를 믿을 수 있습니다.
3. **프로젝트 규칙을 문서로 남기기**: 디자인 토큰, 네이밍, 금지 패턴을 문서화하면 에이전트와 신규 팀원 모두에게 도움이 됩니다.

### 접근성이 더 중요해진다
유럽 접근성 법(EAA)이 시행되면서 접근성은 "있으면 좋은 것"에서 "지켜야 할 요건"으로 바뀌고 있습니다. 자동 검사 도구는 문제의 일부만 잡아내므로 키보드 조작과 스크린 리더 확인을 병행해야 합니다.
