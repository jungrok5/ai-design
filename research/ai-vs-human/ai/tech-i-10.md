# Array vs ArrayList vs LinkedList

## 1. 핵심 개념

| 구분 | Array | ArrayList | LinkedList |
|---|---|---|---|
| 내부 구조 | 연속된 메모리 블록 | 동적 배열(내부에 Object[]) | 이중 연결 리스트(Node) |
| 크기 | 고정 | 가변(자동 확장) | 가변 |
| 저장 타입 | 기본형과 참조형 모두 가능 | 참조형만 가능(오토박싱) | 참조형만 가능 |
| 인덱스 접근 | O(1) | O(1) | O(n) |
| 끝에 삽입 | 불가(크기 고정) | 분할 상환 O(1) | O(1) |
| 중간 삽입·삭제 | O(n) | O(n) | 탐색 O(n) + 연결 변경 O(1) |
| 메모리 효율 | 가장 좋음 | 좋음(여유 공간 있음) | 나쁨(노드마다 prev/next 포인터) |

## 2. Array
- 선언할 때 크기가 정해지고 바꿀 수 없습니다.
- 메모리가 연속되어 있어서 **캐시 지역성**이 좋고, `시작 주소 + 인덱스 × 요소 크기`로 바로 접근합니다.
- `int[]`처럼 기본형을 그대로 저장하므로 박싱 비용이 없습니다.

## 3. ArrayList
- 내부 배열이 가득 차면 **약 1.5배 크기**의 새 배열을 만들고 기존 요소를 복사합니다(Java 기준 `oldCapacity + (oldCapacity >> 1)`).
- 복사 비용은 O(n)이지만 자주 일어나지 않으므로 끝에 추가하는 연산은 **분할 상환(amortized) O(1)**입니다.
- 중간에 삽입하거나 삭제하면 `System.arraycopy`로 뒤쪽 요소를 밀거나 당겨야 해서 O(n)이 걸립니다.
- 넣을 데이터 양을 미리 알면 `new ArrayList<>(capacity)`로 재할당 횟수를 줄일 수 있습니다.

## 4. LinkedList
- 각 노드가 `item`, `prev`, `next`를 가지는 **이중 연결 리스트**입니다.
- 맨 앞과 맨 뒤의 삽입·삭제는 O(1)이라서 `Deque`나 `Queue` 구현체로도 쓰입니다.
- `get(i)`는 head나 tail 중 가까운 쪽부터 따라가야 하므로 O(n)입니다.
- 노드가 힙 곳곳에 흩어져 있어서 **캐시 미스**가 많고 GC 부담도 큽니다.

## 5. 면접 단골 질문

**Q1. 중간 삽입이 잦으면 LinkedList가 항상 유리한가요?**
→ 아닙니다. 삽입할 **위치를 찾는 탐색이 O(n)**이고 캐시 효율도 나쁩니다. 그래서 실제로는 ArrayList가 더 빠른 경우가 많습니다. LinkedList가 확실히 유리한 경우는 Iterator로 이미 위치를 잡아 둔 상태에서 삽입·삭제할 때입니다.

**Q2. ArrayList의 add가 O(1)인 이유는 무엇인가요?**
→ 크기를 늘리며 복사하는 일이 가끔만 일어나고, n번 추가할 때 전체 복사 비용의 합이 O(n)입니다. 따라서 한 번 추가하는 평균 비용은 O(1)입니다.

**Q3. 실무에서는 무엇을 기본으로 쓰나요?**
→ 대부분 **ArrayList**를 씁니다. 양쪽 끝에서 넣고 빼는 큐나 스택이 필요하면 LinkedList보다 **ArrayDeque**를 권장합니다.

**Q4. Array와 ArrayList는 언제 구분해서 쓰나요?**
→ 크기가 고정되어 있고 기본형을 많이 다루는 성능 중심 코드에는 Array를 씁니다. 크기가 바뀌고 Collections API나 제네릭이 필요하면 ArrayList를 씁니다.

**Q5. 스레드 안전한가요?**
→ 셋 다 동기화되어 있지 않습니다. 필요하면 `Collections.synchronizedList`나 `CopyOnWriteArrayList`를 사용합니다.

## 6. 한 줄 요약
> **조회 위주면 Array나 ArrayList, 양쪽 끝 삽입·삭제 위주면 ArrayDeque를 씁니다. LinkedList는 이론상 장점이 있지만 실제로 이득을 보는 경우는 드뭅니다.**
