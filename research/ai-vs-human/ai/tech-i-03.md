# Paging and Segmentation

## 1. 개요
가상 메모리는 프로세스가 사용하는 **논리 주소**를 **물리 주소**로 변환해, 프로세스마다 독립된 주소 공간을 제공합니다. 이 변환을 구현하는 대표적인 방식이 **페이징(Paging)**과 **세그멘테이션(Segmentation)**입니다.

## 2. 페이징 (Paging)
- 논리 주소 공간을 고정 크기의 **페이지(page)**로, 물리 메모리를 같은 크기의 **프레임(frame)**으로 나눕니다.
- 주소는 `페이지 번호(p) + 오프셋(d)`으로 구성됩니다.
- 페이지 번호로 **페이지 테이블**을 조회해 프레임 번호를 얻고, 오프셋을 그대로 붙여 물리 주소를 만듭니다.
- 크기가 고정되어 있으므로 **외부 단편화가 없고**, 마지막 페이지에서 **내부 단편화**만 발생합니다.
- 변환할 때마다 메모리 참조가 추가되므로, 자주 쓰는 변환은 **TLB(Translation Lookaside Buffer)**에 캐싱합니다.
- 주소 공간이 크면 페이지 테이블도 커지므로 **다단계 페이지 테이블**이나 역 페이지 테이블로 줄입니다.

## 3. 세그멘테이션 (Segmentation)
- 프로그램을 함수, 배열, 스택처럼 **의미 단위인 세그먼트**로 나눕니다.
- 주소는 `세그먼트 번호(s) + 오프셋(d)`으로 구성되며, **세그먼트 테이블**의 base(시작 주소)와 limit(길이)으로 변환합니다.
- 오프셋이 limit을 넘으면 세그멘테이션 폴트가 발생합니다.
- 논리 단위에 맞춰 **공유와 보호**를 적용하기 쉽습니다.
- 크기가 제각각이라 **외부 단편화**가 생기며, 이를 해결하려면 압축이나 재배치가 필요합니다.

## 4. 비교

| 구분 | 페이징 | 세그멘테이션 |
|---|---|---|
| 단위 | 고정 크기 | 가변 크기, 논리적 의미 |
| 단편화 | 내부 단편화 | 외부 단편화 |
| 사용자 관점 | 투명하지 않음 | 투명함 |
| 관리 테이블 | 페이지 테이블 | 세그먼트 테이블 |

현대 OS는 보통 페이징을 중심으로 사용하며, 세그멘테이션은 보호와 공유를 위해 보조적으로 결합되는 경우가 많습니다.

## 5. 면접 핵심 포인트
- **페이지 폴트**: 필요한 페이지가 메모리에 없으면 트랩이 발생하고, OS가 디스크(스왑)에서 프레임으로 페이지를 가져온 뒤 명령을 재실행합니다.
- **페이지 크기 trade-off**: 작으면 내부 단편화와 디스크 I/O 횟수는 줄지만 페이지 테이블이 커집니다. 크면 테이블은 작아지지만 내부 단편화와 불필요한 I/O가 늘어납니다.
