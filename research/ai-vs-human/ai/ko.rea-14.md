# React 블로그

React 블로그는 React 팀이 릴리스, 설계 방향, 연구 중인 기능, 행사 소식을 공유하는 공간입니다. 새 버전이 나왔을 때 무엇이 바뀌었는지 확인하거나, React가 앞으로 어디로 향하는지 파악하고 싶을 때 이 페이지에서 시작하면 됩니다.

이 페이지는 블로그의 성격을 설명하고, 게시물 종류별로 무엇을 읽으면 좋은지 안내합니다.

---

## 블로그의 목적

React 블로그는 다음 세 가지 목적을 가집니다.

1. **릴리스 공지**: 새 버전의 주요 변경 사항, 파괴적 변경(breaking change), 마이그레이션 방법을 알립니다.
2. **방향성 공유**: 팀이 연구 중인 기능과 설계 철학을 설명합니다. 아직 정식 출시되지 않은 기능도 포함될 수 있습니다.
3. **커뮤니티 소통**: React Conf 같은 행사 소식과 오픈 소스 기여에 관한 안내를 전합니다.

블로그 글은 공식 문서를 대체하지 않습니다. 기능의 세부 사용법은 [react.dev](https://react.dev)의 레퍼런스와 가이드에서 확인하고, 블로그는 배경과 맥락을 이해하는 용도로 활용하는 것이 좋습니다.

---

## 게시물 종류

블로그 게시물은 대략 다음과 같이 분류됩니다.

| 종류 | 목적 | 언제 읽으면 좋은가 |
|---|---|---|
| 릴리스 게시물 | 새 버전 출시 발표 | 버전을 올리기 전 |
| 업그레이드 가이드 | 마이그레이션 단계 설명 | 메이저 버전을 적용할 때 |
| React Labs | 실험 중인 기능과 연구 현황 | 다음 방향을 미리 알고 싶을 때 |
| 이벤트 및 컨퍼런스 | 행사 발표 요약 | 팀의 최신 생각을 살펴볼 때 |
| 커뮤니티 및 기여 | 오픈 소스 운영 소식 | 프로젝트에 참여하고 싶을 때 |

게시물에는 보통 **요약, 주요 변경 사항, 예제 코드, 다음 단계**가 포함됩니다. 긴 글이라면 목차를 먼저 훑어보고 필요한 부분만 골라 읽는 방식도 효율적입니다.

---

## 주요 게시물 살펴보기

### React 19 릴리스

React 19는 서버 렌더링 환경과 폼 처리를 중심으로 많은 변화를 담은 버전입니다. 블로그 게시물에서 다룬 핵심 내용은 다음과 같습니다.

- **Actions**: 비동기 전환(transition) 상태를 자동으로 관리하는 함수를 작성할 수 있습니다. 폼 제출 시 보류(pending) 상태와 오류 처리를 쉽게 구현할 수 있습니다.
- **`use` API**: Promise와 Context를 렌더링 중에 읽을 수 있습니다.
- **`ref`를 prop으로 전달**: 더 이상 `forwardRef`를 필수로 사용하지 않아도 됩니다.
- **문서 메타데이터**: `<title>`, `<meta>`, `<link>` 태그를 컴포넌트 안에 두면 자동으로 `<head>`로 끌어올려집니다.

```jsx
function SearchForm() {
  async function search(formData) {
    const query = formData.get('query');
    await submitSearch(query);
  }

  return (
    <form action={search}>
      <input name="query" />
      <button type="submit">검색</button>
    </form>
  );
}
```

업그레이드할 때는 **업그레이드 가이드**를 함께 확인하세요. 제거된 API와 변경된 동작을 한눈에 볼 수 있습니다.

### React Compiler

React Compiler는 빌드 시점에 코드를 분석해 불필요한 리렌더링을 줄이는 도구입니다. 개발자가 `useMemo`, `useCallback`, `memo`를 일일이 붙이지 않아도 적절한 메모이제이션을 적용합니다.

블로그에서는 컴파일러가 어떻게 동작하는지, 어떤 규칙(예: 렌더링 중 부수 효과 금지, 불변성 유지)을 지켜야 하는지 설명합니다. 기존 코드에 적용하기 전에 **Rules of React** 문서를 먼저 읽는 것을 권장합니다.

### React Server Components

서버 컴포넌트는 데이터 접근 코드를 서버에 머물게 하면서, 클라이언트로 전달되는 JavaScript 양을 줄이는 방식입니다. 블로그의 관련 게시물은 서버 컴포넌트와 클라이언트 컴포넌트의 경계, 그리고 프레임워크에서 이를 활용하는 방법을 다룹니다.

## React Labs 게시물 읽기

React Labs 게시물은 아직 정식 릴리스되지 않은 기능이나 연구 결과를 소개합니다. 이런 글을 읽을 때는 다음을 염두에 두세요.

- 설명된 API가 **최종 형태가 아닐 수 있습니다.**
- 실험 단계의 기능은 프로덕션 코드에 바로 적용하지 않는 것이 안전합니다.
- 게시물에 제시된 **문제 정의**는 기능이 왜 필요한지 이해하는 데 가장 도움이 됩니다.

---

## 최신 소식 확인 방법

- 공식 사이트의 블로그 페이지에서 최신 게시물 목록을 확인할 수 있습니다.
- 메이저 릴리스 전에는 **업그레이드 가이드**가 함께 공개되는 경우가 많습니다.
- 행사 발표 영상과 슬라이드는 이벤트 게시물에 링크로 연결되어 있습니다.

## 피드백과 기여

블로그 내용에 오류가 있거나 개선할 점이 보이면 React 공식 GitHub 저장소에 이슈를 남기거나 문서 수정 제안(Pull Request)을 올릴 수 있습니다. 문서 기여 가이드는 저장소의 `CONTRIBUTING.md` 파일에서 확인할 수 있습니다.

커뮤니티 질문은 공식 포럼이나 React 관련 커뮤니티 채널에서 나누면 됩니다. 버그 리포트는 재현 가능한 예제와 함께 이슈 트래커에 등록하는 것이 가장 빠른 해결 방법입니다.

---

## 요약

- React 블로그는 **릴리스 소식, 설계 방향, 커뮤니티 소통**을 위한 공간입니다.
- 버전을 올릴 때는 **릴리스 게시물과 업그레이드 가이드**를 먼저 읽으세요.
- **React Labs** 글은 방향성을 이해하는 데 유용하지만, 실험 기능은 최종 API가 아닐 수 있습니다.
- 세부 사용법은 공식 문서에서, 배경과 맥락은 블로그에서 확인하는 방식이 좋습니다.
