# 프론트엔드 소식 | 2025-12

안녕하세요, 이번 달 프론트엔드 소식을 모았습니다. 2025년 마지막 호에서는 보안 이슈, 프레임워크와 빌드 도구의 변화, 브라우저 업데이트, 그리고 올해를 돌아보는 이야기를 다룹니다.

> ⚠️ 버전과 날짜 같은 세부 내용은 도입 전에 공식 릴리스 노트로 한 번 더 확인해 주세요.

## 🛡️ 1. React Server Components 취약점, 꼭 확인하세요

12월 초 React Server Components와 관련해 **원격 코드 실행(RCE)으로 이어질 수 있는 심각한 취약점**(CVE-2025-55182, 일명 *React2Shell*)이 공개되었습니다. React 팀과 Next.js 팀은 패치 버전을 배포했습니다.

**체크리스트**
- `react-server-dom-*` 패키지와 `react`, `next` 버전이 패치 버전 이상인지 확인합니다.
- App Router나 RSC를 쓰는 프로젝트는 락 파일까지 점검합니다.
- Remix 계열이나 모노레포 내부의 간접 의존성도 `npm ls`로 확인합니다.
- 호스팅 플랫폼이 제공하는 임시 방어 규칙(WAF)이 있더라도 근본 대응은 업그레이드입니다.

**교훈**: 서버와 클라이언트의 경계가 얇아질수록 프론트엔드 개발자도 **서버 보안 책임의 일부**를 지게 됩니다. 의존성 업데이트 자동화(Renovate, Dependabot)와 보안 공지 구독을 팀 프로세스에 넣어 두세요.

## ⚙️ 2. 프레임워크와 라이브러리 동향

### React와 Next.js
- **React 19.2**의 `<Activity>`, `useEffectEvent` 같은 기능이 실무에 퍼지고 있습니다.
- **Next.js 16** 계열은 Turbopack 기본 적용, 캐싱 모델 개선, React Compiler 지원 안정화로 정리되는 중입니다. 마이너 업데이트로 개발 경험을 다듬고 있습니다.
- React Compiler를 켜면 `useMemo`, `useCallback`을 줄일 수 있지만, **기존 코드에 일괄 적용하기 전에 점진적으로 검증**하는 것이 안전합니다.

### Angular
- **Angular 21**이 Signal 기반 방향을 이어갑니다. Zoneless 변화 감지와 Signal Forms 같은 흐름이 핵심입니다.
- 테스트 러너도 Vitest 쪽으로 이동하는 분위기입니다.

### Vue / Svelte
- Vue는 **Vapor Mode**(가상 DOM 없는 컴파일 전략) 실험이 계속되고 있습니다.
- Svelte 5의 Runes 기반 생태계가 안정되면서 SvelteKit 관련 도구도 정리되고 있습니다.

## 🧰 3. 빌드 도구와 개발 환경

### Vite 8 베타와 Rolldown
Vite가 개발 서버(esbuild)와 프로덕션 빌드(Rollup)로 나뉘어 있던 구조를 **Rust 기반 Rolldown**으로 통합하는 방향이 베타로 공개되었습니다.
- 기대 효과: 개발과 프로덕션 환경의 불일치 감소, 대형 프로젝트 빌드 시간 단축
- 주의점: 플러그인 호환성을 먼저 확인하세요. 사이드 프로젝트에서 먼저 시험해 볼 것을 권합니다.

### TypeScript
- 컴파일러를 Go로 포팅하는 **네이티브 TypeScript(7.0 계열)** 프리뷰가 진행 중이며, 에디터 응답성과 빌드 시간 개선 사례가 공유되고 있습니다.
- 대형 모노레포를 운영한다면 프리뷰를 CI에 병행 실행해 **호환성 차이만 먼저 수집**하는 방식이 현실적입니다.

### Node.js와 테스트
- Node.js 24가 LTS로 자리 잡는 중이고, 25 버전은 최신 기능을 시험하는 용도로 쓰입니다.
- **Vitest 4**의 Browser Mode와 시각적 회귀 테스트 기능이 컴포넌트 테스트의 선택지를 넓혀 주고 있습니다.

## 🌐 4. 웹 플랫폼과 브라우저

- **Chrome / Safari / Firefox** 모두 12월에 정기 업데이트를 배포했습니다.
- 최근 주목할 만한 CSS 기능
  - `@scope`: 스타일 범위를 선언적으로 제한
  - `anchor positioning`: 툴팁과 팝오버 배치를 CSS만으로 처리
  - `popover` 속성, `<dialog>` 개선: 접근성이 좋은 오버레이를 JS 없이 구현
  - View Transitions: 페이지 전환 애니메이션의 표준화
- **Interop 프로젝트**는 브라우저 간 호환성 개선 목표를 매년 정리해 발표합니다. 다음 해 우선순위를 보면 어떤 기능을 도입해도 안전한지 가늠하기 좋습니다.

**실무 팁**: 새 CSS 기능은 `@supports`로 감싸서 점진적으로 적용하고, [Baseline](https://web.dev/baseline) 상태를 기준으로 도입 시점을 정하세요.

## 🤖 5. AI 시대의 프론트엔드 개발

- AI 코딩 도구가 컴포넌트 생성과 리팩터링의 일상적인 부분이 되었습니다.
- 반대로 **리뷰 부담은 커졌습니다**. 생성된 코드의 접근성, 번들 크기, 상태 관리 일관성을 사람이 확인하는 체크리스트가 필요합니다.
- 디자인 시스템과 토큰, 타입이 탄탄한 팀일수록 AI 도구의 결과물이 좋다는 경험담이 많습니다. **좋은 기반이 곧 좋은 프롬프트**입니다.
