# 렌더링 그리고 커밋

컴포넌트가 화면에 나타나려면 React가 먼저 그 컴포넌트를 **렌더링**해야 합니다. 렌더링은 React가 컴포넌트 함수를 호출해 화면에 무엇을 보여줄지 계산하는 과정입니다. 계산된 결과를 실제 DOM에 반영하는 과정은 **커밋**이라고 합니다. 이 페이지에서는 화면이 업데이트되는 과정을 세 단계로 나누어 살펴봅니다.

화면을 업데이트하는 과정은 다음과 같습니다.

1. **렌더링 촉발하기**: 컴포넌트가 처음 나타나거나 상태가 바뀌어 다시 그려야 한다는 신호를 보냅니다.
2. **컴포넌트 렌더링하기**: React가 컴포넌트 함수를 호출해 결과를 계산합니다.
3. **DOM에 커밋하기**: React가 계산 결과와 이전 결과의 차이만큼 DOM을 변경합니다.

---

## 레스토랑에 비유하기

레스토랑 주방을 떠올려 봅시다. 손님이 주문을 하면 웨이터가 주문서를 주방에 전달하고, 주방에서 요리가 만들어지면 웨이터가 그것을 손님 테이블에 내놓습니다.

- **주문을 받는 일**은 렌더링을 촉발하는 것과 같습니다.
- **주방에서 요리를 만드는 일**은 컴포넌트를 렌더링하는 것과 같습니다.
- **요리를 테이블에 내놓는 일**은 DOM에 커밋하는 것과 같습니다.

주방이 요리를 만드는 동안에는 손님의 테이블이 바뀌지 않습니다. 요리가 완성되어 테이블에 놓이는 순간에 비로소 손님이 결과를 봅니다. React도 마찬가지로, 렌더링을 마치기 전에는 DOM을 건드리지 않습니다.

---

## 1단계: 렌더링 촉발하기

렌더링이 일어나는 원인은 두 가지입니다.

### 초기 렌더링

앱이 처음 시작될 때 React는 루트 컴포넌트를 렌더링해야 합니다. `createRoot`로 루트를 만들고 `render`를 호출하면 이 과정이 시작됩니다.

```jsx
import { createRoot } from 'react-dom/client';
import Gallery from './Gallery';

const root = createRoot(document.getElementById('root'));
root.render(<Gallery />); // 여기서 초기 렌더링이 촉발됩니다.
```

### 상태 업데이트에 의한 리렌더링

컴포넌트의 상태가 `set` 함수로 바뀌면 React는 그 컴포넌트를 다시 렌더링합니다. 이때 상태 업데이트가 렌더링을 촉발합니다.

```jsx
function Counter() {
  const [count, setCount] = useState(0);

  return (
    <button onClick={() => setCount(count + 1)}>
      {count}번 클릭함
    </button>
  );
}
```

버튼을 누르면 `setCount`가 호출되고, React는 `Counter`를 다시 렌더링합니다. 이처럼 상태 업데이트는 렌더링을 촉발하는 대표적인 방법입니다.

---

## 2단계: 컴포넌트 렌더링하기

렌더링이 촉발되면 React는 루트 컴포넌트부터 시작해 필요한 컴포넌트들을 호출합니다. 처음 렌더링되는 컴포넌트는 **마운트**되고, 이미 화면에 있던 컴포넌트가 다시 호출되는 경우는 **리렌더링**이라고 합니다.

React는 컴포넌트 함수가 반환한 JSX를 보고, 그 결과로 화면에 무엇이 있어야 하는지 계산합니다. 이 계산 결과를 흔히 **가상 DOM** 또는 렌더 트리라고 부릅니다.

### 렌더링은 순수해야 합니다

렌더링 단계의 가장 중요한 원칙은 **순수성**입니다. 컴포넌트는 같은 입력(props, state, context)이 주어지면 항상 같은 JSX를 반환해야 합니다. 렌더링 중에 외부 상태를 바꾸면 이 원칙이 깨집니다.

```jsx
let guestCount = 0;

// 잘못된 예: 렌더링 중에 외부 변수를 변경합니다.
function Cup() {
  guestCount = guestCount + 1; // 부수 효과
  return <h2>차 한 잔 드실 손님 {guestCount}번째</h2>;
}
```

위 코드는 렌더링할 때마다 결과가 달라지므로 예측할 수 없습니다. 값을 바꾸고 싶다면 `useState`를 사용하거나, 렌더링 밖의 이벤트 핸들러나 `useEffect`에서 처리해야 합니다.

```jsx
// 올바른 예: 지역 변수로 계산합니다.
function Cup({ guest }) {
  return <h2>차 한 잔 드실 손님 {guest}번째</h2>;
}
```

React는 개발 모드에서 `StrictMode`를 사용하면 컴포넌트를 두 번 호출하기도 합니다. 이는 렌더링이 순수한지 확인하기 위한 장치입니다. 두 번 호출했을 때 결과가 달라진다면 렌더링 로직에 문제가 있다는 뜻입니다.

---

## 3단계: DOM에 커밋하기

렌더링이 끝나면 React는 결과를 DOM에 반영합니다. 이 단계를 **커밋**이라고 합니다.

- **초기 렌더링**에서는 `appendChild` 같은 DOM API를 사용해 모든 노드를 화면에 추가합니다.
- **리렌더링**에서는 이전 결과와 새 결과를 비교해, 실제로 바뀐 부분만 DOM에 변경합니다. 텍스트가 바뀌었다면 텍스트 노드만 갱신하고, 바뀌지 않은 요소는 건드리지 않습니다.

이처럼 React는 필요한 변경만 최소한으로 적용하기 때문에 빠르게 동작합니다.

커밋이 끝나면 React는 DOM 노드를 가리키는 `ref`를 연결하고, 생명주기 효과를 실행합니다.

- **`useLayoutEffect`**: DOM 변경 직후, 브라우저가 화면을 그리기 전에 실행됩니다. 측정이나 위치 조정처럼 화면에 보이기 전에 끝내야 하는 작업에 적합합니다.
- **`useEffect`**: 브라우저가 화면을 그린 뒤에 실행됩니다. 데이터 요청이나 구독 설정처럼 화면 표시를 막으면 안 되는 작업에 적합합니다.

---

## 4단계: 브라우저가 화면을 그리기

커밋으로 DOM이 바뀌면 브라우저는 새로운 화면을 **페인트**합니다. 이 단계는 React가 아니라 브라우저가 담당합니다. 개발자 도구에서 '렌더링'이라고 표시되는 것 중 일부가 이 과정이며, React의 렌더링과는 다른 개념입니다.

---

## 정리

| 단계 | 하는 일 | 누가 담당하는가 |
|------|---------|----------------|
| 렌더링 촉발 | 초기 렌더 또는 상태 업데이트로 다시 그릴 신호를 보냄 | 개발자 코드 |
| 렌더링 | 컴포넌트를 호출해 JSX 결과를 계산함 | React |
| 커밋 | 계산 결과와의 차이만큼 DOM을 변경함 | React |
| 페인트 | 바뀐 DOM을 화면에 그림 | 브라우저 |

기억해야 할 핵심은 다음과 같습니다.

- 렌더링은 **계산**이므로 순수해야 합니다. 렌더링 중에는 외부 값을 바꾸지 마세요.
- 커밋은 **실제 DOM 변경**이며, React가 차이만 골라 적용합니다.
- 상태 업데이트는 렌더링을 촉발하지만, 즉시 DOM이 바뀌지는 않습니다. 렌더링과 커밋이 끝나야 화면에 반영됩니다.
