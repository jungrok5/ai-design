# [java] 자바 가상 머신(Java Virtual Machine)

## 1. 개요
JVM(Java Virtual Machine)은 자바 바이트코드(`.class`)를 실행하는 가상의 컴퓨터다. 컴파일러가 소스 코드를 운영체제나 CPU에 종속되지 않는 바이트코드로 바꾸면, 각 플랫폼의 JVM이 이를 해석하고 실행한다. 이 구조 덕분에 "한 번 작성하면 어디서든 실행한다(WORA, Write Once Run Anywhere)"는 자바의 이식성이 가능해진다.

JDK는 컴파일러(javac)와 개발 도구를 포함하고, JRE는 JVM과 표준 라이브러리를 포함한다. JVM은 이 중 실행을 담당하는 핵심 구성요소다.

## 2. 주요 구성 요소
- **클래스 로더(Class Loader)**: `.class` 파일을 읽어 메모리에 적재한다. 부트스트랩 → 플랫폼 → 애플리케이션 순으로 부모에게 먼저 위임하는 **위임 모델(Parent Delegation)**을 따른다.
- **런타임 데이터 영역**
  - **메서드 영역**: 클래스 메타데이터, 정적 변수, 상수 풀을 저장하며 모든 스레드가 공유한다.
  - **힙(Heap)**: 객체와 배열이 저장되는 공간으로 GC의 주 대상이며 모든 스레드가 공유한다.
  - **JVM 스택**: 스레드마다 하나씩 생성되며, 메서드 호출 시마다 지역 변수와 피연산자 스택을 가진 프레임을 쌓는다.
  - **PC 레지스터**, **네이티브 메서드 스택**: 현재 실행 위치와 네이티브 호출을 관리한다.
- **실행 엔진**: 인터프리터가 바이트코드를 한 줄씩 해석하고, JIT(Just-In-Time) 컴파일러는 자주 호출되는 핫스팟 코드를 기계어로 컴파일해 성능을 높인다.
- **가비지 컬렉터(GC)**: 더 이상 참조되지 않는 객체를 자동으로 회수한다.

## 3. 클래스 로딩 과정
1. **로딩**: 바이트코드를 읽어 메서드 영역에 저장한다.
2. **링킹**
   - 검증(Verification): 바이트코드가 안전한지 검사한다.
   - 준비(Preparation): 정적 변수에 타입별 기본값을 할당한다.
   - 해석(Resolution): 심볼릭 참조를 실제 메모리 참조로 바꾼다.
3. **초기화**: 정적 변수의 초기값을 대입하고 `static` 블록을 실행한다.

## 4. 가비지 컬렉션
대부분의 객체는 생성 직후 소멸한다는 **약한 세대 가설**에 따라 힙을 Young 영역(Eden, Survivor)과 Old 영역으로 나눈다. Young 영역은 Minor GC로 빠르게 정리하고, Old 영역은 Major GC(Full GC)로 정리한다. G1, ZGC 등 여러 수집기가 있으며, 처리량과 지연 시간 사이의 균형을 목표로 선택한다.

## 5. 면접 핵심 질문
- **JDK, JRE, JVM의 차이는?** JDK ⊃ JRE ⊃ JVM 순으로 포함되며, 개발 도구·라이브러리·실행 엔진이 각각 대응한다.
- **스택과 힙의 차이는?** 스택은 스레드별로 지역 변수와 호출 정보를 저장하고, 힙은 스레드가 공유하는 객체를 저장한다. 스택 오버플로는 `StackOverflowError`, 힙 부족은 `OutOfMemoryError`로 나타난다.
- **위임 모델의 장점은?** 핵심 클래스(예: `java.lang.String`)가 임의의 클래스로 대체되는 것을 막아 보안과 일관성을 보장한다.
- **인터프리터와 JIT를 함께 쓰는 이유는?** 인터프리터는 시작이 빠르고, JIT는 장기 실행 시 성능을 높인다. 두 방식을 혼합해 두 가지 장점을 모두 얻는다.
