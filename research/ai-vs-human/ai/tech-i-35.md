# GML Test (2019-10-03)

> 개발자 기술 면접 대비 정리 노트입니다. "GML Test"의 출제 범위를 알 수 없어서, 코딩 테스트 이후 기술 면접에서 자주 나오는 주제로 구성했습니다. 실제 시험 범위에 맞게 항목을 가감해서 쓰세요.

## 1. 면접 준비 전략

- **자기소개 (1분)**: 경력, 주력 기술, 지원 동기 순서로 말합니다.
- **답변 구조**: 결론 → 이유 → 경험 사례 순서로 답합니다.
- **모르는 질문**: 아는 범위까지 말하고, 어떻게 확인할지 덧붙입니다.
- **코딩 테스트 복기**: 풀었던 문제의 시간복잡도와 대안 풀이를 설명할 수 있어야 합니다.

## 2. 자료구조와 알고리즘

### 2.1 주요 자료구조 비교

| 자료구조 | 접근 | 탐색 | 삽입/삭제 | 특징 |
|---|---|---|---|---|
| 배열 | O(1) | O(n) | O(n) | 연속 메모리 |
| 연결 리스트 | O(n) | O(n) | O(1)* | *위치를 알고 있을 때 |
| 해시 테이블 | - | O(1) | O(1) | 충돌 처리 필요 |
| 이진 탐색 트리 | - | O(log n) | O(log n) | 편향 시 O(n) |
| 힙 | - | O(n) | O(log n) | 우선순위 큐 구현 |

### 2.2 자주 나오는 질문

- **스택과 큐의 차이**: 스택은 LIFO, 큐는 FIFO입니다. 스택은 DFS와 괄호 검사에, 큐는 BFS와 작업 대기열에 씁니다.
- **해시 충돌 해결**: 체이닝(연결 리스트)과 개방 주소법(선형 탐사, 이중 해싱)이 있습니다.
- **퀵 정렬과 병합 정렬**
  - 퀵 정렬은 평균 O(n log n), 최악 O(n²)이고 제자리 정렬입니다.
  - 병합 정렬은 항상 O(n log n)이고 안정 정렬이지만 추가 메모리가 필요합니다.
- **DFS와 BFS**: 최단 경로(가중치 없음)는 BFS, 경로 존재 여부나 백트래킹은 DFS가 적합합니다.
- **동적 계획법**: 부분 문제가 겹치고(중복 부분 문제) 최적 부분 구조일 때 씁니다. 메모이제이션(top-down)과 타뷸레이션(bottom-up)이 있습니다.

## 3. 운영체제

- **프로세스와 스레드**: 프로세스는 독립된 메모리 공간을 가집니다. 스레드는 코드, 데이터, 힙을 공유하고 스택과 레지스터만 따로 가집니다.
- **컨텍스트 스위칭**: CPU가 실행 대상을 바꿀 때 PCB에 상태를 저장하고 복원합니다. 이 과정은 비용이 큽니다.
- **교착 상태(Deadlock) 4조건**: 상호 배제, 점유와 대기, 비선점, 환형 대기입니다. 이 중 하나를 깨면 예방할 수 있습니다.
- **뮤텍스와 세마포어**: 뮤텍스는 하나의 스레드만 임계 영역에 접근하게 합니다. 세마포어는 카운터로 동시 접근 수를 제한합니다.
- **가상 메모리**: 페이징으로 물리 메모리보다 큰 주소 공간을 제공합니다. 페이지 폴트가 나면 디스크에서 불러오고, 교체 알고리즘은 LRU, FIFO 등이 있습니다.

## 4. 네트워크

- **TCP와 UDP**: TCP는 연결 지향이며 신뢰성, 순서 보장, 흐름·혼잡 제어를 제공합니다. UDP는 비연결형이라 빠르고 가볍습니다.
- **3-way handshake**: SYN → SYN+ACK → ACK 순서입니다. 연결 종료는 4-way handshake(FIN/ACK 교환)입니다.
- **HTTP와 HTTPS**: HTTPS는 TLS로 암호화합니다. 핸드셰이크에서 비대칭키로 세션키를 교환하고, 이후 통신은 대칭키로 합니다.
- **GET과 POST**: GET은 멱등하고 캐시가 가능하며 조회에 씁니다. POST는 생성이나 변경에 쓰고 본문에 데이터를 담습니다.
- **브라우저에 URL을 입력하면**: DNS 조회 → TCP 연결 → HTTP 요청 → 서버 응답 → 렌더링 순서입니다.

## 5. 데이터베이스

- **트랜잭션 ACID**: 원자성, 일관성, 격리성, 지속성입니다.
- **격리 수준**: READ UNCOMMITTED < READ COMMITTED < REPEATABLE READ < SERIALIZABLE 순이며, 높을수록 정합성은 좋아지고 성능은 떨어집니다.
- **인덱스**: B-Tree 기반이 일반적입니다. 조회는 빨라지지만 쓰기는 느려지고 저장 공간이 더 듭니다. 카디널리티가 높은 컬럼에 적합합니다.
- **정규화와 반정규화**: 정규화는 중복을 제거해 이상 현상을 막습니다. 반정규화는 조회 성능을 위해 중복을 허용합니다.
- **N+1 문제**: 연관 데이터를 조회할 때 쿼리가 반복 실행되는 문제입니다. 조인 페치나 배치 조회로 해결합니다.

## 6. 객체지향과 설계

- **SOLID**: 단일 책임, 개방-폐쇄, 리스코프 치환, 인터페이스 분리, 의존성 역전.
- **상속과 합성**: 가능하면 합성을 우선합니다. 상속은 결합도가 높습니다.
- **오버로딩과 오버라이딩**: 오버로딩은 같은 이름에 다른 시그니처를 두는 것이고, 오버라이딩은 상위 메서드를 재정의하는 것입니다.
- **디자인 패턴**: 싱글톤, 팩토리, 옵저버, 전략, 데코레이터는 사용 사례를 하나씩 준비해 둡니다.

## 7. 실무 경험 질문 (행동 면접)

1. 가장 어려웠던 기술적 문제와 해결 과정은?
2. 팀원과 의견이 충돌했을 때 어떻게 해결했는가?
3. 성능을 개선한 경험이 있는가? (수치로 말하기)
4. 장애를 겪었다면 원인 분석과 재발 방지는 어떻게 했는가?
5. 코드 리뷰에서 중요하게 보는 점은?

> **팁**: STAR 기법(Situation, Task, Action, Result)으로 답을 정리해 두면 안정적입니다.
