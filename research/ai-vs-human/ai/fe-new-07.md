# 프론트엔드 뉴스레터 2023-01

> 새해가 밝았습니다. 2023년 첫 호에서는 2022년 말부터 이어진 프론트엔드 생태계의 흐름과 1월에 주목할 만한 소식을 모아 전해 드립니다. 빠르게 변하는 도구 사이에서 방향을 잡는 데 도움이 되기를 바랍니다.

## 이달의 헤드라인

지난해 프론트엔드 생태계의 키워드는 **메타 프레임워크**와 **서버 중심 렌더링**이었습니다. React 18의 동시성(Concurrent) 기능이 자리를 잡으면서 Next.js, Remix, SvelteKit 같은 풀스택 프레임워크가 "코드를 어디에서, 언제 실행할 것인가"라는 질문에 각자의 답을 내놓고 있습니다. 2023년에는 이 경쟁이 더 본격화될 것으로 보입니다. 이번 호에서는 주요 프레임워크의 동향, 빌드 도구의 변화, 언어와 브라우저 소식을 차례로 정리했습니다.

## 프레임워크 & 라이브러리

### React: 서버 컴포넌트와 동시성 렌더링

React 팀은 서버 컴포넌트(React Server Components)에 대한 논의를 이어가며, 데이터 페칭을 컴포넌트 트리 안에 자연스럽게 녹이는 방향을 탐색하고 있습니다. React 18에서 도입된 `useTransition`, `useDeferredValue`, Suspense 기반 데이터 로딩은 실무에서 점차 채택되는 추세입니다.

마이그레이션을 준비한다면 `StrictMode`의 동작부터 익혀 두는 것을 추천합니다. 개발 모드에서 컴포넌트가 두 번 렌더링되고 이펙트가 한 번 더 실행되는 것은 버그가 아니라, 이펙트의 정리(cleanup) 로직이 올바른지 검증하기 위한 의도된 동작입니다.

### Next.js: 미들웨어와 엣지 런타임

Next.js는 13 버전 라인에서 App 디렉터리 구조와 엣지 런타임 지원을 확장해 왔습니다. 미들웨어를 활용해 요청 단위로 인증이나 리다이렉트를 처리하는 패턴이 많이 소개되고 있으며, 정적 생성과 서버 렌더링을 페이지 단위로 섞어 쓰는 하이브리드 구성도 늘어나는 중입니다.

다만 새 라우팅 구조는 아직 변화가 많으므로, 프로덕션에 적용하기 전에 공식 문서의 변경 기록(changelog)을 꼭 확인하세요.

### SvelteKit 1.0과 Svelte 생태계

SvelteKit 1.0이 정식 출시되면서 Svelte 기반 풀스택 개발이 한층 안정적인 선택지가 되었습니다. 컴파일 시점에 최적화된 번들, 적은 보일러플레이트, 직관적인 반응형 문법이 장점으로 꼽힙니다. 소규모 팀이나 콘텐츠 중심 사이트에서 특히 생산성이 높다는 평가가 많습니다.

### Vue 3 생태계

Vue 3에서는 Composition API와 `<script setup>` 문법이 사실상 표준처럼 자리 잡았습니다. 상태 관리 라이브러리인 Pinia는 Vuex를 대체하는 공식 권장 도구로 굳어졌고, 기존 Vuex 프로젝트에서도 점진적인 전환이 활발합니다. 타입 추론이 개선되어 TypeScript와 함께 쓰기도 한결 편해졌습니다.

## 빌드 도구 & 개발 환경

### Vite 4 안정화

Vite 4가 2022년 12월 출시되며 번들링을 담당하는 Rollup이 3 버전으로 올라갔습니다. 이에 맞춰 지원하는 Node.js 버전 요구 사항도 상향되었습니다. Node.js 14 지원이 종료되는 흐름과 맞물리는 변화이므로, CI 환경과 팀원들의 로컬 Node.js 버전을 한 번 점검해 두는 것이 좋습니다.

### Rust·Go 기반 도구의 부상

esbuild, SWC, 그리고 Next.js가 도입을 준비 중인 Turbopack 등 Rust나 Go로 작성된 도구들이 빌드 속도를 크게 끌어올리고 있습니다. 기존 webpack 기반 프로젝트라도 로더와 플러그인 호환성을 확인하면서 단계적으로 옮겨 볼 수 있습니다. 한 번에 전환하기보다는 개발 서버 속도처럼 체감이 큰 영역부터 시험해 보는 방식을 추천합니다.

### 테스트 도구의 재편

Jest와 Cypress가 여전히 많이 쓰이는 가운데, Vite와 호환되는 Vitest와 여러 브라우저를 한 번에 다루는 Playwright가 대안으로 주목받고 있습니다. 설정이 가볍고 실행 속도가 빠르다는 점이 특히 많이 언급됩니다. 단위 테스트는 Vitest로, 사용자 흐름 테스트는 Playwright로 나누는 구성이 늘고 있습니다.

## 언어 & 표준

### TypeScript 4.9와 `satisfies`

2022년 11월에 공개된 TypeScript 4.9에서 도입된 `satisfies` 연산자는 값이 특정 타입의 요구 사항을 만족하는지 검증하면서도, 실제 값의 세부 타입은 그대로 유지하게 해 줍니다. 설정 객체처럼 키와 값의 구조가 중요한 코드에서 특히 유용합니다.

```ts
const palette = {
  primary: "#2563eb",
  danger: "#dc2626",
} satisfies Record<string, string>;

// palette.primary의 타입은 여전히 "#2563eb"에 가깝게 추론됩니다.
```

### 브라우저 릴리스

2023년 1월에는 Chrome 109, Firefox 109, Safari 16.3이 연이어 출시되었습니다. 새 기능을 도입할 때는 MDN Web Docs와 caniuse의 호환성 표를 함께 확인하고, 지원하지 않는 브라우저에서도 기본 기능이 동작하도록 점진적 향상(Progressive Enhancement) 원칙을 지키는 것이 안전합니다.

## 성능 & 접근성

성능 지표로는 Core Web Vitals가 여전히 검색 노출과 사용자 경험의 기준으로 쓰입니다. 이미지 포맷을 WebP나 AVIF로 바꾸고, 사용하지 않는 자바스크립트를 줄이며, 중요한 리소스에 우선순위를 주는 것만으로도 체감 차이가 큽니다. 번들 분석 도구를 CI에 붙여 번들 크기가 임계값을 넘으면 경고하는 방식도 효과적입니다.

접근성은 "나중에 고려할 항목"이 아니라 처음부터 설계에 포함할 요소입니다. 시맨틱 HTML을 우선 사용하고, 키보드만으로 모든 기능을 조작할 수 있는지 확인하며, 색 대비를 점검하는 습관을 들이면 대부분의 기본 문제를 예방할 수 있습니다.
