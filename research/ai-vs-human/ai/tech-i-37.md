# Page Replacement Algorithm

## 1. 개요

**페이지 교체 알고리즘**은 가상 메모리 환경에서 **페이지 폴트(Page Fault)** 가 발생했는데 물리 메모리에 빈 프레임이 없을 때, 어떤 페이지를 내보낼지(victim) 정하는 정책입니다.

- **목표**: 페이지 폴트 횟수를 최소화해 디스크 I/O 비용을 줄이는 것
- **배경**: 요구 페이징(Demand Paging)에서는 필요한 페이지만 메모리에 올리므로 교체가 반드시 발생함
- **Dirty Bit**: 내보낼 페이지가 수정된 적이 있으면 디스크에 써야(write-back) 하므로 비용이 큼. 교체 대상을 고를 때 함께 고려합니다.

---

## 2. 주요 알고리즘

### 2.1 FIFO (First-In First-Out)
- 메모리에 **가장 먼저 들어온 페이지**를 교체합니다.
- 큐로 구현하므로 단순하고 오버헤드가 적습니다.
- 자주 쓰이는 페이지도 오래됐다는 이유만으로 쫓겨날 수 있습니다.
- **Belady's Anomaly**: 프레임 수를 늘렸는데 오히려 페이지 폴트가 증가하는 현상이 생길 수 있습니다.
  - 참조열 `1 2 3 4 1 2 5 1 2 3 4 5`
  - 프레임 3개 → 폴트 9회, 프레임 4개 → 폴트 10회

### 2.2 OPT (Optimal, MIN)
- **앞으로 가장 오랫동안 사용되지 않을 페이지**를 교체합니다.
- 이론상 페이지 폴트 수가 가장 적습니다.
- 미래의 참조를 알아야 하므로 **실제로 구현할 수 없고**, 다른 알고리즘을 평가하는 **기준(benchmark)** 으로 씁니다.

### 2.3 LRU (Least Recently Used)
- **가장 오랫동안 사용되지 않은 페이지**를 교체합니다.
- 시간 지역성(Temporal Locality)을 활용해 OPT에 가까운 성능을 냅니다.
- **Stack 알고리즘**이라 Belady's Anomaly가 생기지 않습니다.
- 구현 방식
  - **Counter**: 참조할 때마다 시각을 기록하고, 가장 작은 값을 찾아 교체
  - **Stack / Linked List + HashMap**: 참조된 페이지를 맨 앞으로 옮김. 조회와 갱신 모두 O(1)
- 단점: 메모리 참조마다 정보를 갱신해야 하므로 하드웨어 지원이 없으면 오버헤드가 큽니다.

### 2.4 LFU (Least Frequently Used)
- **참조 횟수가 가장 적은 페이지**를 교체합니다.
- 단점: 초기에 많이 쓰이고 이후 안 쓰이는 페이지가 계속 남고, 새로 들어온 페이지가 곧바로 쫓겨나기 쉽습니다.

### 2.5 MFU (Most Frequently Used)
- **참조 횟수가 가장 많은 페이지**를 교체합니다.
- "많이 쓴 페이지는 이미 할 일을 마쳤다"는 가정을 따르지만, 실제 성능은 좋지 않아 거의 쓰이지 않습니다.

### 2.6 Clock (Second-Chance)
- LRU의 **근사(approximation)** 알고리즘이며, 실제 OS에서 널리 씁니다.
- 각 페이지에 **참조 비트(Reference Bit)** 를 두고, 원형 큐를 시곗바늘처럼 돌며 확인합니다.
  - 참조 비트가 1이면 0으로 바꾸고 한 번 더 기회를 줌
  - 참조 비트가 0이면 그 페이지를 교체
- **Enhanced Clock**: (참조 비트, 수정 비트) 쌍을 함께 보고 `(0,0)`인 페이지를 먼저 교체해 write-back 비용을 줄입니다.

---

## 3. 비교 요약

| 알고리즘 | 교체 기준 | 장점 | 단점 |
|---|---|---|---|
| FIFO | 가장 먼저 들어온 페이지 | 구현이 단순함 | Belady's Anomaly |
| OPT | 가장 늦게 쓰일 페이지 | 폴트 최소 | 구현 불가 |
| LRU | 가장 오래 안 쓰인 페이지 | 성능 우수 | 갱신 오버헤드 |
| LFU | 참조 횟수 최소 | 빈도를 반영함 | 과거 이력에 묶임 |
| Clock | 참조 비트 0인 페이지 | 효율적인 LRU 근사 | 정확한 LRU는 아님 |

## 4. 관련 개념

- **Thrashing**: 프로세스에 할당된 프레임이 부족해 페이지 폴트가 계속 발생하고, CPU 이용률이 급격히 떨어지는 현상입니다.
  - 해결: **Working Set 모델**(최근 Δ 동안 참조된 페이지 집합만큼 프레임 보장), **PFF**(Page Fault Frequency에 따라 프레임 수 조절)
- **Global vs Local Replacement**
  - Global: 모든 프로세스의 프레임 중에서 교체. 처리량은 좋지만 다른 프로세스의 영향을 받습니다.
  - Local: 자기 프로세스의 프레임 안에서만 교체. 성능이 예측 가능합니다.

## 5. 면접 예상 질문

1. **OPT가 최적인데 왜 쓰지 않나요?**
   → 미래의 페이지 참조를 미리 알 수 없기 때문입니다. 성능 비교 기준으로만 사용합니다.
2. **Belady's Anomaly란 무엇이고 LRU에서는 왜 생기지 않나요?**
   → 프레임을 늘렸는데 폴트가 늘어나는 현상입니다. LRU는 n개 프레임에 있는 페이지 집합이 항상 n+1개 프레임에 있는 집합에 포함되는 Stack 성질을 가지므로 이 현상이 생기지 않습니다.
3. **LRU를 O(1)로 구현하려면 어떻게 하나요?**
   → HashMap과 Doubly Linked List를 함께 씁니다. HashMap으로 노드를 바로 찾고, 리스트로 사용 순서를 관리합니다.
4. **실제 OS에서 LRU 대신 Clock을 쓰는 이유는 무엇인가요?**
   → 정확한 LRU는 메모리 참조마다 갱신 비용이 들지만, Clock은 하드웨어 참조 비트만으로 비슷한 효과를 적은 비용으로 얻을 수 있기 때문입니다.
