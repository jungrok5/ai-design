# 네이티브 앱 & 웹 앱 & 하이브리드 앱

## 1. 네이티브 앱 (Native App)
특정 OS(iOS, Android)에 맞는 언어와 SDK로 개발하는 앱입니다.
- **언어**: iOS는 Swift/Objective-C, Android는 Kotlin/Java
- **배포**: App Store, Google Play 같은 스토어를 통해 설치합니다.

**장점**
- 실행 속도와 반응성이 가장 좋습니다.
- 카메라, GPS, 블루투스, 푸시 알림 등 기기 기능을 제약 없이 쓸 수 있습니다.
- OS의 UI 가이드라인을 따르므로 사용자 경험(UX)이 자연스럽습니다.

**단점**
- 플랫폼마다 따로 개발해야 해서 비용과 시간이 많이 듭니다.
- 업데이트할 때마다 스토어 심사를 거쳐야 합니다.

---

## 2. 웹 앱 (Web App)
모바일 브라우저에서 실행되는 웹사이트입니다. 화면 크기에 맞춰 레이아웃이 바뀌는 반응형으로 만들어 앱처럼 보이게 합니다.
- **기술**: HTML, CSS, JavaScript
- **PWA(Progressive Web App)**: 홈 화면 추가, 오프라인 캐싱(Service Worker), 푸시 알림을 지원해 네이티브 앱에 가까운 경험을 제공합니다.

**장점**
- 하나의 코드로 모든 플랫폼을 지원합니다.
- 설치가 필요 없고, 서버에 배포하는 즉시 업데이트가 반영됩니다.

**단점**
- 브라우저를 거치므로 성능이 떨어집니다.
- 기기 기능에 접근하는 데 제한이 있습니다. 특히 iOS의 제약이 큽니다.
- 스토어에 등록할 수 없어 사용자에게 노출될 기회가 적습니다.

---

## 3. 하이브리드 앱 (Hybrid App)
네이티브 앱 껍데기 안에 **WebView**를 넣고, 그 안에 웹 콘텐츠를 띄우는 방식입니다.
- **기술**: Cordova, Ionic, Capacitor
- **브릿지(Bridge)**: JavaScript와 네이티브 코드를 연결해 기기 기능을 호출합니다.

**장점**
- 웹 기술로 한 번 개발하면 여러 플랫폼에 배포할 수 있습니다.
- 스토어에 등록할 수 있고, 웹 영역은 스토어 심사 없이 바로 업데이트할 수 있습니다.

**단점**
- WebView를 거치므로 네이티브보다 느립니다.
- 복잡한 애니메이션이나 고성능 기능을 구현하기 어렵습니다.

---

## 4. 한눈에 비교

| 구분 | 네이티브 | 웹 | 하이브리드 |
|---|---|---|---|
| 성능 | 높음 | 낮음 | 중간 |
| 개발 비용 | 높음 | 낮음 | 중간 |
| 기기 기능 접근 | 완전 | 제한적 | 브릿지를 통해 가능 |
| 스토어 배포 | O | X | O |
| 업데이트 | 심사 필요 | 즉시 반영 | 웹 영역은 즉시 반영 |

## 💡 면접 예상 질문
- **Q. React Native와 Flutter는 하이브리드 앱인가요?**
  둘 다 엄밀히 말하면 **크로스 플랫폼 프레임워크**입니다. WebView를 쓰지 않는다는 점이 하이브리드 앱과 다릅니다. React Native는 네이티브 UI 컴포넌트를 사용하고, Flutter는 자체 렌더링 엔진(Skia/Impeller)으로 화면을 직접 그립니다.
- **Q. 어떤 방식을 선택하나요?**
  - 성능과 UX가 중요하면 네이티브를 선택합니다.
  - 빠르게 출시하고 비용을 줄여야 하면 웹 또는 하이브리드를 선택합니다.
  - 콘텐츠 위주의 서비스라면 하이브리드가 적합합니다.
