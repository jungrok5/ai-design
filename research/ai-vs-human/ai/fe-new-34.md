## 🔥 이달의 헤드라인: React 18 정식 출시

3월 말 React 18이 정식 출시되었습니다. 이번 버전의 핵심은 **동시성(Concurrent) 렌더링**을 앱 전반에서 사용할 수 있는 기반을 마련했다는 점입니다. 기존 `ReactDOM.render` 대신 `createRoot` API를 사용하면 새 기능이 활성화됩니다.

주요 변화는 다음과 같습니다.

- **자동 배칭(Automatic Batching)**: 이벤트 핸들러뿐 아니라 `setTimeout`, Promise 콜백 등에서도 상태 업데이트가 자동으로 묶입니다. 불필요한 리렌더링이 줄어듭니다.
- **`useTransition`, `useDeferredValue`**: 긴급하지 않은 업데이트를 낮은 우선순위로 처리해, 입력 반응성을 유지하면서 무거운 목록을 갱신할 수 있습니다.
- **`useId`**: 서버와 클라이언트에서 일관된 고유 ID를 생성합니다. SSR 환경의 hydration 불일치 문제를 줄이는 데 도움이 됩니다.
- **Suspense 개선**: 서버 렌더링에서도 Suspense 경계 단위로 스트리밍 응답을 보낼 수 있게 되었습니다.

> 💡 **마이그레이션 팁**: 업그레이드 후 콘솔에 `ReactDOM.render is no longer supported` 경고가 뜬다면 `createRoot`로 교체해야 합니다. 테스트 환경에서는 `act` 사용 방식도 함께 점검하세요.

## ⚙️ 프레임워크 & 도구 업데이트

**Next.js 12.1**은 온디맨드 ISR(Incremental Static Regeneration)을 도입했습니다. 콘텐츠가 바뀌었을 때 전체 사이트를 다시 빌드하지 않고, 특정 페이지만 API 호출로 재검증할 수 있습니다. 블로그나 상품 페이지처럼 자주 바뀌는 정적 콘텐츠에 특히 유용합니다.

**Vite**는 2.9 계열의 안정화 작업을 이어갔습니다. 개발 서버의 빠른 콜드 스타트와 HMR 덕분에 Vue, React, Svelte 등 여러 프레임워크 템플릿에서 채택이 계속 늘고 있습니다. 다만 플러그인 호환성은 버전마다 확인이 필요하니 업그레이드 전에 체인지로그를 꼭 읽어 주세요.

**TypeScript**는 2월에 나온 4.6의 흐름을 이어 타입 좁히기(narrowing) 개선이 주목을 받았습니다. 구조 분해된 판별 유니온(discriminated union)을 더 정확하게 추론할 수 있게 되어, 조건문 분기 안에서 타입 가드를 따로 작성할 일이 줄었습니다.

## 🌐 브라우저 & 웹 플랫폼

이번 달 브라우저 소식은 CSS 선택자 지원 확대에 집중되었습니다.

- **Chrome 99**가 3월 초 정식 출시되었습니다. 웹 표준 기능과 개발자 도구 개선이 함께 포함되었습니다.
- **Safari 15.4**는 `:has()` 선택자를 포함한 여러 CSS 기능을 지원하기 시작했습니다. 부모 요소를 자식 상태에 따라 스타일링할 수 있게 되어, 그동안 JavaScript로 처리하던 UI 상태 스타일을 CSS만으로 구현하는 사례가 늘어날 전망입니다.

브라우저 간 기능 차이는 여전히 존재하므로, 새 선택자를 실무에 도입할 때는 [Can I use](https://caniuse.com)에서 지원 범위를 확인하고 필요하면 폴백을 준비하세요.

## 🚨 생태계 이슈: 오픈소스 패키지 논란

3월에는 npm 패키지 `node-ipc`에 특정 지역을 겨냥한 동작이 포함된 사실이 알려지며 큰 논란이 있었습니다. 이른바 **프로테스트웨어(protestware)** 사례로, 많은 개발자가 자신의 의존성 트리를 다시 점검하게 되었습니다.

이 사건을 계기로 다음과 같은 점검이 권장됩니다.

1. `npm ls` 또는 `pnpm why`로 간접 의존성까지 확인하기
2. 락 파일(`package-lock.json`, `pnpm-lock.yaml`)을 커밋해 설치 버전을 고정하기
3. `npm audit`이나 SCA 도구를 CI에 연결하기
4. 메인테이너가 적은 패키지를 사용할 때 리스크를 한 번 더 생각하기

오픈소스의 편리함은 크지만, 그만큼 공급망 보안에 대한 책임도 우리 모두에게 있습니다.
