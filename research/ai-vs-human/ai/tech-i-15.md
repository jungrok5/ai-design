# [JPA] 더티 체킹 (Dirty Checking)

## 1. 개념
더티 체킹은 영속성 컨텍스트가 관리하는 엔티티의 변경을 감지해서, `update` 메서드를 따로 호출하지 않아도 `UPDATE` 쿼리를 자동으로 DB에 반영하는 기능입니다. 개발자는 엔티티의 필드 값만 바꾸면 됩니다.

## 2. 동작 원리
1. 트랜잭션 안에서 `em.find()` 등으로 엔티티를 조회하면, 영속성 컨텍스트는 엔티티를 1차 캐시에 저장하면서 **최초 상태의 스냅샷**도 함께 보관합니다.
2. 엔티티의 필드 값을 변경합니다.
3. 커밋 시점(또는 JPQL 실행 전)에 flush가 일어나면, 스냅샷과 현재 상태를 비교합니다.
4. 변경된 엔티티에 대해서만 `UPDATE` SQL을 생성해 DB에 전달합니다.

```java
@Transactional
public void changeName(Long id, String name) {
    Member member = em.find(Member.class, id); // 영속 상태
    member.changeName(name);                   // 값만 변경
    // 커밋 시 UPDATE member SET name = ? WHERE id = ? 자동 실행
}
```

## 3. 주의할 점
- **영속 상태의 엔티티에만** 적용됩니다. 준영속(detached) 엔티티나 트랜잭션 밖에서 바꾼 객체는 감지되지 않습니다.
- 기본 전략은 **모든 컬럼**을 포함해 UPDATE합니다. 변경된 컬럼만 반영하려면 `@DynamicUpdate`를 사용합니다.
- 스냅샷을 메모리에 보관하고 flush 때 비교하므로, 대량 엔티티를 다루면 비용이 커집니다. 이때는 배치 처리나 `clear()`를 고려합니다.
- setter 대신 `changeName()`처럼 **의미 있는 비즈니스 메서드**로 변경하는 편이 추적과 유지보수에 좋습니다.

## 4. 면접 핵심 답변
"영속성 컨텍스트가 조회 시점의 스냅샷을 보관하고, flush 시 스냅샷과 현재 상태를 비교해 변경된 엔티티만 UPDATE합니다. 그래서 영속 상태 엔티티의 값만 바꾸면 별도의 저장 호출 없이 반영됩니다."
