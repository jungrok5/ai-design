# HTTP & HTTPS

## 1. HTTP란?
HTTP(HyperText Transfer Protocol)는 클라이언트(주로 브라우저)와 서버가 리소스를 주고받기 위해 사용하는 **애플리케이션 계층** 프로토콜입니다. **요청(Request)–응답(Response)** 구조로 동작하며, 서버는 이전 요청의 상태를 기억하지 않는 **무상태(Stateless)** 특성을 가집니다. 기본 포트는 80번입니다.

## 2. 요청과 응답 구조
- **요청**: 시작 줄(메서드, 경로, 버전), 헤더(Host, User-Agent, Content-Type 등), 빈 줄, 바디
- **응답**: 시작 줄(버전, 상태 코드, 상태 메시지), 헤더, 빈 줄, 바디

## 3. 주요 메서드

| 메서드 | 용도 | 안전 | 멱등 |
|---|---|---|---|
| GET | 리소스 조회 | O | O |
| POST | 리소스 생성, 처리 요청 | X | X |
| PUT | 리소스 전체 교체 | X | O |
| PATCH | 리소스 일부 수정 | X | X |
| DELETE | 리소스 삭제 | X | O |

- **안전(Safe)**: 서버의 상태를 변경하지 않습니다.
- **멱등(Idempotent)**: 같은 요청을 여러 번 보내도 결과가 한 번 보낸 것과 같습니다.

## 4. 상태 코드
- **2xx 성공**: 200 OK, 201 Created, 204 No Content
- **3xx 리다이렉션**: 301 영구 이동, 302 임시 이동, 304 Not Modified(캐시 사용)
- **4xx 클라이언트 오류**: 400 Bad Request, 401 Unauthorized(인증 필요), 403 Forbidden(권한 없음), 404 Not Found
- **5xx 서버 오류**: 500 Internal Server Error, 502 Bad Gateway, 503 Service Unavailable

## 5. HTTP 버전별 특징
- **HTTP/1.0**: 요청마다 TCP 연결을 새로 맺어 비효율적입니다.
- **HTTP/1.1**: Keep-Alive로 연결을 재사용합니다. 한 연결에서 요청을 순서대로 처리하므로 앞선 요청이 지연되면 뒤가 막히는 **HOL(Head-of-Line) Blocking**이 발생합니다.
- **HTTP/2**: 바이너리 프레이밍, 하나의 연결에서 여러 스트림을 동시에 처리하는 **멀티플렉싱**, 헤더 압축(HPACK)을 지원합니다. 다만 TCP 수준의 HOL Blocking은 남아 있습니다.
- **HTTP/3**: TCP 대신 UDP 기반의 **QUIC**을 사용해 HOL Blocking을 줄이고 연결 수립 시간을 단축합니다.

## 6. HTTPS란?
HTTPS는 HTTP에 **TLS(Transport Layer Security)** 암호화 계층을 더한 프로토콜이며, 기본 포트는 443번입니다. 평문 전송의 문제를 해결하며 다음 세 가지를 제공합니다.
- **기밀성**: 대칭키로 데이터를 암호화해 도청을 방지합니다.
- **무결성**: 메시지 인증 코드로 전송 중 변조를 탐지합니다.
- **인증**: CA가 서명한 인증서로 서버 신원을 확인해 중간자(MITM) 공격을 막습니다.

### TLS 핸드셰이크(개략)
1. **Client Hello**: 지원하는 암호 스위트와 난수를 전송합니다.
2. **Server Hello**: 암호 스위트를 선택하고 인증서를 전송합니다.
3. 클라이언트가 인증서를 검증한 뒤 키 교환을 수행합니다(RSA 또는 ECDHE).
4. 양측이 세션 키를 도출하고 Finished 메시지를 교환합니다.
5. 이후 대칭키로 암호화된 HTTP 통신을 합니다.

> 비대칭키는 키 교환과 인증에만 쓰고, 실제 데이터 암호화는 속도가 빠른 대칭키로 합니다.

## 7. 면접 핵심 질문

**Q. GET과 POST의 차이는?**
A. 의미상 GET은 조회, POST는 생성·처리에 쓰입니다. GET은 파라미터가 URL에 노출되고 캐시될 수 있으며, POST는 바디에 담겨 기본적으로 캐시되지 않습니다. 둘 다 보안 수단은 아니므로 HTTPS가 필요합니다.

**Q. HTTP와 HTTPS의 차이는?**
A. HTTPS는 TLS로 데이터를 암호화하고 서버 인증을 수행합니다. 기본 포트(80/443)와 인증서 사용 여부가 다릅니다.

**Q. HTTP는 무상태인데 로그인은 어떻게 유지하나요?**
A. 쿠키, 세션, 토큰(JWT 등)을 요청 헤더에 실어 보내 상태 정보를 유지합니다. 세션은 서버에, 토큰은 클라이언트에 상태를 두는 방식입니다.

**Q. PUT과 PATCH의 차이는?**
A. PUT은 리소스 전체를 교체하며 멱등하고, PATCH는 일부만 수정하며 멱등하지 않을 수 있습니다.
