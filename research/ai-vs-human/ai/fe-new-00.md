## 🌐 브라우저·웹 플랫폼

### Chrome 84: 웹이 앱에 더 가까워지다

7월 중순 안정 버전으로 배포된 Chrome 84의 눈에 띄는 변화는 다음과 같습니다.

- **Web OTP API**: SMS로 받은 인증 코드를 웹 페이지가 직접 받아 입력할 수 있습니다. 모바일 로그인 흐름에서 사용자가 문자 앱을 오가야 하던 불편이 줄어듭니다.
- **Screen Wake Lock API**: 레시피, 발표 자료, 동영상처럼 화면이 꺼지면 곤란한 서비스에서 화면 유지를 요청할 수 있습니다.
- **Badging API**: 설치된 PWA 아이콘에 읽지 않은 알림 수 같은 배지를 표시합니다.
- **Content Indexing API**: 오프라인에서 볼 수 있는 콘텐츠를 브라우저에 알려 줍니다.

PWA를 운영하고 있다면 지원 범위를 점검할 시기입니다. 다만 브라우저별 지원 편차가 크니, 기능 감지 후 점진적으로 적용하는 방식을 권합니다.

### 크로스 브라우저 동향

Firefox는 7월 말 79 버전을 배포했고, Safari 14 베타는 WebP 지원과 확장 프로그램 호환성 개선으로 주목받았습니다. 이미지 포맷 전략을 다시 검토할 만합니다. 이 소식은 WWDC 이후 이어진 흐름이니, 정식 지원 시점은 직접 확인해 보세요.

### Core Web Vitals

LCP, FID, CLS 세 가지 지표를 중심으로 한 사용자 경험 측정 방식이 자리 잡아 가고 있습니다. 성능 개선을 감으로 하지 말고, 이 지표를 기준 삼아 측정하고 개선하는 팀이 늘었습니다.

## ⚛️ 프레임워크·라이브러리

### Next.js 9.5와 ISR

Next.js 9.5의 대표 기능은 **증분 정적 재생성(Incremental Static Regeneration)**입니다. 정적으로 생성한 페이지를 전체 재빌드 없이 일정 주기로 갱신할 수 있습니다. 페이지 수가 많은 블로그나 커머스 사이트에서 빌드 시간 문제를 완화합니다. 정적 사이트의 속도와 서버 렌더링의 신선도 사이에서 고민하던 팀에게 새 선택지가 생겼습니다.

### Vue 3, 정식 출시 카운트다운

Vue 3가 RC 단계에 들어서면서 Composition API 기반의 코드 구성이 본격적으로 논의되고 있습니다. 마이그레이션 빌드와 생태계 라이브러리 호환 상황을 미리 확인해 두면 좋습니다. 정식 출시 후 곧바로 전환하기보다, 사용 중인 플러그인이 대응했는지 먼저 살피길 권합니다.

### Angular 10과 React의 행보

6월 말에 나온 Angular 10은 엄격 모드 옵션과 번들 크기 개선이 핵심이며, 7월에는 업데이트 후기가 이어졌습니다. React 쪽은 다음 메이저 버전 준비 이야기가 커뮤니티에서 계속 화제였습니다.

## 🧰 언어·도구

### TypeScript 4.0

베타 단계에서 공개된 주요 기능은 다음과 같습니다.

- **가변 인자 튜플 타입(Variadic Tuple Types)**: 튜플 타입을 더 유연하게 조합합니다.
- **레이블 있는 튜플 요소**: 튜플 각 요소에 이름을 붙여 가독성을 높입니다.
- **단축 평가 할당 연산자**: `&&=`, `||=`, `??=`

### ES2020 문법, 이제 써도 될까?

옵셔널 체이닝(`?.`)과 널 병합 연산자(`??`)는 이미 많은 프로젝트에서 쓰이고 있습니다.

```js
// 이전
const city = user && user.address && user.address.city;

// 이후
const city = user?.address?.city ?? '알 수 없음';
```

Babel이나 TypeScript가 변환해 주므로 지원 브라우저 범위만 정하면 바로 적용할 수 있습니다.

### 번들러와 런타임

Webpack 5가 베타 단계에서 영구 캐싱과 모듈 페더레이션으로 기대를 모았고, Snowpack처럼 번들 없이 개발 서버를 띄우는 도구도 꾸준히 언급됩니다. Deno도 마이너 버전을 빠르게 올리며 존재감을 키우고 있습니다.

## 💡 이달의 팁: 이미지 로딩 개선 체크리스트

성능 개선에서 가장 효과가 큰 항목 중 하나가 이미지입니다.

1. 뷰포트 밖 이미지에 `loading="lazy"` 적용하기
2. `width`와 `height` 속성을 명시해 레이아웃 이동(CLS) 줄이기
3. 가능하면 WebP 등 최신 포맷을 `<picture>`로 제공하고 대체 이미지 두기
4. 첫 화면 대표 이미지는 지연 로딩하지 않고 우선 로드하기

```html
<img src="hero.jpg" width="800" height="450" alt="대표 이미지">
<img src="photo.jpg" width="400" height="300" loading="lazy" alt="본문 사진">
```
