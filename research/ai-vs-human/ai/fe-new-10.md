## 이달의 헤드라인: React Conf 2021

10월 20일부터 이틀간 온라인으로 열린 React Conf 2021에서는 차기 메이저 버전인 **React 18**의 방향이 공개되었습니다. 이번 발표의 핵심은 **동시성(Concurrency)** 렌더링입니다. 렌더링을 중간에 멈추거나 우선순위를 나눌 수 있게 되면서, 입력 반응성을 해치지 않는 UI를 만들기가 한결 쉬워집니다.

발표된 주요 기능은 다음과 같습니다.

- **자동 배칭(Automatic Batching)**: 이벤트 핸들러뿐 아니라 Promise, setTimeout 등 모든 위치의 상태 업데이트를 하나로 묶어 불필요한 리렌더링을 줄입니다.
- **startTransition**: 긴급하지 않은 상태 업데이트를 표시하여, 사용자 입력이 먼저 처리되도록 돕습니다.
- **useId**: 서버와 클라이언트에서 동일한 고유 ID를 생성해 하이드레이션 불일치 문제를 줄입니다.
- **Suspense 서버 렌더링 확장**: 페이지의 일부가 준비되지 않아도 나머지를 먼저 스트리밍할 수 있습니다.
- **새로운 루트 API(createRoot)**: 동시성 기능을 사용하려면 새 API로 앱을 시작해야 합니다.

아직 베타 단계이지만, 기존 앱을 어떻게 마이그레이션할지 고민하는 팀이라면 지금부터 `StrictMode`를 켜고 부작용이 있는 코드를 점검해 두는 것이 좋습니다.

## 프레임워크 & 런타임

### Next.js 12 출시

10월 말 공개된 **Next.js 12**는 두 가지 큰 변화를 담았습니다.

첫째, **Rust 기반 컴파일러(SWC)**가 기본 컴파일러로 도입되었습니다. 기존 Babel 기반 파이프라인보다 빌드와 Fast Refresh가 크게 빨라졌다고 소개되었습니다. 기존 Babel 설정이 있는 프로젝트는 호환성을 확인하는 것이 좋습니다.

둘째, **미들웨어(Middleware)**가 추가되었습니다. 요청이 페이지에 도달하기 전에 엣지에서 실행되는 코드를 작성할 수 있어, 인증 확인이나 A/B 테스트, 지역별 리다이렉트를 서버 부담 없이 처리할 수 있습니다.

> **팁**: 미들웨어는 엣지 런타임에서 실행되므로 Node.js 전용 API를 사용할 수 없습니다. 인증 로직을 옮길 때 이 제약을 먼저 확인하세요.

### Node.js 17 출시와 Node.js 16 LTS 전환

10월 19일 **Node.js 17**이 출시되었습니다. 이 버전은 짧은 수명의 비LTS 릴리스이지만, 이어서 **Node.js 16**이 장기 지원(LTS) 버전으로 전환되면서 실무에서는 16을 기준으로 삼는 팀이 많아졌습니다. 빌드 도구와 CI 환경의 Node 버전을 점검해 보세요.

## 브라우저 & 웹 표준

### Chrome 95 정식 출시

10월 초 **Chrome 95**가 정식 출시되었습니다. 브라우저 자체의 변화도 중요하지만, 개발자에게 체감되는 변화는 성능 지표 측정 쪽에서 나타났습니다. 실사용자 데이터(RUM)를 수집하는 도구들이 Core Web Vitals 지표를 더 정확하게 보고하도록 개선되는 흐름이 이어지고 있습니다.

### Core Web Vitals와 페이지 경험

Google 검색 순위에 **페이지 경험(Page Experience)** 신호가 반영되면서, LCP(최대 콘텐츠 풀 페인트), FID(첫 입력 지연), CLS(누적 레이아웃 이동)는 이제 기술 지표가 아니라 비즈니스 지표가 되었습니다. 이번 달 여러 팀의 사례 글에서는 다음과 같은 개선법이 반복해서 나왔습니다.

- 히어로 이미지에 명시적인 `width`와 `height`를 지정해 레이아웃 이동을 막기
- 자주 쓰는 폰트는 `font-display`를 설정하고 서브셋으로 용량 줄이기
- 무거운 서드파티 스크립트는 `async`나 지연 로딩으로 메인 스레드에서 떼어 내기

## 도구 & 생태계

### Vite 2.x 생태계의 확장

Vite는 개발 서버의 즉시 실행과 빠른 HMR 덕분에 많은 프로젝트에서 Webpack의 대안으로 자리 잡고 있습니다. 이달에는 React, Vue, Svelte 템플릿뿐 아니라 SSR 예제와 플러그인 생태계에 관한 글이 늘었습니다. 기존 Webpack 프로젝트를 옮기려는 분이라면, 설정 파일을 그대로 옮기기보다 **번들러가 기본으로 해 주는 일**을 먼저 파악하는 것이 시간을 아끼는 방법입니다.

### Tailwind CSS JIT 모드의 확산

Tailwind CSS의 **JIT(Just-In-Time) 모드**는 필요한 클래스만 즉석에서 생성하여 CSS 번들을 크게 줄여 줍니다. 임의 값(`w-[347px]`)이나 여러 변형(variant)을 조합해 쓰는 방식이 자연스러워지면서, 디자인 시스템을 Tailwind로 구축하는 사례가 눈에 띄었습니다.

### TypeScript 4.5 준비

TypeScript는 이 시기 템플릿 리터럴 타입과 재귀적 조건부 타입 같은 고급 타입 기능을 발전시키고 있습니다. 라이브러리 작성자라면 공개 API의 타입이 사용자에게 어떻게 보이는지 점검할 좋은 시기입니다.
