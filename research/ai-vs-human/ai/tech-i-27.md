# README

> 개발자 기술 면접 대비 정리 노트

## 1. 답변 기본 구조

기술 질문은 **정의 → 동작 원리 → 트레이드오프 → 실무 사례** 순서로 답하면 논리가 자연스럽게 이어집니다. 모르는 질문은 추측하지 말고 아는 범위를 먼저 밝힌 뒤, 어떤 방식으로 알아볼지 설명하는 편이 좋습니다.

## 2. 핵심 CS 주제

| 분야 | 핵심 키워드 | 자주 나오는 질문 |
|---|---|---|
| 자료구조 | 해시맵, 트리, 힙 | 해시 충돌은 어떻게 해결하나요? |
| 운영체제 | 프로세스, 스레드, 데드락 | 프로세스와 스레드의 차이는? |
| 네트워크 | TCP/UDP, HTTP, TLS | HTTP와 HTTPS의 차이는? |
| 데이터베이스 | 인덱스, 트랜잭션, ACID | B+Tree 인덱스가 조회를 빠르게 하는 이유는? |

## 3. 답변 예시

**Q. 인덱스는 왜 조회를 빠르게 하나요?**

- **정의**: 인덱스는 컬럼 값과 행 위치를 정렬된 자료구조(주로 B+Tree)로 저장합니다.
- **원리**: 전체 테이블을 훑는 풀 스캔 대신 O(log N) 탐색으로 범위를 좁힙니다.
- **트레이드오프**: 쓰기 시 인덱스도 함께 갱신해야 하므로 쓰기 비용과 저장 공간이 늘어납니다.
- **사례**: 주문 조회 API에서 `user_id` 인덱스를 추가해 응답 시간을 줄인 경험을 덧붙입니다.

## 4. 시스템 설계 질문 접근법

1. **요구사항 확인**: 사용자 수, 트래픽 규모, 지연 시간 목표를 먼저 질문합니다.
2. **개략 설계**: 클라이언트, API 서버, 저장소, 캐시 등 핵심 구성 요소를 그립니다.
3. **병목 분석**: 읽기와 쓰기 중 어디가 병목인지 짚고 확장 방안을 제시합니다.
4. **장애 대응**: 단일 장애점(SPOF)을 찾고 이중화, 재시도, 모니터링을 말합니다.

## 5. 실무 경험 정리법 (STAR)

- **Situation (상황)**: 어떤 시스템이었는지 간단히 설명합니다.
- **Task (과제)**: 내가 맡은 문제가 무엇이었는지 밝힙니다.
- **Action (행동)**: 여러 선택지 중 무엇을 왜 골랐는지 구체적으로 말합니다.
- **Result (결과)**: "응답 시간 40% 단축"처럼 수치로 표현합니다.
