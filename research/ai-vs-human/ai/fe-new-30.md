## 🚀 1. Web Vitals, 성능을 보는 공통 언어

5월 초 구글은 **Web Vitals** 이니셔티브를 발표했습니다. 좋은 사용자 경험에 필요한 품질 신호를 하나의 틀로 묶은 것입니다. 핵심은 세 가지 지표입니다.

| 지표 | 의미 | 좋은 기준(권장) |
|---|---|---|
| **LCP** (Largest Contentful Paint) | 가장 큰 콘텐츠가 그려지는 시점, 즉 로딩 | 2.5초 이내 |
| **FID** (First Input Delay) | 첫 입력에 반응하기까지의 지연, 즉 상호작용 | 100ms 이내 |
| **CLS** (Cumulative Layout Shift) | 레이아웃이 예기치 않게 움직이는 정도, 즉 시각적 안정성 | 0.1 이하 |

지금까지는 팀마다 성능을 재는 기준이 달랐습니다. 이제 Lighthouse, PageSpeed Insights, Chrome 개발자 도구가 같은 지표를 보여 주므로 팀 안에서 대화하기가 훨씬 쉬워집니다.

**실무 팁**
- 이미지와 광고, 웹폰트 영역에 `width`/`height` 또는 `aspect-ratio` 박스를 미리 잡아 CLS를 줄이세요.
- LCP 요소(대표 이미지나 헤드라인)는 우선 로딩하고, 불필요한 렌더 블로킹 스크립트를 줄이세요.
- 긴 자바스크립트 작업은 쪼개서 FID를 개선하세요.

## 🦕 2. Deno 1.0 정식 출시

5월 13일, Node.js를 만든 라이언 달이 설계한 런타임 **Deno 1.0**이 나왔습니다. 주요 특징은 다음과 같습니다.

- **보안 기본값**: 파일, 네트워크, 환경 변수 접근은 `--allow-*` 플래그로 명시적으로 허용해야 합니다.
- **TypeScript 내장**: 별도 설정 없이 `.ts` 파일을 바로 실행합니다.
- **URL 기반 모듈**: `node_modules`와 `package.json` 대신 URL로 모듈을 가져옵니다.
- **표준 웹 API 지향**: `fetch` 등 브라우저와 같은 API를 사용합니다.

프론트엔드 개발자에게는 당장 Node를 대체할 도구라기보다 "서버 사이드 자바스크립트가 앞으로 어떤 방향으로 갈 것인가"를 보여 주는 신호로 볼 만합니다. 사이드 프로젝트에서 가볍게 써 보기에는 좋습니다.

## 🌐 3. 브라우저 소식

### Chrome 83
- 보안과 프라이버시 설정이 개편되었고, 서드파티 쿠키 제어가 더 쉬워졌습니다.
- 개발자 도구에 새 기능이 들어왔습니다. 색각 이상 에뮬레이션과 쿠키·보안 관련 문제를 보여 주는 **Issues** 탭이 대표적입니다.
- XSS 방어를 위한 **Trusted Types**가 지원됩니다.

### Firefox 76
- 개발자 도구에서 접근성 검사 기능이 강화되었습니다.
- 사용자 편의 기능으로 Picture-in-Picture 조작과 비밀번호 유출 알림이 개선되었습니다.

브라우저마다 지원 범위가 다르니, 새 API를 쓸 때는 [Can I use](https://caniuse.com)와 MDN 호환성 표를 꼭 확인하세요.

## 🧩 4. 언어와 프레임워크

### TypeScript 3.9
- 타입 추론과 속도가 개선되었습니다.
- `// @ts-expect-error` 주석이 추가되었습니다. 오류가 나야 하는 줄에 쓰면, 오류가 사라졌을 때 오히려 알려 줍니다. 테스트 코드에 유용합니다.
- 옵셔널 체이닝과 널 병합 연산자가 포함된 코드의 처리도 더 안정적이 되었습니다.

### Next.js 9.4
- **Fast Refresh**: 편집한 컴포넌트만 상태를 유지한 채 즉시 갱신합니다.
- **Incremental Static Regeneration**: 정적 페이지를 빌드 이후에도 점진적으로 갱신할 수 있어, 정적 사이트의 규모 한계를 줄여 줍니다.
- 환경 변수 처리와 `fetch` 폴리필 등 개발 경험도 좋아졌습니다.

### 그 밖의 흐름
- Babel 7.10 등 도구 체인이 최신 문법 지원을 꾸준히 넓히고 있습니다.
- Vue 3와 React의 다음 버전 소식이 계속 들려오고 있으니, 릴리스 노트를 미리 읽어 두면 좋습니다.

## ⚡ 5. 번들 없는 개발 경험: Snowpack과 Vite

브라우저가 ES 모듈을 기본 지원하면서, 개발 서버에서는 **번들링 없이** 파일을 그대로 제공하는 방식이 주목받고 있습니다.

- **Snowpack**: 의존성을 한 번만 ES 모듈로 변환해 두고, 소스 파일은 변경된 것만 처리합니다. 시작과 갱신이 빠릅니다.
- **Vite**: Vue를 만든 에반 유가 공개한 도구로, 네이티브 ES 모듈 기반 개발 서버를 제공합니다.

웹팩 빌드가 느려서 고민이라면 작은 프로젝트에서 먼저 시험해 보세요. 다만 프로덕션 빌드, 레거시 브라우저 대응, 플러그인 생태계는 아직 웹팩이 더 성숙합니다.
