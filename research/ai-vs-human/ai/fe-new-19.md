## 📌 이달의 헤드라인

이번 달 프론트엔드 생태계의 키워드는 **'성능을 자동으로, 표준을 네이티브로'**입니다. 개발자가 최적화를 직접 챙기던 작업을 컴파일러와 브라우저가 떠맡고, 예전에 라이브러리가 하던 기능을 플랫폼 표준이 대신하는 흐름이 뚜렷해지고 있습니다.

## ⚛️ 프레임워크와 라이브러리

**메타프레임워크의 서버 중심 구조가 자리 잡았습니다.** React Server Components를 기반으로 한 메타프레임워크들은 데이터 페칭과 렌더링 경계를 서버 쪽으로 옮기고 있습니다. 클라이언트로 내려가는 JavaScript 양을 줄이는 것이 목표이며, 번들 크기가 큰 앱일수록 체감 효과가 큽니다. 다만 서버와 클라이언트 경계를 잘못 나누면 오히려 디버깅이 어려워지므로, 상호작용이 많은 컴포넌트만 클라이언트로 두는 원칙을 지키는 것이 좋습니다.

**컴파일러 기반 메모이제이션이 확산되고 있습니다.** React Compiler처럼 빌드 단계에서 불필요한 리렌더링을 줄여 주는 도구가 실사용 단계에 들어서면서, 수동으로 `useMemo`와 `useCallback`을 남발하던 관행이 줄어드는 추세입니다. 그렇다고 성능 프로파일링이 필요 없어진 것은 아니므로, 측정을 먼저 하고 최적화를 적용하는 순서는 그대로 유지해야 합니다.

**시그널(Signals) 패턴은 여러 프레임워크의 공통 언어가 되었습니다.** 세밀한 반응성을 제공하는 시그널 방식은 Vue, Solid, Svelte, Angular 등에서 각자의 형태로 채택되고 있습니다. TC39에서 시그널을 표준화하려는 논의도 계속되고 있어, 프레임워크를 넘나드는 상태 관리 지식의 가치가 높아지고 있습니다.

## 🛠️ 도구와 빌드

**Rust 기반 도구 체인이 기본값이 되고 있습니다.** Vite, Rolldown, Biome, Oxc처럼 Rust나 Go로 작성된 도구가 빌드와 린트, 포매팅 속도를 크게 끌어올리고 있습니다. 대규모 모노레포에서 콜드 스타트 시간이 몇 분에서 몇 초로 줄었다는 사례가 늘어나면서, 도구 교체를 검토하는 팀도 많아졌습니다.

**TypeScript 컴파일러의 네이티브 전환이 진행 중입니다.** Go로 포팅한 새 컴파일러는 타입 체크 속도를 크게 개선하는 것을 목표로 하고 있습니다. 기존 `tsconfig` 설정과의 호환성을 미리 점검해 두면 전환 시 시행착오를 줄일 수 있습니다.

**CSS 유틸리티 방식의 재정비.** Tailwind CSS가 엔진을 새로 짜며 빌드 속도와 설정 방식을 바꾼 뒤, 설정 파일 없이 CSS 안에서 테마를 정의하는 방식이 자리 잡았습니다. 디자인 토큰을 CSS 변수로 관리하는 팀이 많아진 만큼, 프레임워크에 묶이지 않는 토큰 체계를 먼저 설계하는 것이 중요해졌습니다.

## 🌐 웹 플랫폼

이번 달 가장 주목할 흐름은 **표준이 라이브러리를 대체하는 속도**입니다.

- **CSS 앵커 포지셔닝**: 툴팁이나 드롭다운을 JavaScript 계산 없이 요소에 붙일 수 있습니다. 기존에 Popper 계열 라이브러리에 의존하던 UI 중 상당수를 줄일 수 있습니다.
- **Popover API와 `<dialog>`**: 모달, 팝오버, 라이트박스를 브라우저 기본 기능으로 구현하면서 포커스 관리와 접근성을 상당 부분 보장받을 수 있게 되었습니다.
- **View Transitions API**: 페이지와 상태 전환에 부드러운 애니메이션을 적용하기 쉬워졌습니다. 단일 페이지 앱과 다중 페이지 앱 모두에서 사용할 수 있습니다.
- **컨테이너 쿼리와 `:has()` 선택자**: 뷰포트가 아니라 부모 컨테이너 크기에 따라 스타일을 바꾸는 컴포넌트 설계가 실무에 자리 잡았습니다.

브라우저 호환성은 Baseline 기준으로 확인하는 습관을 들이면 좋습니다. 기능이 주요 브라우저에서 모두 지원되는지, 지원 시점이 언제인지 한눈에 볼 수 있어 점진적 향상 전략을 세우기 편합니다.

## 🎓 커뮤니티와 학습

- **접근성을 개발 초기부터**: 린트 규칙과 자동 테스트로 접근성 결함을 빌드 단계에서 걸러내는 팀이 늘고 있습니다. 자동 검사로 잡히는 문제는 전체의 일부에 그치므로, 키보드 탐색과 스크린리더 점검을 주기적으로 병행하는 것이 권장됩니다.
- **테스트 전략의 재편**: 단위 테스트 대비 실제 브라우저에서 사용자 흐름을 검증하는 E2E 테스트의 비중이 조금씩 커지고 있습니다. 브라우저 자동화 도구의 안정성이 높아진 덕분입니다.
- **AI 도구와 협업**: 컴포넌트 생성, 테스트 작성, 마이그레이션 같은 반복 작업에 AI 코딩 도구를 쓰는 사례가 많아졌습니다. 생성된 코드의 접근성과 보안은 사람이 검토해야 한다는 점이 여전히 강조되고 있습니다.
