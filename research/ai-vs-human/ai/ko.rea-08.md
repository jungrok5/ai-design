# 컴포넌트 간 상태 공유하기

> 제목이 비어 있어 React 공식 문서의 "Sharing State Between Components" 주제로 정했습니다. 원문을 옮긴 것이 아니라 내용을 풀어 쓴 글입니다.

어떤 컴포넌트의 상태를 다른 컴포넌트와 함께 사용해야 할 때가 있습니다. 이때 일반적인 방법은 두 컴포넌트가 공유하는 가장 가까운 부모로 상태를 **끌어올리는(lift state up)** 것입니다. 이 글에서는 상태를 끌어올려야 하는 상황, 구현 방법, 제어 컴포넌트 패턴, 그리고 자주 하는 실수를 살펴봅니다.

## 1. 문제 상황

아코디언 패널이 두 개 있다고 가정해 봅시다. 각 패널은 자신의 열림/닫힘 상태를 독립적으로 가지고 있습니다. 두 패널이 동시에 열리지 않게 하려면 어떻게 해야 할까요?

각 자식 컴포넌트가 자기 상태만 가지고 있다면 한쪽이 열릴 때 다른 쪽에 "닫혀라"라고 알릴 방법이 없습니다. 자식끼리 직접 통신하는 것은 React의 데이터 흐름 원칙에 맞지 않습니다. 따라서 두 패널이 공유하는 부모가 "어느 패널이 열려 있는지"를 상태로 관리하도록 바꾸는 것이 해결책입니다.

## 2. 상태 끌어올리기의 기본 단계

1. 상태를 사용하는 컴포넌트들을 찾습니다.
2. 이들의 가장 가까운 공통 부모를 찾습니다.
3. 상태를 공통 부모로 옮깁니다.
4. 공통 부모가 상태를 props로 자식에게 내려줍니다.
5. 자식이 상태를 바꿔야 할 때는 부모가 제공한 핸들러 함수를 props로 받아 호출합니다.

## 3. 예제 코드

```jsx
import { useState } from 'react';

function Panel({ title, children, isActive, onShow }) {
  return (
    <section>
      <h3>{title}</h3>
      {isActive ? (
        <p>{children}</p>
      ) : (
        <button onClick={onShow}>보이기</button>
      )}
    </section>
  );
}

export default function Accordion() {
  const [activeIndex, setActiveIndex] = useState(0);
  return (
    <>
      <Panel
        title="소개"
        isActive={activeIndex === 0}
        onShow={() => setActiveIndex(0)}
      >
        안녕하세요. React를 배우고 있습니다.
      </Panel>
      <Panel
        title="여행"
        isActive={activeIndex === 1}
        onShow={() => setActiveIndex(1)}
      >
        저는 지금 칠레의 바닷가 마을에 있습니다.
      </Panel>
    </>
  );
}
```

이제 `Accordion`이 어떤 패널이 열려 있는지를 단일 진실 공급원(single source of truth)으로 관리합니다. 한 패널을 열면 `activeIndex`가 바뀌고, 다른 패널의 `isActive`는 자동으로 `false`가 되어 닫힙니다.

## 4. 핵심 원칙: 단일 진실 공급원

같은 데이터를 여러 곳의 상태로 중복 저장하면 값이 서로 어긋날 위험이 생깁니다. 그래서 React에서는 데이터마다 **하나의 소유자(상태를 가진 컴포넌트)**를 두고, 나머지는 props로 받아 씁니다.

예를 들어 온도 입력 컴포넌트 두 개가 섭씨와 화씨를 각자 상태로 가지면 변환 로직을 두 번 작성해야 하고 값이 어긋날 수 있습니다. 대신 부모가 온도 하나만 상태로 가지고 두 자식에게 값과 변경 함수를 넘기면 항상 일치합니다.

## 5. 제어 컴포넌트 패턴

끌어올린 상태를 받아 쓰고 값 변경을 부모에게 맡기는 컴포넌트를 **제어 컴포넌트(controlled component)**라고 부릅니다. 입력창의 `value`와 `onChange`가 대표적인 예입니다.

```jsx
function SearchBox({ query, onQueryChange }) {
  return (
    <input
      value={query}
      onChange={(e) => onQueryChange(e.target.value)}
      placeholder="검색어를 입력하세요"
    />
  );
}
```

이 컴포넌트는 자신의 상태를 가지지 않습니다. 부모가 `query`를 바꾸면 화면이 바뀌고, 사용자가 입력하면 부모에게 알려 상태를 갱신하게 합니다. 같은 검색어를 목록 필터링이나 결과 개수 표시 등 여러 곳에서 일관되게 사용할 수 있습니다.

반대로 자식이 자기 상태를 스스로 관리하는 방식은 **비제어 컴포넌트(uncontrolled component)**라고 합니다. 부모가 값을 알 필요가 없는 간단한 경우에는 이 방식이 더 편리합니다.

## 6. 흔한 실수

- **상태를 복사해서 두 곳에 두기**: props로 받은 값을 `useState`의 초기값으로 넣으면, 이후 부모가 값을 바꿔도 자식 상태는 갱신되지 않습니다. 가능하면 props를 직접 사용하세요.
- **자식이 부모 상태를 직접 변경하기**: 객체나 배열을 props로 받아 직접 수정하면 변경 사항을 추적하기 어렵습니다. 변경은 항상 부모가 제공한 함수를 통해 하세요.
- **불필요하게 높이 올리기**: 상태를 사용하는 곳이 한 컴포넌트뿐이라면 위로 올릴 필요가 없습니다. 필요한 만큼만 끌어올리세요.

## 7. 정리

- 여러 컴포넌트가 같은 상태에 의존하면 가장 가까운 공통 부모로 상태를 끌어올립니다.
- 데이터의 소유자는 하나만 두고, 나머지는 props로 받습니다.
- 자식은 상태를 직접 바꾸지 않고, 부모가 넘겨준 핸들러를 호출합니다.
- 제어 컴포넌트 패턴은 값과 변경 함수를 props로 받아 여러 곳에서 일관되게 쓰는 데 유용합니다.

상태 끌어올리기는 React에서 데이터 흐름을 설계하는 가장 기본적인 도구입니다. 처음에는 번거롭게 느껴질 수 있지만, 상태의 위치가 명확해지면 애플리케이션을 이해하고 디버깅하기가 훨씬 쉬워집니다.
