# 프론트엔드 소식 월간 뉴스레터 2022-07

안녕하세요, 프론트엔드 개발자 여러분. 무더운 여름이 시작된 2022년 7월의 프론트엔드 소식을 모아 전합니다. React 18이 자리를 잡으면서 프레임워크 생태계가 어디로 움직이는지, 빌드 도구가 어떤 속도 경쟁을 벌이는지, 브라우저가 어떤 새 기능을 준비하는지 차례로 살펴보겠습니다.

## 이달의 키워드

- **서버 중심 렌더링의 확산**: SSR, SSG, 스트리밍 렌더링이 메타 프레임워크의 기본 기능으로 자리 잡고 있습니다.
- **빌드 도구의 속도 경쟁**: 번들러와 개발 서버는 "개발 중 즉시 실행"을 목표로 계속 재설계되고 있습니다.
- **프라이버시와 웹 표준**: 서드파티 쿠키 정책 변화가 광고, 분석, 로그인 방식 전반에 영향을 주고 있습니다.

## 1. 프레임워크와 라이브러리

### React 18 이후의 흐름

React 18이 정식 출시된 뒤 커뮤니티의 관심은 동시성 기능(Concurrent Features)을 실제 서비스에 어떻게 적용할지로 옮겨 갔습니다. `useTransition`과 `useDeferredValue`로 입력 반응성을 지키는 패턴, `Suspense`를 데이터 로딩 경계로 쓰는 사례가 기술 블로그를 중심으로 많이 공유되었습니다. 상태 관리 라이브러리 작성자들도 자사 도구가 새 렌더링 동작과 충돌하지 않도록 점검하느라 분주했습니다.

```jsx
const Chart = lazy(() => import('./Chart'));

<Suspense fallback={<Spinner />}>
  <Chart data={data} />
</Suspense>
```

### 라우팅과 데이터 로딩

라우터 라이브러리들은 "화면을 그린 뒤 데이터를 가져오는" 방식에서 "라우트 단위로 데이터를 미리 가져오는" 방식으로 무게 중심을 옮기고 있습니다. 로더(loader)와 액션(action) 개념이 도입되면서 폼 제출과 데이터 갱신을 라우팅 계층에서 처리하는 패턴이 주목받았습니다. 컴포넌트마다 흩어져 있던 페칭 로직이 한곳으로 모이면서 로딩 상태와 에러 처리가 단순해진다는 평가가 많았습니다.

### Angular와 Vue

Angular는 14 버전에서 선보인 독립형 컴포넌트(standalone component)를 중심으로 NgModule 의존을 줄이는 방향을 이어 가고 있습니다. 새 프로젝트에서는 모듈 없이 컴포넌트를 바로 가져다 쓰는 구성이 점점 자연스러워지는 흐름입니다. Vue 생태계에서는 Vue 3 기반 도구 체인과 TypeScript 지원이 안정되면서, Vue 2 프로젝트를 Vue 3로 옮기는 마이그레이션 가이드와 사례 글이 크게 늘었습니다.

## 2. 빌드 도구와 개발 환경

### Vite 3.0 출시

7월 중순 Vite 3.0이 공개되었습니다. 메이저 업데이트답게 지원 Node.js 버전 정책이 정리되었고, 내부 번들러 기반이 Rollup 3 계열로 바뀌었습니다. 기존 프로젝트를 업그레이드할 때는 Node.js 최소 버전과 플러그인 호환성을 먼저 확인하는 것이 좋습니다. 빌드 설정 파일이 단순한 편이라 마이그레이션 자체는 대부분 어렵지 않다는 후기가 이어졌습니다.

### TypeScript 차기 버전

TypeScript는 4.8 공개를 앞두고 있었습니다. 타입 추론 개선과 제네릭 관련 동작 변화가 예고되어, 라이브러리의 타입 정의를 관리하는 팀은 미리 테스트 빌드를 돌려 보는 것이 권장되었습니다. 타입 변화로 기존 코드가 깨지는 경우를 대비해 `tsc --noEmit`을 CI 단계에 넣어 두면 릴리스 직전의 당황을 줄일 수 있습니다.

### 패키지 매니저와 모노레포

npm, Yarn, pnpm을 비교하는 글과 모노레포 도구(Turborepo, Nx) 활용기가 꾸준히 공유되었습니다. 설치 속도와 디스크 사용량 측면에서 pnpm의 장점이 자주 언급되었고, 원격 캐시와 작업 그래프 최적화가 대규모 저장소의 핵심 관심사로 떠올랐습니다. 여러 패키지가 한 저장소에서 빌드와 테스트를 공유하는 구조가 더는 특별하지 않은 선택이 되어 가는 분위기입니다.

## 3. 웹 플랫폼과 브라우저

- **서드파티 쿠키 단계적 폐지 연기**: 구글은 크롬에서 서드파티 쿠키 차단 일정을 늦추고, 대체 기술인 Privacy Sandbox 제안을 계속 다듬겠다고 발표했습니다. 광고 식별이나 로그인 연동을 쿠키에 의존해 온 서비스라면 대응 계획을 다시 점검할 시점입니다. 퍼스트파티 데이터 수집 구조를 준비해 두는 것이 공통된 조언이었습니다.
- **웹 상호운용성 프로젝트**: 주요 브라우저 엔진 개발사들이 함께 추진하는 Interop 2022는 CSS 레이아웃, 폼, 스크롤, 날짜와 시간 처리 등에서 브라우저 간 차이를 줄이는 것을 목표로 합니다. 같은 기능이 브라우저마다 다르게 동작하던 문제를 줄이면, 개발자가 호환성 코드에 쓰던 시간도 자연히 줄어듭니다.
- **CSS 신기능**: 컨테이너 쿼리, 상위 선택자 `:has()`, 캐스케이드 레이어 `@layer` 등이 지원 범위를 넓혀 가고 있습니다. "자바스크립트 없이 할 수 있는 일"의 경계가 계속 옮겨 가는 만큼, 레이아웃 로직을 스크립트에서 CSS로 옮길 수 있는지 한 번씩 검토해 볼 만합니다.

## 4. 테스트와 품질

컴포넌트 테스트에서는 React Testing Library와 Vitest를 함께 쓰는 조합이 주목받았습니다. 사용자 관점에서 화면을 검증하는 방식이 권장되면서, 구현 세부 사항보다 "사용자가 보는 결과"를 기준으로 테스트를 작성하는 팀이 늘었습니다. 접근성 측면에서는 린터와 자동 검사 도구를 CI에 포함해 배포 전에 누락된 대체 텍스트나 키보드 접근 문제를 잡아내는 사례도 많이 공유되었습니다.

## 5. 커뮤니티 소식

국내외 프론트엔드 밋업과 컨퍼런스에서는 SSR 성능 개선, 디자인 시스템 운영, 마이크로 프론트엔드 도입 사례 발표가 이어졌습니다. 특히 디자인 시스템을 여러 팀이 함께 쓰기 위해 문서화와 버전 관리를 어떻게 하는지에 대한 발표가 많았습니다. Storybook 같은 컴포넌트 카탈로그 도구는 디자이너와 개발자가 같은 화면을 보고 대화하는 공통 언어 역할을 한다는 점이 강조되었습니다.

## 6. 이달의 팁: 번들 크기 점검 루틴

번들이 커지는 문제는 한 번 해결해도 다시 쌓이기 쉽습니다. 다음 루틴을 정기적으로 돌려 보세요.

1. 빌드 결과물을 시각화하는 도구로 큰 청크와 중복 의존성을 찾습니다.
2. 라우트 단위로 동적 `import`를 적용해 처음 로딩에 필요한 코드를 줄입니다.
3. 날짜, 아이콘, 유틸리티 라이브러리는 전체를 가져오지 말고 필요한 함수만 가져옵니다.
4. CI에 번들 용량 임계값을 설정해, 큰 변경이 들어올 때 자동으로 알림을 받습니다.

작은 습관이 쌓이면 첫 화면 로딩 시간과 모바일 사용자의 체감 속도가 눈에 띄게 달라집니다.
