# 2021-11

프론트엔드 개발 소식을 모아 전하는 월간 뉴스레터입니다. 2021년 11월에는 메타 프레임워크, 타입스크립트, 브라우저 릴리스, 그리고 서버 컴포넌트 같은 새로운 렌더링 방식까지 여러 분야에서 변화가 이어졌습니다. 이번 호에서는 개발 현장에 바로 영향을 줄 만한 소식을 중심으로 정리했습니다.

---

## 1. 이달의 헤드라인: 메타 프레임워크의 진화

10월 말 출시된 **Next.js 12**의 여파가 11월에도 계속되었습니다. Rust로 작성된 컴파일러 SWC를 도입해 빌드와 새로고침 속도를 크게 끌어올렸고, 요청이 페이지에 도달하기 전에 로직을 실행하는 **미들웨어(Middleware)** 기능이 추가되었습니다. 인증 검사나 A/B 테스트처럼 요청 단계에서 처리해야 하는 작업을 CDN에 가까운 엣지 런타임에서 수행할 수 있다는 점이 많은 관심을 받았습니다.

**Angular 13**도 11월 초 출시되었습니다. 이번 버전부터 기존 렌더링 엔진인 View Engine이 완전히 제거되고 Ivy 렌더러만 남았습니다. 그 결과 번들 크기가 줄고 빌드 구조가 단순해졌습니다. 다만 오래된 라이브러리에 의존하는 프로젝트라면 마이그레이션 전에 호환성을 점검할 필요가 있습니다.

## 2. 언어와 도구: TypeScript 4.5

11월 중순 **TypeScript 4.5**가 공개되었습니다. 실무에서 체감하기 쉬운 변화는 다음과 같습니다.

- **`Awaited` 유틸리티 타입**: `Promise`를 중첩된 깊이까지 재귀적으로 벗겨 최종 값의 타입을 얻을 수 있습니다. 비동기 함수의 반환 타입을 다룰 때 특히 유용합니다.
- **조건부 타입의 꼬리 재귀 최적화**: 재귀적으로 작성한 조건부 타입이 깊이 제한에 걸리는 경우가 줄었습니다. 타입 수준의 반복 계산을 더 안정적으로 작성할 수 있게 되었습니다.
- **`import { type X }` 구문**: 타입 전용 가져오기를 명확히 표시할 수 있어, 런타임 번들에 불필요한 코드가 포함되는 문제를 줄일 수 있습니다.

빌드 도구 쪽에서는 Vite 2.x 계열이 꾸준한 개선을 이어갔습니다. 개발 서버의 빠른 시작과 즉각적인 모듈 교체(HMR)라는 장점이 여전히 유효하다는 평가가 많았습니다.

## 3. 브라우저와 웹 플랫폼

**Firefox 94**가 11월 초 배포되었고, **Chrome 96**도 11월 중순 정식 출시되었습니다. 두 브라우저 모두 최신 웹 표준 지원 범위를 넓히는 업데이트를 담았습니다. 새로운 API를 도입하기 전에는 릴리스 노트와 지원 현황 표를 한 번 확인해 두는 것이 좋습니다.

Core Web Vitals(LCP, FID, CLS)가 검색 순위 신호로 반영되면서 성능 측정은 이제 출시 직전에 하는 점검이 아니라, 설계 단계에서부터 고려해야 할 기본 요건으로 자리 잡고 있습니다. 이미지 포맷 최적화, 불필요한 자바스크립트 줄이기, 레이아웃 흔들림 방지 같은 주제가 이달 여러 커뮤니티에서 반복해서 다뤄졌습니다.

## 4. 커뮤니티와 생태계의 방향

React 팀은 10월 말 React Conf 2021에서 **React 18**의 방향을 공유했습니다. 동시성 렌더링(Concurrent Rendering)과 **서버 컴포넌트(Server Components)**가 핵심 주제였고, 11월 내내 관련 실험 사례와 해설 글이 이어졌습니다. 서버 컴포넌트는 데이터 가져오기를 서버 쪽으로 옮겨 클라이언트 번들을 줄이는 접근이라, 기존 SSR 구조를 어떻게 바꿀지에 대한 논의가 활발했습니다.

## 5. 이달 자주 다뤄진 주제

- **상태 관리의 분리**: 서버에서 가져온 상태(서버 상태)와 화면 안에서만 쓰는 상태(클라이언트 상태)를 나눠 관리하라는 조언이 여러 글에서 반복되었습니다. 캐싱과 재검증 로직을 전용 라이브러리에 맡기는 방식이 확산되는 흐름입니다.
- **디자인 토큰의 단일 출처**: 색상과 간격 같은 디자인 값을 CSS 변수와 TypeScript 타입으로 함께 관리해, 디자이너와 개발자가 같은 값을 보게 하는 사례가 늘었습니다.
- **번들 분석과 코드 분할**: 번들 분석 도구로 실제 용량을 확인하고, 라우트 단위로 코드를 나누어 초기 로딩을 줄인 경험담이 많이 공유되었습니다.

## 6. 이번 달의 실천 과제

이달 소식을 바탕으로 세 가지를 제안합니다.

1. 사용 중인 프레임워크의 **다음 메이저 버전 마이그레이션 가이드**를 미리 읽어 보세요.
2. 프로젝트의 **번들 크기를 한 번 측정**하고, 가장 큰 의존성 하나를 대체할 수 있는지 검토해 보세요.
3. 새로 쓰려는 브라우저 API는 **지원 현황을 먼저 확인**하고, 폴백 전략을 함께 설계하세요.
