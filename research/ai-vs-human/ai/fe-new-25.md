# 프론트엔드 뉴스레터 2021-04

안녕하세요. 한 달 동안 쏟아진 프론트엔드 소식을 모아 전해 드리는 월간 뉴스레터입니다. 2021년 4월에는 주요 브라우저와 런타임의 정식 릴리스, 타입스크립트 베타, 자바스크립트 표준 진행 상황 등 굵직한 소식이 이어졌습니다. 이번 호에서는 릴리스, 웹 표준, 도구와 생태계, 커뮤니티 순서로 정리하고, 실무에서 바로 써볼 수 있는 작은 팁도 준비했습니다.

---

## 1. 이달의 주요 릴리스

### Chrome 90 정식 출시
4월 중순 Chrome 90이 안정 채널에 배포되었습니다. 웹 플랫폼 기능과 개발자 도구 쪽에 여러 변경이 포함되었습니다. 자신의 프로젝트에 영향을 줄 수 있는 항목은 릴리스 노트에서 먼저 확인해 보시기를 권합니다. 브라우저 호환성 표를 주기적으로 점검하는 습관은 이런 릴리스 시즌에 특히 도움이 됩니다.

### Firefox 88
4월 하순에 공개된 Firefox 88은 렌더링 안정성과 개발자 도구 개선에 초점을 맞췄습니다. 여러 브라우저에서 같은 화면을 보장해야 하는 팀이라면 교차 브라우저 테스트 범위를 다시 점검할 좋은 시점입니다.

### Node.js 16
4월 중순 Node.js 16이 공개되었습니다. 최신 V8 엔진이 적용되어 자바스크립트 실행 성능이 개선되었고, 이 버전은 그해 10월 LTS로 전환될 예정이었습니다. 프론트엔드 빌드 도구와 테스트 러너가 Node 런타임에 의존하므로, 로컬 개발 환경의 Node 버전을 함께 점검하는 것이 좋습니다.

### TypeScript 4.3 베타
TypeScript 4.3 베타에서는 `override` 키워드가 소개되었습니다. 상위 클래스의 메서드를 재정의할 때 실수로 이름을 틀리는 문제를 컴파일 단계에서 잡아낼 수 있게 되었습니다. 또한 getter와 setter가 서로 다른 타입을 가질 수 있도록 하는 변경이 포함되었습니다. 정식 릴리스 전이라 세부 동작은 바뀔 수 있으니 베타 단계에서 미리 실험해 보는 용도로 활용하시면 좋겠습니다.

## 2. 웹 표준과 자바스크립트 언어

### ES2021 기능의 최종 단계 진입
TC39 회의에서 논리 할당 연산자(`&&=`, `||=`, `??=`), `String.prototype.replaceAll`, `Promise.any`, `WeakRef` 등의 제안이 최종 단계인 4단계(Stage 4)에 도달했다는 소식이 전해졌습니다. 4단계에 오른 제안은 다음 ECMAScript 명세에 포함될 것으로 봐도 무방합니다. 최신 문법을 바로 쓰기 어려운 환경이라면 트랜스파일러 설정에서 대상 브라우저 목록을 점검해 두세요.

### 성능 지표가 검색 순위에 반영되는 흐름
Core Web Vitals 지표(LCP, FID, CLS)를 검색 순위 신호로 활용하겠다는 구글의 계획이 구체화되면서 성능 측정에 대한 관심이 커졌습니다. 실사용자 데이터(RUM)와 실험실 측정 도구를 함께 쓰는 방식이 권장되었습니다. 이미지 크기 지정, 웹 폰트 로딩 전략, 레이아웃 이동 방지 같은 기본기가 다시 강조된 한 달이었습니다.

## 3. 도구와 생태계

- **빌드 도구:** Vite가 개발 서버의 빠른 시작과 즉각적인 모듈 교체(HMR)로 많은 관심을 받았습니다. 번들 기반 도구와 비교하는 벤치마크 글이 여럿 공유되었습니다.
- **CSS 프레임워크:** Tailwind CSS는 JIT(Just-in-Time) 방식의 컴파일러를 중심으로 빌드 속도와 생성 CSS 용량을 줄이는 방향으로 발전하고 있었습니다. 사용하지 않는 클래스를 자동으로 제거하는 방식이 실무에서도 점점 자리를 잡았습니다.
- **메타 프레임워크:** Next.js는 이미지 최적화와 서버 사이드 렌더링, 정적 생성 기능을 강화하는 방향이었습니다. 페이지별 렌더링 방식을 고르는 기준을 정리한 글도 많이 읽혔습니다.
- **컴포넌트 문서화:** Storybook을 활용해 디자인 시스템과 UI 컴포넌트를 독립적으로 검증하는 사례가 늘었습니다. 시각적 회귀 테스트를 함께 붙이는 팀도 많아졌습니다.

## 4. 커뮤니티에서 읽을 만한 글

- **접근성(a11y):** 키보드 포커스 순서, 의미 있는 ARIA 사용법, 색상 대비 기준을 다룬 실무 가이드가 꾸준히 공유되었습니다. 접근성은 나중에 덧붙이는 기능이 아니라 컴포넌트 설계 단계에서 함께 고려해야 한다는 의견이 많았습니다.
- **상태 관리:** 전역 스토어를 줄이고 서버 상태와 클라이언트 상태를 분리하자는 흐름이 계속되었습니다. 데이터 페칭 라이브러리를 중심으로 구조를 다시 짜는 사례가 소개되었습니다.
- **CSS 레이아웃:** 컨테이너 쿼리와 같은 새로운 CSS 기능을 어떻게 점진적으로 도입할지에 대한 논의가 이어졌습니다. 브라우저 지원 현황을 기준으로 폴백을 설계하는 방법도 자주 다뤄졌습니다.

## 5. 이달의 팁: `Promise.any`로 가장 빠른 응답 쓰기

여러 엔드포인트 중 가장 먼저 성공한 응답만 필요할 때 `Promise.any`가 유용합니다. 모든 요청이 실패하면 `AggregateError`가 던져지므로 이를 함께 처리해 주세요.

```js
async function fetchFastest(urls) {
  try {
    const response = await Promise.any(urls.map((url) => fetch(url)));
    return await response.json();
  } catch (error) {
    if (error instanceof AggregateError) {
      console.error('모든 요청이 실패했습니다.', error.errors);
    }
    throw error;
  }
}

const data = await fetchFastest([
  'https://api-a.example.com/data',
  'https://api-b.example.com/data',
]);
```

미러 서버나 여러 CDN 중 응답이 빠른 쪽을 고르는 상황에 잘 맞습니다. 다만 요청이 모두 서버에 전달되므로 트래픽 비용을 함께 고려해야 합니다.
