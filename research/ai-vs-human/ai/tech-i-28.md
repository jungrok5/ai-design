# Sort_Radix (기수 정렬)

## 1. 개요
기수 정렬(Radix Sort)은 **원소끼리 비교하지 않는 정렬 알고리즘**입니다. 수를 자릿수(digit) 단위로 나누고, 각 자릿수를 기준으로 정렬을 여러 번 반복해 전체를 정렬합니다. 비교 기반 정렬은 하한이 `O(n log n)`인데, 기수 정렬은 키의 길이가 정해져 있으면 **선형 시간**에 정렬할 수 있습니다.

## 2. 동작 방식
- **LSD(Least Significant Digit)**: 가장 낮은 자리(1의 자리)부터 높은 자리 순서로 정렬합니다. 정수 정렬에 주로 씁니다.
- **MSD(Most Significant Digit)**: 가장 높은 자리부터 정렬합니다. 그룹마다 재귀로 처리하며, 문자열의 사전순 정렬에 적합합니다.

**LSD 예시** `[170, 45, 75, 90, 802, 24, 2, 66]`
1. 1의 자리 기준: `[170, 90, 802, 2, 24, 45, 75, 66]`
2. 10의 자리 기준: `[802, 2, 24, 45, 66, 170, 75, 90]`
3. 100의 자리 기준: `[2, 24, 45, 66, 75, 90, 170, 802]`

## 3. 핵심 포인트: 안정 정렬
자릿수마다 수행하는 정렬은 반드시 **안정 정렬(Stable Sort)** 이어야 합니다. 그래야 앞 단계에서 정해진 순서가 다음 단계에서도 유지됩니다. 보통 **계수 정렬(Counting Sort)** 이나 버킷(큐)을 사용합니다.

## 4. 구현 (Python)
```python
def counting_sort(arr, exp):
    n = len(arr)
    output = [0] * n
    count = [0] * 10
    for num in arr:
        count[(num // exp) % 10] += 1
    for i in range(1, 10):
        count[i] += count[i - 1]          # 누적합
    for num in reversed(arr):             # 역순 순회 → 안정성 보장
        idx = (num // exp) % 10
        count[idx] -= 1
        output[count[idx]] = num
    return output

def radix_sort(arr):
    if not arr:
        return arr
    exp = 1
    while max(arr) // exp > 0:
        arr = counting_sort(arr, exp)
        exp *= 10
    return arr
```

## 5. 복잡도
| 항목 | 값 |
|---|---|
| 시간 복잡도 | `O(d · (n + k))` |
| 공간 복잡도 | `O(n + k)` |
| 안정성 | 안정 정렬 |
| 제자리 정렬 | 아님 |

- `n`: 원소 수, `d`: 최대 자릿수, `k`: 기수(10진수면 10)

## 6. 장단점
**장점**
- 자릿수가 작고 고정되어 있으면 비교 정렬보다 빠릅니다.
- 안정 정렬이라 다중 키 정렬에 활용할 수 있습니다.

**단점**
- 추가 메모리가 필요합니다.
- 정수나 고정 길이 문자열처럼 자릿수로 나눌 수 있는 데이터에만 쓸 수 있습니다.
- 실수와 음수는 따로 처리해야 합니다. 음수는 양수와 분리하거나 오프셋을 더해 처리합니다.

## 7. 면접 예상 질문
- **Q. 기수 정렬은 왜 `O(n log n)` 하한을 깰 수 있나요?**
  A. 원소끼리 비교하지 않고 키의 구조(자릿수)를 이용하기 때문입니다. 비교 기반 정렬의 하한은 이 경우에 적용되지 않습니다.
- **Q. LSD에서 내부 정렬이 안정적이지 않으면 어떻게 되나요?**
  A. 앞 자릿수에서 맞춰 둔 순서가 깨져서 결과가 틀립니다.
- **Q. 계수 정렬과 어떻게 다른가요?**
  A. 계수 정렬은 값의 범위 `k`가 크면 메모리를 많이 씁니다. 기수 정렬은 자릿수로 나눠 처리하므로 범위가 큰 정수도 다룰 수 있습니다.
- **Q. 언제 쓰면 좋나요?**
  A. 전화번호, 우편번호, 고정 길이 ID처럼 길이가 정해진 키를 대량으로 정렬할 때 좋습니다.
