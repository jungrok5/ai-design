**웹의 동작 방식**은 컴퓨터나 휴대폰의 웹 브라우저에서 웹 페이지를 볼 때 어떤 일이 일어나는지 간단히 설명합니다.

당장 웹 코드를 작성하는 데 이 이론이 꼭 필요하지는 않습니다. 하지만 머지않아 배경에서 무슨 일이 일어나는지 알면 도움이 됩니다.

## 클라이언트와 서버

웹에 연결된 컴퓨터는 **클라이언트**와 **서버**로 나뉩니다. 둘이 주고받는 과정을 단순화하면 다음과 같습니다.

![클라이언트와 서버의 기본 구조](simple-client-server.png)

- **클라이언트**는 일반 사용자의 인터넷 연결 기기(예: Wi-Fi에 연결된 컴퓨터, 모바일 네트워크에 연결된 휴대폰)와 그 기기에서 실행되는 웹 접근 소프트웨어(보통 Firefox나 Chrome 같은 웹 브라우저)를 말합니다.
- **서버**는 웹 페이지, 사이트, 앱을 저장하는 컴퓨터입니다. 클라이언트 기기가 웹 페이지에 접근하려고 하면, 페이지 사본이 서버에서 클라이언트로 내려받아져 사용자의 웹 브라우저에 표시됩니다.

## 도구 상자의 다른 부분들

위에서 설명한 클라이언트와 서버만으로는 전체 그림이 완성되지 않습니다. 다른 많은 요소가 함께 관여하며, 아래에서 하나씩 살펴보겠습니다.

지금은 웹을 하나의 길이라고 상상해 봅시다. 길 한쪽 끝에는 여러분의 집과 같은 클라이언트가 있고, 반대쪽 끝에는 여러분이 물건을 사고 싶은 가게와 같은 서버가 있습니다.

![도로에 비유한 웹](road.jpg)

클라이언트와 서버 외에도 다음 요소들을 알아 두어야 합니다.

- **인터넷 연결**: 웹에서 데이터를 주고받을 수 있게 해 줍니다. 집과 가게 사이를 잇는 길과 같습니다.
- **TCP/IP**: 전송 제어 프로토콜(Transmission Control Protocol)과 인터넷 프로토콜(Internet Protocol)은 데이터가 인터넷을 통해 어떻게 이동하는지 정의하는 통신 프로토콜입니다. 가게에 가서 물건을 주문하고 사는 데 쓰는 교통수단과 같습니다. 우리의 예에서는 자동차나 자전거(혹은 그 밖의 어떤 이동 수단)에 해당합니다.
- **DNS**: 도메인 이름 시스템(Domain Name System)은 웹사이트의 주소록과 같습니다. 브라우저에 웹 주소를 입력하면 브라우저는 원하는 웹사이트를 불러오기 전에 DNS를 조회합니다. 브라우저는 웹 페이지가 있는 서버를 찾아 HTTP 메시지를 올바른 곳으로 보내야 하기 때문입니다. 가게의 주소를 찾아보는 일과 같습니다.
- **HTTP**: 하이퍼텍스트 전송 프로토콜(Hypertext Transfer Protocol)은 클라이언트와 서버가 서로 소통하는 데 쓰는 언어를 정의하는 애플리케이션 {{Glossary("Protocol", "프로토콜")}}입니다. 물건을 주문할 때 쓰는 말과 같습니다.
- **구성 파일**: 웹사이트는 여러 개의 서로 다른 파일로 이루어집니다. 가게에 있는 다양한 상품과 같습니다. 이 파일들은 크게 두 종류로 나뉩니다.
  - **코드 파일**: 웹사이트는 주로 HTML, CSS, JavaScript로 만들어집니다. 다른 기술도 나중에 만나게 될 것입니다.
  - **애셋**: 웹사이트를 이루는 코드 외의 모든 것을 통틀어 부르는 이름입니다. 이미지, 음악, 비디오, Word 문서, PDF 등이 여기에 속합니다.

## 그래서 정확히 무슨 일이 일어나나요?

브라우저에 웹 주소를 입력하면(비유하자면 가게로 걸어가면) 다음과 같은 일이 일어납니다.

1. 브라우저가 DNS 서버로 가서 웹사이트를 보관 중인 서버의 실제 주소를 찾습니다(가게 주소를 찾습니다).
2. 브라우저가 서버에 HTTP 요청 메시지를 보내, 웹사이트 사본을 클라이언트에게 보내 달라고 요청합니다(가게에 가서 상품을 주문합니다). 이 메시지를 포함해 클라이언트와 서버 사이를 오가는 모든 데이터는 TCP/IP를 통해 인터넷 연결 위로 전송됩니다.
3. 서버가 클라이언트의 요청을 승인하면, 서버는 클라이언트에게 "200 OK" 메시지를 보냅니다. 이는 "물론이죠, 웹사이트를 보시면 됩니다! 여기 있어요"라는 뜻입니다. 그리고 웹사이트 파일을 **데이터 패킷**이라는 작은 조각들로 나누어 브라우저에 보내기 시작합니다(가게에서 상품을 건네주고, 여러분은 그것을 집으로 가져옵니다).
4. 브라우저가 작은 조각들을 모아 완전한 웹 페이지로 조립하고 여러분에게 보여 줍니다(상품이 집 앞에 도착합니다. 반짝반짝 새것이네요!).

## 구성 파일을 해석하는 순서

브라우저가 서버에 HTML 파일을 요청하면, 그 HTML 파일에는 보통 외부 CSS 스타일시트를 참조하는 {{htmlelement("link")}} 요소와 외부 JavaScript 스크립트를 참조하는 {{htmlelement("script")}} 요소가 들어 있습니다. 페이지를 불러올 때 브라우저가 이 파일들을 어떤 순서로 해석하는지 알아 두는 것이 중요합니다.

- 브라우저는 먼저 HTML 파일을 해석하고, 그 과정에서 CSS를 가리키는 `<link>` 요소와 JavaScript를 가리키는 `<script>` 요소를 발견합니다.
- 브라우저는 HTML을 해석하면서 발견한 `<link>`의 CSS 파일과 `<script>`의 JavaScript 파일을 서버에 다시 요청합니다.
- 브라우저는 불러온 HTML로부터 메모리에 {{Glossary("DOM")}} 트리를 만들고, 불러온 CSS로부터 {{Glossary("CSSOM")}} 구조를 만들며, 불러온 JavaScript를 컴파일하고 실행합니다.
- DOM 트리와 CSSOM이 만들어지는 동안, 브라우저는 그 구조를 바탕으로 렌더 트리를 구성하고, 각 노드에 적용될 스타일을 계산해 화면에 픽셀을 그립니다. 이렇게 페이지가 화면에 나타나면 불러오기가 끝납니다.

> [!NOTE]
> 이 설명은 매우 단순화한 것입니다. 실제 과정은 훨씬 복잡하며, 자세한 내용은 [브라우저의 동작 방식](/ko/docs/Web/Performance/How_browsers_work)에서 확인할 수 있습니다.

## DNS 설명

실제 웹 주소는 여러분이 주소 표시줄에 입력하는 기억하기 좋은 문자열이 아닙니다. 웹 주소는 `192.0.2.172`처럼 특수한 숫자들로 이루어져 있습니다. 이를 **IP 주소**라고 하며, 웹상의 고유한 위치를 나타냅니다.

그러나 이런 숫자는 기억하기 어렵습니다. 그래서 도메인 이름 시스템이 고안되었습니다. 도메인 이름 시스템은 여러분이 브라우저에 입력하는 웹 주소("mozilla.org" 등)를 웹사이트의 실제 IP 주소와 연결해 주는 특별한 서버입니다.

웹사이트에는 IP 주소로 직접 접근할 수도 있습니다. [DNS 조회 도구](https://www.nslookup.io/website-to-ip-lookup/)에 도메인을 입력하면 해당 웹사이트의 IP 주소를 확인할 수 있습니다.

## 패킷 설명

앞에서 데이터가 서버에서 클라이언트로 "패킷" 형태로 전송된다는 표현을 썼습니다. 이게 무슨 의미일까요?

기본적으로 데이터는 웹을 통해 보내질 때 수천 개의 작은 덩어리로 나뉘어 전송됩니다. 데이터를 작은 패킷으로 보내는 데에는 여러 이유가 있습니다. 패킷은 가끔 손실되거나 손상되는데, 이럴 때는 작은 덩어리를 다시 보내는 편이 파일 전체를 다시 보내는 것보다 훨씬 수월합니다. 또한 패킷은 서로 다른 경로로 전달될 수 있어, 한 경로가 막히거나 혼잡할 때도 더 빠르게 교환할 수 있습니다. 덕분에 여러 사용자가 동시에 같은 웹사이트를 내려받을 수 있습니다. 만약 각 웹사이트를 하나의 큰 덩어리로 보낸다면 한 번에 한 사용자만 내려받을 수 있을 것이고, 웹은 지금보다 훨씬 비효율적이고 쓰기 불편할 것입니다.
