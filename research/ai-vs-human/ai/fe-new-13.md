## 🔥 이달의 헤드라인: React 18 시대가 열리다

3월 29일, React 18이 정식으로 출시되었습니다. 이번 릴리스의 핵심은 **동시성(Concurrent) 렌더링**을 앱 개발자가 실제로 활용할 수 있는 기반을 마련했다는 점입니다.

- **`createRoot` API**: 기존 `ReactDOM.render` 대신 `createRoot`로 루트를 생성해야 새 기능이 동작합니다. 기존 방식은 경고와 함께 React 17 모드처럼 동작합니다.
- **자동 배칭(Automatic Batching)**: 이벤트 핸들러뿐 아니라 `setTimeout`, Promise 콜백 등에서도 상태 업데이트가 자동으로 묶입니다. 불필요한 리렌더링이 줄어듭니다.
- **`useTransition`, `useDeferredValue`**: 검색창 입력처럼 긴급하지 않은 업데이트를 뒤로 미뤄, 입력 반응성을 지키는 패턴을 공식적으로 제공합니다.
- **`useId`와 Suspense 개선**: 서버 렌더링과 클라이언트 하이드레이션 간 ID 불일치 문제를 해결하고, Suspense로 데이터 로딩 경계를 더 자연스럽게 표현할 수 있게 되었습니다.

커뮤니티에서는 마이그레이션 중 발견된 **StrictMode의 이중 호출 동작**과 서드파티 라이브러리 호환성 이슈가 주요 화제였습니다. 업그레이드 전에는 공식 업그레이드 가이드를 먼저 확인하고, 개발 모드에서 부작용이 있는 `useEffect` 코드를 점검하는 것이 좋습니다.

## 🌐 브라우저 소식

- **Chrome 100 (3월 말)과 Chrome 101 (4월 말)**: 4월 말 정식 배포된 Chrome 101을 비롯해 여러 웹 플랫폼 기능이 안정화되었습니다. 메이저 버전 번호가 세 자리로 넘어간 것도 이슈가 되었습니다. 일부 오래된 User-Agent 파싱 로직이 버전 문자열 길이 가정 때문에 깨지는 사례가 보고되어, 라이브러리들이 관련 패치를 내놓았습니다.
- **Safari 15.4**: `:has()` 선택자가 Safari에서도 지원되기 시작하면서, 이제 주요 브라우저 전반에서 부모 선택과 상태 기반 스타일링을 표준 CSS만으로 구현할 수 있게 되었습니다. 폼 검증 스타일이나 카드 레이아웃 변형 등에 쓰임새가 큽니다.
- **Firefox**: 다음 달 초 Firefox 100 공개를 앞두고, 개발자 도구와 성능 프로파일링 기능 개선이 이어졌습니다.

> 💡 **체크포인트**: 브라우저 지원 현황은 [Can I use](https://caniuse.com)에서 확인하고, 실무 기준 브라우저 목록은 팀의 `browserslist` 설정에 명시해 두는 것이 좋습니다.

## 🛠 도구와 빌드 생태계

### Vite의 빠른 성장
Vite는 개발 서버의 네이티브 ESM 기반 구동 방식과 빠른 HMR 덕분에 입지를 넓히고 있습니다. 이번 달에는 Vue, React, Svelte 등 주요 프레임워크 템플릿과 플러그인 생태계가 함께 성장했습니다. 차기 메이저 버전을 향한 논의도 활발했고, 기존 Webpack 프로젝트에서 Vite로 옮기는 마이그레이션 사례가 늘었습니다.

### TypeScript 4.7 준비
TypeScript 4.7 베타가 공개되며, Node.js의 ES 모듈(ESM) 지원, `infer` 타입의 `extends` 제약, 인스턴스화 표현식(instantiation expressions) 등이 소개되었습니다. 타입 시스템이 최신 Node 모듈 체계와 더 잘 맞물리게 된 점이 특히 주목받았습니다.

### Angular 13.3
Angular 13.3에서는 빌드 성능과 개발 경험을 중심으로 한 개선이 이어졌습니다. 같은 시기 Angular 팀은 독립형(standalone) 컴포넌트 등 모듈 없는 구조를 향한 방향을 공개적으로 논의하고 있었습니다.

## 📚 읽을거리와 커뮤니티 이야기

- **상태 관리의 다양화**: Redux 중심의 구조에서 벗어나 Recoil, Jotai, Zustand처럼 가볍고 원자(atom) 단위인 라이브러리를 선택하는 흐름이 이어졌습니다. 기준은 "전역 상태가 정말 필요한가"를 먼저 묻는 것입니다.
- **런타임 CSS-in-JS에 대한 재고**: 스타일을 자바스크립트 런타임에서 주입하는 방식이 렌더링 성능에 미치는 영향이 다시 논의되었습니다. 정적 추출(zero-runtime) 방식과 Tailwind 같은 유틸리티 기반 접근이 대안으로 언급되었습니다.
- **마이크로 프론트엔드의 현실**: 조직 규모가 커질수록 독립 배포의 이점이 있지만, 공통 디자인 시스템과 번들 중복 관리 비용이 크다는 실무 경험담이 많이 공유되었습니다.

## 💡 이달의 팁: 사용자 경험을 숫자로 보기

Google의 **Core Web Vitals** 지표는 검색 노출에도 영향을 주기 시작했습니다. 주요 지표는 다음과 같습니다.

| 지표 | 의미 | 권장 기준(75퍼센타일) |
|---|---|---|
| **LCP** | 가장 큰 콘텐츠가 그려지는 시간 | 2.5초 이하 |
| **FID** | 첫 입력에 대한 반응 지연 | 100ms 이하 |
| **CLS** | 레이아웃이 밀리는 정도 | 0.1 이하 |

`web-vitals` 라이브러리를 프로덕션에 붙여 실제 사용자 데이터를 수집하면, 개발 환경에서는 놓치기 쉬운 문제를 찾을 수 있습니다. 이미지에 명시적인 `width`와 `height`를 지정하는 것만으로도 CLS를 크게 줄일 수 있습니다.
