# 프론트엔드 소식 2021-03

*매달 프론트엔드 생태계의 주요 소식을 모아 전합니다.*

---

## 편집자의 인사

안녕하세요, 프론트엔드 개발자 여러분. 2021년 3월 호를 보내드립니다.

3월은 봄이 시작되는 달이지만 개발자 커뮤니티에는 겨울이 끝나고 새 기능이 쏟아지는 달이었습니다. 2월에 공개된 TypeScript 4.2를 실제 프로젝트에 적용해 보는 분들이 늘었고, React 17의 안정화 패치가 이어졌으며, 브라우저 제작사들은 웹 플랫폼의 새로운 기능을 계속 출시했습니다. 이번 호에서는 그중 실무에 바로 영향을 줄 만한 소식을 골라 정리했습니다.

---

## 이번 달의 핵심 소식

- **React 17.0.2 패치 릴리스**: 3월 말 React 17의 첫 패치 버전이 나왔습니다. 기능 변화보다는 안정성을 다듬는 릴리스였습니다. 17 버전은 "점진적 업그레이드"를 목표로 한 버전이라, 새 기능보다는 여러 React 버전이 한 앱 안에서 공존할 수 있도록 하는 데 초점이 맞춰져 있습니다.
- **Chrome 89 정식 출시**: 3월 초 Chrome 89가 공개되었습니다. 웹 플랫폼 기능의 확장이 꾸준히 이어지는 흐름 속에서, 개발자들은 새 버전의 호환성 변화를 점검할 필요가 있습니다.
- **Firefox 87 출시**: 3월 말 Firefox 87이 출시되었습니다. 브라우저 간 기능 격차를 확인하는 데 참고할 만한 릴리스입니다.
- **Google 페이지 경험(Page Experience) 신호 적용 예고**: 구글은 Core Web Vitals를 검색 순위 신호에 포함하는 계획을 이어서 알렸습니다. 2021년 5월 적용이 예정되어 있어, 이 시기 많은 사이트가 LCP, FID, CLS 지표를 점검하기 시작했습니다.

## 프레임워크와 라이브러리

### React 생태계

React 17은 기능 추가보다 **업그레이드 경로**를 바꾸는 데 의미가 큰 버전입니다. 이벤트 위임 위치가 `document`에서 루트 컨테이너로 옮겨져, 하나의 페이지에 여러 React 버전을 섞어 쓰는 상황에서도 충돌이 줄었습니다. 3월의 패치 릴리스는 이 변화에 따른 일부 엣지 케이스를 다듬었습니다.

실무에서는 다음 사항을 점검하면 좋습니다.

- 콘솔에 나타나는 경고 메시지를 모두 확인하고, 사용 중인 서드파티 라이브러리가 React 17을 지원하는지 확인합니다.
- `useEffect` 정리(cleanup) 시점이 이전보다 명확해졌으므로, 정리 로직이 있는 컴포넌트를 다시 살펴볼 만합니다.
- 점진적 업그레이드 기능을 활용하면 큰 앱도 페이지 단위로 옮길 수 있습니다.

### TypeScript 4.2 적용 후기

TypeScript 4.2는 2월 말에 공개되었고, 3월에는 실제 적용 후기가 많이 올라왔습니다. 대표적인 변화는 다음과 같습니다.

- **템플릿 리터럴 타입의 확장**: 문자열 조합으로 타입을 만드는 패턴이 더 자연스러워졌습니다.
- **리커시브 타입 참조 개선**: 재귀적인 타입 정의에서 이전보다 유연하게 동작합니다.
- **`unknown` 활용 확대**: 외부 입력을 다룰 때 `any` 대신 `unknown`을 쓰도록 안내하는 글이 많았습니다.

새 기능을 한꺼번에 도입하기보다, 기존 코드의 `any`를 줄이는 방향으로 작은 단위에서 시작하는 것이 좋다는 의견이 많았습니다.

### 그 밖의 소식

- **Vue**: Vue 3 생태계의 라이브러리와 개발 도구가 빠르게 안정화되고 있었습니다. 기존 Vue 2 프로젝트를 Vue 3로 옮기기 위한 마이그레이션 가이드도 계속 보강되었습니다.
- **Svelte**: 컴파일 방식의 장점을 강조하는 성능 비교 글이 많이 공유되었습니다. 작은 번들 크기가 여전히 가장 많이 언급되는 장점입니다.

## 브라우저와 웹 플랫폼

이번 달 브라우저 소식의 공통 주제는 **점진적 기능 확장**이었습니다. 새 기능이 한꺼번에 나오기보다는 여러 브라우저가 조금씩 지원 범위를 넓혔습니다.

- **Chrome 89**는 웹 표준 기능과 개발자 도구 개선을 함께 담았습니다. 개발자 도구에서 성능과 메모리 관련 정보를 더 쉽게 확인할 수 있도록 한 점이 눈에 띕니다.
- **Firefox 87**은 CSS와 웹 API 관련 기능을 추가하며, 여러 브라우저에서 동일하게 동작하는 기능을 늘리는 방향을 보였습니다.

실무에서는 **기능 감지(feature detection)**를 기본으로 두고, 지원 여부를 확인한 뒤 점진적으로 기능을 사용하는 방식을 권장합니다. 다음 사항도 함께 기억해 두시면 좋습니다.

- 릴리스 노트를 읽을 때는 "새 기능"보다 "깨지는 변경(breaking change)"을 먼저 확인합니다.
- 주요 브라우저의 지원 현황은 MDN과 Can I use 같은 자료에서 주기적으로 확인합니다.

## 도구와 빌드 환경

### Vite의 부상

2021년 초 공개된 Vite 2.0은 개발 서버를 ES 모듈 기반으로 구동해, 번들링 없이도 빠르게 화면을 띄우는 방식을 제시했습니다. 3월에는 Webpack에서 Vite로 옮긴 사례 글이 여러 편 올라왔습니다. 설정 파일이 단순해지고, 콜드 스타트 시간이 줄었다는 경험담이 많았습니다.

다만 플러그인 생태계는 Webpack보다 아직 작으므로, 사용 중인 로더나 플러그인이 있다면 대체 가능 여부를 먼저 확인해야 합니다.

### Node.js 16 준비

Node.js 16은 4월 정식 출시를 앞두고 베타 단계에 있었습니다. 프론트엔드 도구 체인이 Node 버전에 의존하는 경우가 많으므로, 팀의 CI 환경과 빌드 스크립트가 새 버전에서 동작하는지 미리 테스트해 두는 것이 좋습니다.

## 성능과 접근성

성능과 접근성은 이번 달에도 가장 많이 다뤄진 주제였습니다.

### Core Web Vitals 점검

Core Web Vitals의 세 지표는 다음과 같습니다.

- **LCP (Largest Contentful Paint)**: 가장 큰 콘텐츠가 그려지는 시간입니다. 2.5초 이내를 목표로 합니다.
- **FID (First Input Delay)**: 첫 입력에 반응하기까지의 지연 시간입니다. 100밀리초 이내가 권장됩니다.
- **CLS (Cumulative Layout Shift)**: 화면 레이아웃이 예기치 않게 움직이는 정도입니다. 0.1 이하를 목표로 합니다.

실무 팁으로는 이미지와 광고, 웹 폰트가 레이아웃을 밀어내지 않도록 크기를 미리 지정하는 방법이 많이 소개되었습니다. 또한 실제 사용자 데이터(RUM)를 수집하면 랩 환경의 점수와 현실의 차이를 줄일 수 있다는 의견도 많았습니다.

### 접근성

접근성 관련 글에서는 키보드 탐색, 명확한 포커스 표시, 의미 있는 HTML 구조를 강조하는 내용이 많았습니다. 특히 `div` 대신 `button`과 `a` 같은 시맨틱 요소를 쓰는 것만으로도 많은 문제가 해결된다는 점이 반복해서 언급되었습니다.

## 함께 읽어 볼 글

이번 달 커뮤니티에서 반응이 좋았던 주제는 다음과 같습니다.

- **상태 관리 단순화**: 전역 상태를 최소화하고, 서버 상태와 클라이언트 상태를 분리해 생각하는 접근법
- **컴포넌트 설계**: 재사용 가능한 컴포넌트와 도메인 컴포넌트를 구분하는 기준
- **디자인 시스템 운영**: 토큰 기반 디자인과 문서화를 함께 가져가는 방법
- **테스트 전략**: 단위 테스트보다 사용자 행동 중심의 통합 테스트에 무게를 두는 흐름

3월은 새 버전이 많이 나온 달이었지만, 가장 중요한 메시지는 **"새 기능을 쓰기 전에 기존 것을 안정적으로 다듬자"**였던 것 같습니다. React 17의 점진적 업그레이드, TypeScript의 타입 안정성 강화, 그리고 Core Web Vitals 같은 실제 사용자 경험 지표까지, 모두 기존 서비스를 더 견고하게 만드는 주제입니다.
