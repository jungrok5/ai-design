안녕하세요, 독자 여러분. 2023년 6월 호를 전해 드립니다. 이번 달에는 메타 프레임워크의 서버 중심 전환이 가장 큰 화두였습니다. 타입스크립트의 문법 개선, 브라우저의 새 기능 구현, 디자인 도구와 개발 도구의 연결도 눈에 띄었습니다. 주요 소식을 영역별로 나누어 정리했습니다.

## 🔥 이달의 헤드라인

### Next.js 13.4 이후의 App Router 생태계

5월에 공개된 Next.js 13.4에서 App Router가 안정 버전으로 자리 잡으면서, 6월에는 이를 실제 프로젝트에 적용한 사례가 크게 늘었습니다. React Server Components를 기반으로 한 레이아웃 구조와 데이터 패칭 방식이 주로 다뤄졌습니다. 커뮤니티에서 가장 많이 논의된 질문은 서버 컴포넌트와 클라이언트 컴포넌트의 경계를 어디에서 나눌 것인가였습니다. 상호작용이 많은 UI는 클라이언트 컴포넌트로, 데이터 조회 중심의 영역은 서버 컴포넌트로 두는 방식이 실무 권장 패턴으로 굳어지는 분위기입니다.

### Server Actions의 등장

폼 제출과 데이터 변경을 별도의 API 라우트 없이 서버 함수 호출로 처리하는 Server Actions도 실험 기능으로 소개되었습니다. 클라이언트 코드에서 서버 함수를 직접 호출하는 구조라 보일러플레이트가 줄어든다는 장점이 있습니다. 다만 아직 실험 단계이므로 프로덕션 적용 전에는 공식 문서의 제약 사항을 꼭 확인하셔야 합니다.

## 📦 프레임워크와 라이브러리

### React 생태계

React 18 이후 `useTransition`과 `Suspense`를 활용한 로딩 상태 관리 경험담이 많이 공유되었습니다. 긴급하지 않은 상태 업데이트를 낮은 우선순위로 처리해 입력 반응성을 지키는 방식입니다. 상태 관리 측면에서는 전역 상태를 줄이고, 서버에서 가져온 데이터를 별도의 캐시 계층으로 분리하는 패턴이 계속 자리 잡고 있습니다. 데이터 페칭 라이브러리를 중심으로 상태를 설계하면 로딩과 에러 처리 코드가 한결 간결해진다는 사례가 많았습니다.

### Angular 16의 시그널(Signals)

5월에 출시된 Angular 16은 시그널 프리뷰를 도입해 변화 감지 방식의 새로운 대안을 제시했습니다. 6월에는 기존 Zone.js 기반 모델과 시그널 기반 모델을 비교하는 글과 단계별 마이그레이션 가이드가 여러 편 올라왔습니다. 시그널은 값이 바뀐 부분만 정확히 추적하므로 불필요한 렌더링을 줄일 수 있다는 점이 핵심 장점으로 소개되었습니다.

### Svelte 4 업그레이드 가이드

Svelte 4가 출시되면서 Svelte 3 프로젝트를 옮기는 방법과 주요 변경점을 정리한 글이 함께 공유되었습니다. 컴파일러 중심 접근을 유지하면서 툴링과 호환성을 정비한 릴리스입니다. 기존 프로젝트를 운영 중이라면 변경점 목록을 먼저 훑어보고 테스트를 충분히 돌린 뒤 업그레이드하시는 것을 권장합니다.

## 🛠 언어와 도구

### TypeScript 5.1

6월에 출시된 TypeScript 5.1의 주요 변화는 두 가지입니다. 첫째, 게터(getter)와 세터(setter)가 서로 관련 없는 타입을 가질 수 있게 되었습니다. 읽을 때와 쓸 때의 타입을 다르게 선언할 수 있어 입력값 정규화 같은 패턴을 더 자연스럽게 표현할 수 있습니다. 둘째, 반환 타입이 `undefined`로 선언된 함수는 `return` 문을 생략해도 타입 오류가 나지 않도록 개선되었습니다. 콜백 함수를 작성할 때 불필요한 `return undefined`를 줄일 수 있습니다.

```ts
// TypeScript 5.1: 게터와 세터의 타입을 다르게 선언 가능
class Temperature {
  #celsius = 0;

  get fahrenheit(): number {
    return this.#celsius * 9 / 5 + 32;
  }

  set fahrenheit(value: string | number) {
    this.#celsius = (Number(value) - 32) * 5 / 9;
  }
}
```

### Vite 4 계열 업데이트

Vite 4 계열의 패치와 마이너 업데이트가 이어지며 개발 서버의 안정성과 플러그인 호환성이 개선되었습니다. Vite는 빠른 개발 서버와 Rollup 기반 빌드를 함께 제공하며, 많은 프레임워크의 기본 도구로 자리 잡은 상태입니다. 플러그인 작성자들이 Rollup 버전 상향에 맞춰 설정을 정비하는 움직임도 함께 나타났습니다.

### Node.js 20과 최소 지원 버전 상향

4월에 출시된 Node.js 20이 자리를 잡으면서, 여러 프론트엔드 도구가 최소 지원 Node 버전을 올리는 흐름이 나타났습니다. 빌드 도구와 테스트 러너를 업데이트할 때는 로컬 개발 환경과 CI 환경의 Node 버전이 일치하는지 확인하는 것이 좋습니다.

## 🌐 브라우저와 웹 표준

- **WebGPU 정식 공개**: 5월 Chrome 113에서 WebGPU가 정식으로 공개되었습니다. 브라우저에서 GPU 연산과 그래픽을 직접 다룰 수 있게 되면서, 3D 시각화와 머신러닝 추론을 웹에서 처리하는 실험이 늘었습니다.
- **View Transitions API**: 페이지나 상태가 바뀔 때 요소 간 전환 애니메이션을 선언적으로 구현할 수 있는 API입니다. 복잡한 애니메이션 라이브러리 없이도 부드러운 화면 전환을 만들 수 있다는 점이 소개되었습니다.
- **WWDC 2023과 Safari 17 베타**: 6월 5일 WWDC에서 Safari 17 베타가 공개되었습니다. 새 버전에서 지원하는 웹 기능을 확인하고, 주요 기능의 호환성 테이블을 점검해 볼 좋은 시점입니다.
- **Interop 2023**: 브라우저 벤더들이 함께 추진하는 상호 운용성 프로젝트의 중간 진행 상황이 공유되었습니다. 여러 브라우저에서 같은 방식으로 동작하는 CSS와 웹 API가 늘고 있다는 점에서 의미가 있습니다.

## 🎨 디자인과 개발의 연결

6월 말 열린 Figma Config 2023에서는 개발자를 위한 Dev Mode가 공개되었습니다. 디자인 파일에서 간격, 색상, 폰트 값과 코드 스니펫을 바로 확인할 수 있어 디자이너와 개발자 사이의 전달 과정이 짧아질 것으로 기대를 모았습니다. 디자인 토큰을 코드의 변수와 일치시키는 방식도 함께 논의되었습니다. 디자인 시스템을 운영하는 팀이라면 토큰 이름 규칙을 먼저 합의해 두면 도구 도입 효과를 더 크게 얻을 수 있습니다.

## 📈 성능과 측정

Google이 Core Web Vitals의 상호작용 지표 후보로 INP(Interaction to Next Paint)를 주목하면서, 사용자 입력 이후 화면이 반응하기까지 걸리는 시간을 측정하는 글이 많이 올라왔습니다. 기존의 로딩 지표만으로는 놓치기 쉬운 메인 스레드 지연을 찾아낼 수 있다는 점이 강조되었습니다. 긴 작업을 잘게 나누고, 무거운 이벤트 핸들러를 줄이는 것이 기본 대응 방법으로 소개되었습니다.
