3. 코드 리뷰 규칙
리뷰로 코드 품질을 높이고, 바뀐 코드를 팀 전체가 이해하게 합니다. 리뷰 대상은 사람이 아니라 코드입니다.
3-1. 작성자(PR 올리는 사람)의 책임
셀프 리뷰 먼저: 올리기 전에 diff를 직접 한 번 읽고 불필요한 변경, 디버그 코드, 주석 처리된 코드를 지웁니다.
CI 통과 확인: 빌드, 린트, 테스트가 모두 통과한 뒤 리뷰를 요청합니다.
PR 크기: 변경 400줄 이내를 권장합니다. 넘으면 PR을 나눠 올립니다.
설명 작성: 무엇을 왜 바꿨는지, 어떻게 확인했는지, 리뷰어가 특히 볼 부분을 적습니다.
코멘트 답글: 코멘트마다 반영 여부를 답글로 남깁니다. 반영하지 않으면 이유를 적습니다.
3-2. PR 제목 및 브랜치 이름
복사
3-3. 리뷰어의 책임
요청을 받으면 1 영업일 이내에 첫 리뷰를 남깁니다. 바빠서 늦어지면 미리 알립니다.
정확성, 가독성, 테스트, 보안을 중심으로 봅니다.
취향은 강요하지 않습니다. 팀 컨벤션에 없는 스타일 문제는 린터에 맡깁니다.
문제를 지적할 때는 가능하면 이유나 대안을 함께 씁니다.
남은 코멘트가 모두 해결되면 승인(Approve)합니다. 머지하려면 승인이 최소 1건 필요합니다.
3-4. 코멘트 라벨
코멘트 앞에 라벨을 붙이면 작성자가 우선순위를 바로 알 수 있습니다.
반드시 고쳐야 머지할 수 있음 (버그, 보안, 데이터 손실)
다른 방법 제안. 반영 여부는 작성자가 판단
이해가 안 되는 부분 질문. 답변이 코드 설명 역할을 함
사소한 취향·오타. 반영하지 않아도 머지 가능
잘한 부분 칭찬. 반영할 것 없음
3-5. 머지 전 확인 사항
CI 전 항목 통과
승인 1건 이상, 코멘트 모두 해결
관련 문서(README, API 문서 등) 갱신 여부 확인
DB 스키마 변경이 있다면 마이그레이션 파일 포함 여부 확인
리뷰어가 승인하면 작성자가 직접 머지
코멘트로 오해가 생기면 댓글을 더 주고받기보다 메신저나 통화로 짧게 이야기합니다.
