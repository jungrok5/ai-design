API 키 발급
약 3분
API 키는 PayAPI 서버에 요청할 때 본인을 증명하는 값입니다. 키는 두 종류가 있고,
처음에는 테스트 키만 사용합니다.
대시보드에 로그인한 뒤 개발자 > API 키 메뉴로 이동합니다.
테스트 모드가 켜져 있는지 확인합니다. 화면 상단에 주황색 배너가 보이면 테스트 모드입니다.
Secret key 생성 버튼을 누릅니다. 로 시작하는 키가 발급됩니다.
키는 생성 직후 한 번만 전체가 표시됩니다. 바로 안전한 곳(비밀 관리자, 환경 변수 파일 등)에 저장하세요.
Secret key는 서버에서만 사용하세요
브라우저 코드, 모바일 앱, 공개 저장소에 넣으면 누구나 결제를 만들거나 환불할 수 있습니다.
키가 노출됐다면 대시보드에서 즉시 폐기(Roll)하고 새 키를 발급받으세요.
환경 변수로 저장하기
예제 코드는 키를 환경 변수 에서 읽습니다. 터미널에서 한 번 설정하세요.
복사
키가 올바른지 확인하려면 계정 정보를 조회해 보세요. 가 오면 준비가 끝났습니다.

Idempotency-Key 헤더를 붙이세요
네트워크 오류로 응답을 받지 못해 같은 요청을 다시 보내도 결제는 한 번만 생성됩니다.
같은 키로 다시 보낸 요청에는 처음 응답이 그대로 돌아옵니다. 키는 주문 시도마다 고유한 값을 쓰세요.
고객을 checkout으로 보내기
응답의 로 고객을 이동시키면 결제 화면이 열립니다.

돌아오지 않을 수 있으므로, 주문 완료 처리는 웹훅을 받은 뒤에 하세요.

테스트 결제
테스트 키로 만든 결제는 실제로 청구되지 않습니다. checkout에서 카드 번호로
, 만료일은 미래 날짜, CVC는 아무 숫자 3자리를 입력하면 성공합니다.
실패 시나리오는 테스트 카드 목록을 참고하세요.
웹훅 설정
약 5분
웹훅은 결제 상태가 바뀔 때 PayAPI가 가맹점 서버의 주소로 보내는 HTTP 요청입니다.
고객이 결제 화면을 닫거나 은행 승인이 늦게 나와도 가맹점 서버는 최종 결과를 받습니다.
1) 엔드포인트 등록
대시보드의 개발자 > 웹훅에서 엔드포인트 추가를 눌러 주소를 등록합니다.
아래처럼 API로도 등록할 수 있습니다. 주소는 HTTPS여야 합니다.
복사
응답에 포함된 (로 시작)은 서명 검증에 쓰는 값입니다.
이 값도 환경 변수 에 저장하세요.
2) 받을 이벤트 선택
결제가 승인되어 완료됨. 주문을 "결제 완료"로 바꾸는 기준 이벤트입니다.
카드 거절, 한도 초과 등으로 결제가 실패함. 고객에게 재시도를 안내하세요.
결제가 취소됨. 고객이 checkout을 닫았거나 가맹점이 취소한 경우입니다.
3) 서명 검증 후 처리하기
누구나 이 주소로 요청을 보낼 수 있으므로, 모든 요청은 헤더로 진위를 확인해야 합니다.
헤더 형식은 이며, 서명은 을 HMAC-SHA256으로 계산한 값입니다.
JSON을 파싱하기 전의 원본 본문으로 계산해야 합니다.
복사
10초 안에 2xx로 응답하고 중복 이벤트를 막으세요
10초 안에 2xx 응답이 없으면 PayAPI는 전송 실패로 보고 이벤트를 다시 보냅니다.
같은 가 두 번 와도 주문이 두 번 결제 처리되지 않도록 DB에 처리 이력을 남기세요.
4) 재시도 정책
2xx가 아닌 응답이나 시간 초과가 발생하면 PayAPI는 다음 간격으로 최대 3일 동안 재시도합니다.
1분 → 5분 → 30분 → 2시간 → 이후 매 2시간 간격
대시보드 > 웹훅 > 전송 로그에서 개별 이벤트를 다시 보내거나 상태를 확인할 수 있습니다.
5) 로컬에서 테스트하기
개발 중인 로컬 서버는 외부에서 접근할 수 없습니다. 터널링 도구(예: ngrok, Cloudflare Tunnel)로
공개 HTTPS 주소를 만든 뒤, 그 주소를 웹훅 엔드포인트로 등록하세요.
테스트 키로 결제를 한 번 완료하면 요청이 도착하는지 전송 로그에서 확인할 수 있습니다.
연동 완료 확인
테스트 키()를 환경 변수로 저장했다
서버에서 결제를 생성하고 을 받았다
테스트 카드로 결제를 완료했다
웹훅 엔드포인트를 등록하고 서명을 검증한다
수신 시 주문 상태를 변경한다 (중복 처리 방지 포함)
