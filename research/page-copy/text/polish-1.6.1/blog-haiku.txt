# 우리 팀이 모노레포로 옮긴 이야기
> 웹 앱, 공통 UI 라이브러리, API 서버로 나뉘어 있던 저장소 세 개를 모노레포 하나로 합친 과정과 그때 생긴 문제를 정리했습니다.
## 시작은 작은 불편함이었습니다
웹 앱, 공통 UI 라이브러리, API 서버가 각각 다른 저장소에 있었습니다. 그래서 기능 하나를 바꾸려면 저장소 세 개에 PR을 따로 올려야 했습니다. 공통 라이브러리를 고칠 때마다 버전을 올리고 배포한 뒤 앱에서 다시 버전을 맞췄습니다.
어느 날 기능 하나를 배포하는 데 하루가 걸렸습니다. 코드 때문이 아니라 저장소 사이의 의존성을 맞추느라 걸린 시간이었습니다. 그 뒤 팀원 몇 명이 이 과정을 줄일 방법을 찾자고 제안했습니다.
## 모노레포를 고른 이유
저장소를 나눈 채 패키지 레지스트리로 연결하는 방법도 검토했지만, 다음 세 가지가 필요해서 모노레포를 골랐습니다.
- API 응답 형식과 클라이언트 코드를 한 PR에서 함께 수정
- 공통 라이브러리 수정을 앱에 바로 반영
- 프로젝트마다 따로 관리하던 린트, 테스트, CI 설정을 한 곳으로 통합
모노레포에도 비용이 있습니다. CI 실행 시간이 길어지고, 저장소가 커지고, 접근 권한을 세분화하기 어렵습니다. 그래서 옮기기 전에 이 비용을 감수할 만한지 먼저 확인했습니다.
## 옮기기 전에 한 일
1. **의존성 그래프 그리기**: 어떤 패키지가 어떤 패키지를 참조하는지 표로 정리했습니다. 예상하지 못한 순환 참조가 있어서 이것부터 끊었습니다.
2. **변경 빈도 조사**: 최근 6개월 커밋 기록에서 여러 저장소가 같은 시기에 함께 바뀐 경우가 많았습니다. 그래서 하나로 묶어도 실제 작업 흐름과 맞는다고 판단했습니다.
이 단계에서 팀 전체가 원칙 두 가지에 합의했습니다. 히스토리는 `git subtree`로 보존하고, 기존 저장소는 한 달 동안 읽기 전용으로 남겨 둡니다.
## 옮기는 과정
이전은 세 단계로 나눠 진행했습니다.
- **1단계**: 공통 라이브러리를 `packages/`로 옮기고, 기존 저장소에서 참조하도록 설정했습니다.
- **2단계**: API 서버와 웹 앱을 `apps/` 아래로 옮겼습니다. 이때 CI 파이프라인을 변경된 패키지만 빌드하도록 바꿨습니다.
- **3단계**: 기존 저장소를 정리하고, 문서와 배포 절차를 새 구조에 맞췄습니다.
단계마다 배포를 한 번씩 확인했습니다. 한 번에 모두 바꾸면 문제가 생겼을 때 원인을 찾기 어렵기 때문입니다.
## 겪은 문제들
**CI 시간이 늘어났습니다.** 처음에는 변경이 생길 때마다 모든 테스트가 돌았습니다. 변경 영향 범위를 계산해 바뀐 패키지와 그 패키지에 의존하는 패키지만 테스트하도록 바꾸자 평균 빌드 시간이 크게 줄었습니다. 팀 내부 측정 기준이 달라 구체적인 수치는 생략합니다.
**버전 관리 방식을 정해야 했습니다.** 패키지마다 버전을 따로 올릴지, 저장소 전체를 하나의 버전으로 볼지를 두고 논의가 길어졌습니다. 결국 내부 패키지는 버전 없이 워크스페이스 링크로 참조하고, 외부에 배포하는 패키지만 버전을 따로 관리하기로 했습니다.
**코드 소유권이 흐려졌습니다.** 한 저장소에 여러 팀의 코드가 섞이면서 리뷰어를 정하기 어려워졌습니다. `CODEOWNERS` 파일에 디렉터리별 담당자를 적어 해결했습니다.
**옛 습관이 남았습니다.** 공통 라이브러리를 복사해서 쓰려는 팀원이 여전히 있었습니다. 이 문제는 도구로 막기보다 설명과 코드 리뷰로 풀었습니다.
## 얻은 것
가장 크게 바뀐 것은 작업 흐름입니다.
- API와 클라이언트를 한 PR에서 함께 수정
- 공통 코드 수정이 바로 반영되어 버전 동기화 작업이 사라짐
- 린트와 테스트 설정을 한 곳에서 관리
- 새로 합류한 팀원이 저장소 하나에서 전체 구조를 파악
## 아쉬운 점
저장소가 커지면서 로컬 클론과 IDE 인덱싱이 느려졌습니다. 빌드 도구 설정을 이해하는 사람도 몇 명뿐입니다. 두 문제 모두 아직 개선하는 중입니다.
## 마치며
우리가 원한 것은 변경을 빠르고 안전하게 배포하는 일이었고, 모노레포는 그 수단으로 골랐습니다. 돌아보면 도구를 바꾸기 전에 저장소 사이의 의존성과 변경 패턴을 먼저 조사한 단계가 가장 중요했습니다.
