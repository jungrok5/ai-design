1API 키 발급
모든 API 요청은 시크릿 키로 인증합니다. 처음에는 실제 돈이 오가지 않는 테스트 키로 시작하세요.
대시보드에 로그인한 뒤 개발자 → API 키 메뉴로 이동합니다.
상단 토글이 테스트 모드인지 확인합니다.
새 키 만들기를 누르고 이름(예: )을 입력합니다.
발급된 공개 키와 시크릿 키를 복사해 둡니다.

3웹훅 설정
가상계좌 입금, 취소, 비동기 승인처럼 API 요청 뒤에 일어나는 일은 PayAPI가 웹훅으로 보냅니다. 주문 상태는 API 응답이 아니라 웹훅 이벤트를 받았을 때 바꾸세요.
엔드포인트 등록
개발자 → 웹훅 → 엔드포인트 추가를 엽니다.
HTTPS URL을 입력합니다. (예: )
수신할 이벤트를 고릅니다: , ,
생성된 서명 비밀값을 에 저장합니다.
팁
로컬에서 개발 중이라면 같은 터널링 도구로 공개 URL을 만들어 등록하세요.
서명 검증하고 이벤트 처리하기
모든 웹훅 요청에는 형식의 헤더가 붙습니다. 을 서명 비밀값으로 HMAC-SHA256 계산해 과 같은지 비교합니다. 이때 본문은 JSON으로 파싱하기 전의 원본(raw body)이어야 합니다.

동작 확인과 재시도
대시보드의 웹훅 → 테스트 이벤트 보내기를 누르면 이벤트가 바로 전송됩니다.
2xx가 아닌 응답을 받거나 10초 안에 응답이 없으면 실패로 처리하고, 최대 24시간 동안 지수 백오프로 다시 보냅니다.
같은 이벤트가 두 번 올 수 있으므로 처리한 를 저장해 두고 중복은 건너뛰세요.
라이브 키로 바꾸기 전 확인할 항목
테스트 모드에서 결제와 웹훅이 동작하면 아래 항목을 확인한 뒤 라이브 키로 교체하세요.
대시보드에서 사업자 심사를 완료하고 라이브 모드를 활성화했다
환경 변수의 키를 로 교체했고 저장소에 키가 남아 있지 않다
웹훅 엔드포인트를 라이브 모드에서 다시 등록하고 새 서명 비밀값을 적용했다
웹훅에서 서명·타임스탬프 검증과 중복 처리를 한다
결제 요청마다 를 사용한다
