개발 환경 세팅

macOS 기준입니다. 순서대로 하면 한두 시간이면 끝납니다. 파란 번호는 다른 사람이 처리해 줘야 하는 단계라 월요일 오전에 먼저 요청해 두세요.

  1. 권한 요청

    #it-support에 GitHub 조직, VPN, 스테이징 DB 읽기 권한을 요청합니다. 보통 반나절 걸립니다.

    IT 담당

  2. 기본 도구 설치

    Homebrew를 설치한 뒤, 저장소의 Brewfile로 나머지를 한 번에 설치합니다. 저장소를 받기 전이라면 먼저 git만 설치하세요.

    /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)" brew install git

  3. SSH 키 만들고 GitHub에 등록

    출력된 공개 키를 GitHub > Settings > SSH and GPG keys에 붙여 넣습니다.

    ssh-keygen -t ed25519 -C "회사메일@example.com" pbcopy < ~/.ssh/id_ed25519.pub # 공개 키를 클립보드로

  4. 저장소 받기와 의존성 설치

    make setup이 Brewfile, 언어 런타임, 패키지, 로컬 DB 컨테이너를 차례로 준비합니다.

    git clone git@github.com:our-org/app.git cd app make setup

  5. 환경 변수 파일 만들기

    예시 파일을 복사한 뒤, 비어 있는 값은 사내 비밀번호 관리자의 dev-local 항목에서 채웁니다.

    cp .env.example .env.local

    .env.local은 커밋하지 마세요. .gitignore에 들어 있지만, git add -A 전에 한 번 더 확인하는 습관을 들이세요. 실수로 올렸다면 지우지 말고 바로 #dev-help에 알려 주세요. 키를 교체해야 합니다.

  6. 앱 띄우고 테스트 돌리기

    http://localhost:3000이 열리고 테스트가 모두 통과하면 세팅은 끝입니다.

    make dev # 개발 서버 make test # 다른 터미널에서

  7. 버디에게 확인받기

    화면 공유로 로컬 앱과 테스트 결과를 보여 주세요. 세팅 중 막힌 곳은 이 문서에 바로 반영합니다.

코드 리뷰 규칙

main 브랜치에는 승인 1개 이상과 CI 통과가 있어야 머지됩니다. 리뷰는 코드를 보는 일이지 사람을 평가하는 일이 아닙니다. 신입도 첫 주부터 리뷰어로 참여합니다.

PR을 올릴 때

  • 변경은 400줄 이하로 나눕니다. 넘으면 리뷰 품질이 떨어집니다.
  • 설명에 왜 바꿨는지, 어떻게 확인했는지를 적습니다.
  • UI 변경은 전후 스크린샷을 붙입니다.
  • 올리기 전에 직접 diff를 한 번 읽습니다.
  • 받은 댓글에는 모두 답합니다. 반영했으면 커밋 링크, 안 했으면 이유를 적습니다.

리뷰할 때

  • 요청받은 PR은 영업일 하루 안에 첫 리뷰를 남깁니다.
  • 댓글 앞에 아래 말머리를 붙여 무게를 알립니다.
  • 문제만 짚지 말고 대안을 함께 적습니다.
  • 포맷, 린트처럼 도구가 잡을 수 있는 건 지적하지 않습니다.
  • 잘한 점이 보이면 그것도 적습니다.

커밋 메시지

첫 줄은 무엇을 했는지 50자 안쪽으로, 본문은 이유를 적습니다. 머지는 squash merge라 PR 제목이 그대로 main에 남습니다.

feat(auth): 비밀번호 재설정 메일에 만료 시간 표시

사용자가 링크 만료를 몰라 고객 문의가 늘어서 추가함.
Refs: #1234
이 문서가 틀렸거나 빠진 게 있으면 직접 고쳐 주세요. 신입이 올리는 문서 수정 PR이 가장 정확합니다.
