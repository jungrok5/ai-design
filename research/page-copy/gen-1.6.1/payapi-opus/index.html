빠른 시작

테스트 키를 발급받고, 1,000원짜리 테스트 결제를 한 번 보내고, 결제 완료를 웹훅으로 받는 데까지 따라 합니다. 실제 돈은 움직이지 않습니다.

필요한 것
Tolpay 계정(사업자 등록 없이 테스트 모드 사용 가능), 터미널, Node.js 18 이상
걸리는 시간
15분 안팎
API 주소
https://api.tolpay.dev/v1

1단계

API 키 발급

모든 요청은 비밀 키로 인증합니다. 가입하면 테스트 키가 바로 만들어지고, 라이브 키는 사업자 심사가 끝난 뒤에 열립니다.

  1. 대시보드에 로그인

    오른쪽 위 모드 스위치가 테스트인지 확인합니다.

  2. 개발 › API 키 메뉴로 이동

    공개 키와 비밀 키가 한 쌍으로 보입니다.

  3. 비밀 키 보기를 누르고 복사

    비밀 키는 처음 한 번만 전체가 표시됩니다. 놓쳤다면 새로 발급하세요.

    직접
키형식쓰는 곳
공개 키pk_test_…브라우저와 앱. 결제창을 띄울 때만 씁니다.
비밀 키sk_test_…서버에서만. 결제 생성, 취소, 조회 등 모든 API 요청에 씁니다.

키는 코드에 직접 적지 말고 환경 변수에 넣어 둡니다. 아래 예제는 모두 TOLPAY_SECRET_KEY를 읽습니다.

export TOLPAY_SECRET_KEY=sk_test_EXAMPLE
비밀 키가 노출됐다면 바로 폐기하세요. 깃 저장소, 프런트엔드 번들, 스크린숏에 비밀 키가 들어갔다면 대시보드에서 키 재발급을 누릅니다. 기존 키는 즉시 막힙니다.

2단계

첫 결제 요청

결제는 POST /v1/payments 한 번으로 만듭니다. 테스트 모드에서는 카드 대신 테스트 결제수단 pm_card_success를 넣으면 결제창 없이 바로 승인됩니다.

cURL터미널에 그대로 붙여 넣으세요
curl https://api.tolpay.dev/v1/payments \
  -H "Authorization: Bearer $TOLPAY_SECRET_KEY" \
  -H "Idempotency-Key: order-1001" \
  -H "Content-Type: application/json" \
  -d '{
    "amount": 1000,
    "currency": "KRW",
    "order_id": "order-1001",
    "order_name": "아메리카노 1잔",
    "payment_method": "pm_card_success"
  }'
같은 요청을 Node.js로 보내기 
// pay.mjs — node pay.mjs 로 실행
const res = await fetch("https://api.tolpay.dev/v1/payments", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${process.env.TOLPAY_SECRET_KEY}`,
    "Idempotency-Key": "order-1001",
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    amount: 1000,
    currency: "KRW",
    order_id: "order-1001",
    order_name: "아메리카노 1잔",
    payment_method: "pm_card_success",
  }),
});
console.log(res.status, await res.json());

요청 필드

필드필수설명
amount예결제 금액. 원 단위 정수이며 100 이상입니다.
currency예지금은 KRW만 받습니다.
order_id예내 서비스의 주문 번호. 같은 값으로 두 번 결제되지 않습니다.
order_name예결제창과 영수증에 보이는 상품명. 최대 100자.
payment_method아니요비워 두면 응답의 checkout_url로 결제창을 엽니다.
응답 예시 · 201 Created
{
  "id": "pay_8XkQ2mVn4tR7",
  "object": "payment",
  "status": "succeeded",
  "amount": 1000,
  "currency": "KRW",
  "order_id": "order-1001",
  "order_name": "아메리카노 1잔",
  "method": { "type": "card", "issuer": "TEST", "last4": "4242" },
  "approved_at": "2026-10-22T14:03:51+09:00",
  "livemode": false
}

✓ succeeded 가 보이면 첫 결제가 끝났습니다. 대시보드 › 결제 내역에서도 같은 id를 찾을 수 있습니다.

다른 결과도 시험하기

테스트 결제수단을 바꾸면 실패와 추가 인증 흐름을 미리 확인할 수 있습니다.

payment_method결과
pm_card_success✓ succeeded 즉시 승인
pm_card_declined✕ failed 잔액 부족 (card_declined)
pm_card_3ds! requires_action 본인 인증 후 승인
Idempotency-Key는 꼭 넣으세요. 네트워크 오류로 같은 요청을 다시 보내도 결제는 한 번만 일어납니다. 키는 24시간 동안 유지되며, 주문 번호를 그대로 써도 됩니다.

3단계

웹훅 설정

API 응답만 믿으면 결제창을 닫거나 3D 인증이 늦게 끝난 결제를 놓칩니다. 결제 상태가 바뀔 때마다 Tolpay가 내 서버로 보내는 웹훅을 받아 주문을 확정하세요.

웹훅 받는 서버 만들기

서명은 Tolpay-Signature 헤더에 t=타임스탬프,v1=서명 형태로 옵니다. 타임스탬프.원본본문을 웹훅 시크릿으로 HMAC-SHA256 한 값과 비교합니다. 본문을 JSON으로 먼저 파싱하면 서명이 맞지 않으니 원본 그대로 읽으세요.

Node.js · Expressserver.mjs
import express from "express";
import crypto from "node:crypto";

const app = express();
const secret = process.env.TOLPAY_WEBHOOK_SECRET; // whsec_로 시작

app.post("/webhooks/tolpay", express.raw({ type: "application/json" }), (req, res) => {
  const header = req.get("Tolpay-Signature") ?? "";
  const { t, v1 } = Object.fromEntries(header.split(",").map((p) => p.split("=")));
  const expected = crypto.createHmac("sha256", secret).update(`${t}.${req.body}`).digest("hex");

  const valid = v1 && v1.length === expected.length &&
    crypto.timingSafeEqual(Buffer.from(v1), Buffer.from(expected));
  const fresh = Math.abs(Date.now() / 1000 - Number(t)) < 300; // 5분 넘은 요청은 거절
  if (!valid || !fresh) return res.sendStatus(400);

  const event = JSON.parse(req.body);
  res.sendStatus(200); // 먼저 응답하고, 무거운 처리는 그 뒤에

  if (event.type === "payment.succeeded") {
    console.log("주문 확정:", event.data.order_id);
  }
});

app.listen(3000);

로컬에서 바로 받아 보기

Tolpay CLI가 테스트 웹훅을 내 컴퓨터로 전달해 줍니다. 공개 주소나 터널을 따로 만들 필요가 없습니다.

npm install -g @tolpay/cli
tolpay login
tolpay listen --forward-to localhost:3000/webhooks/tolpay

listen을 실행하면 웹훅 시크릿이 출력됩니다. 이 값을 TOLPAY_WEBHOOK_SECRET에 넣고 서버를 띄운 뒤, 2단계의 결제 요청을 한 번 더 보내 보세요. order_id와 Idempotency-Key는 새 값으로 바꿔야 합니다.

$ tolpay listen --forward-to localhost:3000/webhooks/tolpay
웹훅 시크릿: whsec_EXAMPLE (이 세션 동안 유효)

    HTTPS 주소만 등록할 수 있습니다. 예: https://shop.example.com/webhooks/tolpay

  2. 받을 이벤트 선택

    처음에는 아래 세 개면 충분합니다.

  3. 엔드포인트별 웹훅 시크릿을 서버 환경 변수에 저장

    CLI에서 쓴 시크릿과 다른 값입니다.

    직접

  4. 테스트 이벤트 보내기

    대시보드의 테스트 전송으로 응답 코드를 확인합니다.

이벤트보내는 때
payment.succeeded결제가 승인됐을 때. 주문을 확정하세요.
payment.failed승인이 거절됐거나 고객이 결제를 포기했을 때
refund.succeeded전체 또는 부분 환불이 끝났을 때
응답이 실패하면 언제 다시 보내나요?

10초 안에 2xx를 받지 못하면 1분, 10분, 1시간, 6시간, 24시간 뒤에 다시 보냅니다. 다섯 번 모두 실패하면 대시보드에 알림이 뜨고, 웹훅 기록에서 직접 재전송할 수 있습니다.

같은 이벤트가 두 번 올 수 있으니 event.id를 저장해 두고 이미 처리한 이벤트는 건너뛰세요.
