빠른 시작

테스트 모드에서 50,000원짜리 결제를 하나 만들고, 결제가 끝나면 웹훅으로 결과를 받습니다. 테스트 모드에서는 카드에 실제 청구가 일어나지 않습니다.

  1. API 키 발급

    대시보드에서 테스트 시크릿 키를 받아 서버 환경 변수에 넣습니다.

    대시보드

  2. 첫 결제 요청

    POST /v1/payments로 결제를 만들고 받은 결제 페이지에서 테스트 카드로 결제합니다.

    API

  3. 웹훅 설정

    결제 결과를 받을 URL을 등록하고 요청의 서명을 검증합니다.

    API · 대시보드

준비물

  • Paylane 계정 (가입하면 테스트 모드가 바로 열립니다)
  • HTTPS 요청을 보낼 수 있는 서버 환경. 예제는 curl, Node.js 18 이상, Python 3.9 이상 기준입니다.
1단계

API 키 발급

대시보드에서 아래 순서로 이동한 뒤 테스트 키 발급을 누릅니다.

  1. 대시보드
  2. 개발자
  3. API 키
  4. 테스트 키 발급

키는 모드별로 따로 발급됩니다. 접두사를 보면 어떤 키인지 알 수 있고, 테스트 키로 만든 결제는 테스트 데이터에만 보입니다.

키접두사쓰는 곳청구
테스트 시크릿 키sk_test_개발·스테이징 서버청구 없음
라이브 시크릿 키sk_live_운영 서버실제 청구
웹훅 서명 시크릿whsec_웹훅 요청 검증 (3단계)—
시크릿 키는 서버에서만 사용합니다. 브라우저 코드, 앱 번들, 저장소에 들어가면 누구나 내 계정으로 결제와 환불을 요청할 수 있습니다. 키가 노출되면 대시보드의 같은 화면에서 키 교체를 눌러 기존 키를 즉시 폐기합니다.

발급한 키를 환경 변수에 넣습니다. 이후 예제는 모두 이 변수를 읽습니다.

export PAYLANE_SECRET_KEY=sk_test_51Hx...
2단계

첫 결제 요청

서버에서 결제를 만들면 응답에 결제 페이지 주소 checkout_url이 옵니다. 고객을 이 주소로 보내면 카드 입력과 본인 인증은 Paylane 결제 페이지에서 진행됩니다.

요청 본문

amountinteger필수
결제 금액. KRW는 원 단위 정수입니다. 최소 100.
currencystring필수
통화 코드(ISO 4217). 지금은 KRW만 받습니다.
order_idstring필수
내 시스템의 주문 번호. 64자 이내. 웹훅에도 그대로 실려 옵니다.
success_urlstring필수
결제 완료 뒤 고객이 돌아올 주소.
fail_urlstring필수
결제 실패나 취소 뒤 고객이 돌아올 주소.
descriptionstring
결제 페이지와 영수증에 보이는 상품명.

Idempotency-Key 헤더에 요청마다 고유한 값을 넣으면, 네트워크 오류로 같은 요청을 다시 보내도 결제가 한 번만 만들어집니다. 같은 키는 24시간 동안 같은 응답을 돌려줍니다.

curl https://api.paylane.example/v1/payments \
  -H "Authorization: Bearer $PAYLANE_SECRET_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: $(uuidgen)" \
  -d '{
    "amount": 50000,
    "currency": "KRW",
    "order_id": "order_1024",
    "description": "기계식 키보드",
    "success_url": "https://shop.example/orders/1024/done",
    "fail_url": "https://shop.example/orders/1024/fail"
  }'
// Node.js 18 이상: fetch와 crypto.randomUUID가 내장돼 있습니다.
const res = await fetch("https://api.paylane.example/v1/payments", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${process.env.PAYLANE_SECRET_KEY}`,
    "Content-Type": "application/json",
    "Idempotency-Key": crypto.randomUUID(),
  },
  body: JSON.stringify({
    amount: 50000,
    currency: "KRW",
    order_id: "order_1024",
    description: "기계식 키보드",
    success_url: "https://shop.example/orders/1024/done",
    fail_url: "https://shop.example/orders/1024/fail",
  }),
});

const payment = await res.json();
if (!res.ok) throw new Error(payment.error.code);
// 고객을 payment.checkout_url로 리다이렉트합니다.
import os, uuid

res = requests.post(

res.raise_for_status()
payment = res.json()

결제 상태

만든 직후의 결제는 pending입니다. 결제 페이지는 30분 뒤 만료됩니다.

pending
결제 생성됨. 고객이 아직 결제 페이지에서 결제하지 않았습니다.
succeeded
승인 완료. 이 상태가 되면 상품을 보내거나 서비스를 열어도 됩니다.
failed
카드사 거절, 인증 실패 등으로 승인되지 않았습니다. failure_code에 이유가 있습니다.
canceled
고객이 결제 페이지에서 취소했거나, 서버에서 취소 API를 호출했습니다.
expired
expires_at까지 결제가 끝나지 않았습니다.

자주 나는 오류

오류 응답은 {"error": {"code", "message"}} 형식입니다.

HTTP · code원인과 조치
401

409

3단계

웹훅 설정

주문 상태는 웹훅을 받은 뒤 바꿉니다. 고객이 success_url에 도착했다는 사실은 결제 완료의 근거가 되지 않습니다. 고객이 결제 직후 창을 닫으면 5번은 일어나지 않고, URL은 누구나 직접 열 수 있습니다.

엔드포인트 등록

대시보드 개발자 › 웹훅 › 엔드포인트 추가에서 HTTPS 주소(예: https://shop.example/webhooks/paylane)를 입력하고 받을 이벤트를 고릅니다. 저장하면 이 엔드포인트 전용 서명 시크릿 whsec_…이 나옵니다. 1단계의 키와 같은 방식으로 환경 변수에 넣습니다.

export PAYLANE_WEBHOOK_SECRET=whsec_9tQ...

서명 검증

Paylane은 모든 웹훅 요청에 Paylane-Signature: t=1792649400,v1=5f3a… 헤더를 붙입니다. v1은 t 값, 마침표, 요청 본문 원문을 이어 붙인 문자열의 HMAC-SHA256(키: 서명 시크릿)입니다. 본문을 JSON으로 파싱하기 전의 바이트로 계산해야 값이 맞습니다.

// Express 예제. express.raw로 본문을 원문 그대로 받습니다.
import crypto from "node:crypto";
import express from "express";

const app = express();
const secret = process.env.PAYLANE_WEBHOOK_SECRET;

app.post("/webhooks/paylane", express.raw({ type: "application/json" }), (req, res) => {
  const header = req.get("Paylane-Signature") ?? "";
  const { t, v1 } = Object.fromEntries(header.split(",").map((p) => p.split("=")));

  const expected = crypto.createHmac("sha256", secret)
    .update(`${t}.`).update(req.body).digest();
  const given = Buffer.from(v1 ?? "", "hex");
  const fresh = Math.abs(Date.now() / 1000 - Number(t)) <= 300; // 5분 넘은 요청은 거부

  if (given.length !== expected.length || !crypto.timingSafeEqual(given, expected) || !fresh) {
    return res.sendStatus(400);
  }

  const event = JSON.parse(req.body);
  // 같은 이벤트가 두 번 이상 올 수 있습니다. event.id를 저장해 두고 이미 처리한 ID면 건너뜁니다.
  if (event.type === "payment.succeeded") {
    markOrderPaid(event.data.order_id, event.data.id); // 내 주문 처리 함수
  }
  res.sendStatus(200);
});

이벤트 종류

이벤트보내는 시점보통 하는 처리
payment.succeeded승인 완료주문을 결제 완료로 바꾸고 배송·발급 시작
payment.failed승인 거절, 인증 실패주문을 결제 실패로 표시
payment.canceled결제 페이지 취소, 취소 API 호출재고 복원
payment.expiredexpires_at 경과미결제 주문 정리
refund.succeeded환불 완료주문을 환불됨으로 바꾸고 고객에게 안내

응답과 재시도

엔드포인트가 10초 안에 2xx로 응답하지 않으면 전송 실패로 보고 아래 간격으로 다시 보냅니다. 처리에 시간이 걸리는 작업은 큐에 넣고 먼저 200을 돌려줍니다.

  1. 1회1분 뒤
  2. 2회10분 뒤
  3. 3회1시간 뒤
  4. 4회6시간 뒤
  5. 5회24시간 뒤

5회 모두 실패하면 대시보드 웹훅 › 전송 기록에 실패로 남고, 같은 화면에서 직접 다시 보낼 수 있습니다. 로컬 개발 중에는 테스트 이벤트 보내기로 등록한 엔드포인트에 샘플 이벤트를 보내 검증 코드를 확인합니다.

라이브 모드로 전환

사업자 심사가 끝나면 대시보드에서 라이브 키를 발급할 수 있습니다. 코드는 그대로 두고 아래 값만 바꿉니다.

  • 운영 서버의 PAYLANE_SECRET_KEY를 sk_live_ 키로 교체
  • 라이브 모드에서 웹훅 엔드포인트를 다시 등록하고, 새로 나온 whsec_ 시크릿으로 PAYLANE_WEBHOOK_SECRET 교체 (테스트 모드 엔드포인트는 라이브 이벤트를 받지 않습니다)
  • 웹훅 처리 코드에서 event.livemode가 운영 환경과 맞는지 확인
