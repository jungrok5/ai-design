# 우리 팀이 모노레포로 옮긴 이야기

[팀 이름]은 [날짜]에 저장소 [숫자 필요]개를 모노레포(monorepo) 하나로 합쳤습니다. 이 글은 옮기기 전에 겪던 문제, 도구를 고른 기준, 이전 순서, 옮긴 뒤 달라진 점과 아직 남은 문제를 정리합니다.

## 옮기기 전: 저장소마다 따로 움직이던 코드

당시 서비스는 웹 프런트엔드, API 서버, 공용 라이브러리가 각각 다른 저장소에 있었습니다. 공용 라이브러리를 한 줄 고치면 다음 순서를 거쳐야 했습니다.

1. 라이브러리 저장소에서 PR을 올리고 병합합니다.
2. 새 버전을 패키지 레지스트리에 배포합니다.
3. 라이브러리를 쓰는 저장소마다 버전을 올리는 PR을 따로 올립니다.
4. 각 저장소의 CI가 통과하면 병합하고 배포합니다.

이 과정에서 반복해서 생긴 문제는 다음과 같습니다.

| 문제 | 실제로 일어난 일 |
| --- | --- |
| 버전 불일치 | 저장소마다 공용 라이브러리 버전이 달라, 같은 버그를 [숫자 필요]번 고쳤습니다. |
| 변경 한 건에 PR 여러 개 | 라이브러리 수정 하나에 PR이 평균 [숫자 필요]개 필요했습니다. |
| 설정 중복 | ESLint, TypeScript, CI 설정을 저장소마다 복사해 따로 관리했습니다. |
| 리뷰 범위 단절 | API 변경과 그 API를 쓰는 화면 변경을 한 PR에서 볼 수 없었습니다. |

## 이전 순서

한 번에 모든 저장소를 옮기지 않고, 의존 관계가 적은 저장소부터 하나씩 옮겼습니다.

1. 빈 모노레포를 만들고 `apps/`, `packages/` 디렉터리 구조를 정합니다.
2. 공용 라이브러리를 `packages/`로 옮깁니다. `git subtree`로 옮겨 커밋 기록을 유지했습니다.
3. 프런트엔드와 API 서버를 `apps/`로 옮기고, 레지스트리에서 받던 공용 라이브러리를 워크스페이스 의존성으로 바꿉니다.
4. 저장소마다 있던 CI 설정을 하나로 합치고, 바뀐 패키지만 실행하도록 설정합니다.
5. 기존 저장소를 읽기 전용으로 바꾸고 README에 새 저장소 위치를 적습니다.

커밋 기록을 유지하며 저장소를 옮길 때 쓴 명령은 다음과 같습니다.

```bash
git subtree add --prefix=packages/shared <기존-저장소-URL> main
```

전체 이전에는 [숫자 필요]주가 걸렸고, 그동안 기능 개발은 [멈췄습니다 / 병행했습니다 — 실제 상황으로 수정].

## 옮긴 뒤 달라진 점

공용 라이브러리 수정과 그 수정을 쓰는 코드 변경이 PR 하나에 들어갑니다. 리뷰어는 API 응답 형식이 바뀐 이유와 화면이 그 형식을 어떻게 쓰는지 한 화면에서 봅니다. 라이브러리 버전을 올리는 PR은 더 이상 만들지 않습니다.

| 지표 | 이전 | 이후 | 측정 방법 |
| --- | --- | --- | --- |
| 공용 라이브러리 수정 한 건당 PR 수 | [숫자 필요] | 1 | [측정 기간과 방법] |
| CI 평균 실행 시간 | [숫자 필요]분 | [숫자 필요]분 | [측정 기간과 방법] |
| 관리하는 설정 파일 수 | [숫자 필요] | [숫자 필요] | 저장소 내 파일 수 |

## 아직 남은 문제

CI 시간은 캐시가 적중할 때 줄었지만, 공용 라이브러리를 고치면 모든 앱을 다시 빌드하므로 그때는 [숫자 필요]분이 걸립니다. 저장소 클론 크기도 [숫자 필요] MB로 커져, 새로 합류한 사람이 처음 설치할 때 시간이 더 듭니다. 코드 소유권은 `CODEOWNERS` 파일로 디렉터리마다 지정했지만, 여러 팀이 함께 쓰는 `packages/` 아래 코드는 리뷰 담당자를 아직 정하지 못했습니다.
