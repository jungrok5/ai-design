개발 환경 세팅

macOS 기준입니다. 순서대로 하면 1시간 정도 걸립니다. 명령은 오른쪽 복사 버튼으로 그대로 붙여 넣으세요.

  1. Homebrew와 기본 도구 설치

    Git, Node 버전 관리자, Docker를 한 번에 설치합니다.

    # Homebrew가 없을 때만
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
brew install git fnm gh
brew install --cask docker visual-studio-code

  2. Git 사용자 정보 설정

    커밋 작성자로 회사 메일을 씁니다. 개인 메일로 커밋하면 CI에서 막힙니다.

    git config --global user.name "홍길동"
git config --global user.email "gildong.hong@example.com"
git config --global pull.rebase true

  3. SSH 키 만들고 GitHub에 등록

    공개키를 GitHub 설정의 SSH keys에 붙여 넣은 뒤, 조직 SSO 승인(Configure SSO)까지 눌러야 사내 저장소에 접근됩니다.

    ssh-keygen -t ed25519 -C "gildong.hong@example.com"
pbcopy < ~/.ssh/id_ed25519.pub   # 공개키가 클립보드에 복사됩니다
    직접 확인

  4. 저장소 클론, 런타임 맞추기

    Node 버전은 저장소의 .nvmrc를 따릅니다.

    git clone git@github.com:example-corp/main-service.git
cd main-service
fnm use --install-if-missing
npm ci

  5. 환경 변수 파일 만들기

    예시 파일을 복사한 다음, 비어 있는 값은 사내 비밀번호 관리자의 “dev-local” 항목에서 채웁니다. .env는 절대 커밋하지 않습니다.

    cp .env.example .env

  6. 로컬 실행과 테스트

    DB와 Redis는 Docker로 띄웁니다. 테스트가 모두 통과하고 브라우저에서 localhost:3000이 열리면 세팅이 완료된 것입니다.

    docker compose up -d
npm run db:migrate
npm test
npm run dev

코드 리뷰 규칙

리뷰는 코드를 보는 일이지 사람을 평가하는 일이 아닙니다. 아래 다섯 가지만 지키면 됩니다.

  • PR은 작게, 400줄 이하로넘으면 나눕니다. 테스트와 자동 생성 파일은 줄 수에서 빼고 셉니다.
  • 승인 1명 이상, CI 통과 후 머지머지는 PR 작성자가 직접 합니다. 리뷰어가 대신 머지하지 않습니다.
  • 리뷰 요청을 받으면 영업일 기준 하루 안에 응답바로 못 보면 언제 볼 수 있는지라도 코멘트로 남깁니다.
  • 코멘트 앞에 말머리를 붙여 무게를 알리기꼭 고쳐야 하는 것과 취향을 구분해야 작성자가 덜 헤맵니다. 아래 표를 보세요.
  • 설명 없이 “별로예요”는 금지왜 문제인지, 어떻게 바꾸면 좋을지 함께 씁니다. 칭찬도 구체적으로 합니다.

코멘트 말머리

말머리뜻머지 전 반영
[must]버그, 보안, 데이터 손실 위험필수
[suggest]더 나은 방법 제안작성자 판단
[question]이해를 위한 질문답변만 하면 됨
[nit]사소한 스타일, 오타선택
[praise]잘된 부분없음

이렇게 씁니다

[must]여기서 userId가 없으면 전체 주문을 조회합니다.

빈 값일 때 400을 돌려주고, 그 경우 테스트를 하나 추가해 주세요.

[nit]변수명 tmp 대신 pendingOrders면 읽기 쉬울 것 같아요.

✕ 피할 것: “이건 좀 아닌 것 같은데요.” — 무엇이 왜 문제인지 없어서 작성자가 고칠 수 없습니다.
