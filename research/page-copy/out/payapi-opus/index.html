빠른 시작

API 키를 발급받고, 테스트 결제를 한 건 만든 뒤, 결제 결과를 웹훅으로 받아보세요. 처음부터 끝까지 15분 정도 걸립니다.

01API 키 발급대시보드에서 테스트 키 받기 02첫 결제 요청서버에서 결제 생성하고 승인 03웹훅 설정결제 결과를 실시간으로 받기
기본 URL https://api.paygrid.dev/v1 형식 JSON 인증 Bearer 토큰

API 키 발급

약 2분
  1. Paygrid 대시보드에 로그인합니다. 계정이 없다면 이메일로 가입하세요. 가입 즉시 테스트 모드를 쓸 수 있습니다.
  2. 왼쪽 메뉴에서 개발자 → API 키로 이동합니다.
  3. 테스트 키 만들기를 누르고, 화면에 한 번만 표시되는 시크릿 키를 복사해 둡니다.

키는 두 종류이며, 접두사로 환경과 용도를 구분합니다.

키접두사사용 위치
시크릿 키sk_test_ / sk_live_서버에서만 사용. 모든 API 호출 가능
퍼블리셔블 키pk_test_ / pk_live_브라우저·앱에서 결제창 띄울 때 사용
시크릿 키는 서버에만 두세요 프런트엔드 코드나 Git 저장소에 시크릿 키를 넣지 마세요. 노출됐다면 대시보드에서 바로 키를 폐기하고 새로 발급하세요.

키를 환경 변수로 저장한 뒤, 잘 동작하는지 확인합니다.

export PAYGRID_SECRET_KEY="sk_test_51Hx9..."

curl https://api.paygrid.dev/v1/account \
  -H "Authorization: Bearer $PAYGRID_SECRET_KEY"
// npm install @paygrid/node
import Paygrid from "@paygrid/node";

const paygrid = new Paygrid(process.env.PAYGRID_SECRET_KEY);
const account = await paygrid.account.retrieve();
console.log(account.mode); // "test"
# pip install paygrid
import os, paygrid

paygrid.api_key = os.environ["PAYGRID_SECRET_KEY"]
account = paygrid.Account.retrieve()
print(account.mode)  # "test"
응답에 "mode": "test"가 보이면 준비 완료 테스트 모드에서는 실제 돈이 오가지 않습니다. 마음껏 실험하세요.

첫 결제 요청

약 5분

결제는 두 단계로 이뤄집니다. 서버에서 결제를 생성하고, 고객이 결제 수단을 입력하면 승인합니다. 여기서는 테스트 카드로 두 단계를 한 번에 진행합니다.

결제 생성

POST /v1/payments로 결제를 만듭니다. 금액은 원 단위 정수로 보냅니다.

curl https://api.paygrid.dev/v1/payments \
  -H "Authorization: Bearer $PAYGRID_SECRET_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: order_1024_try1" \
  -d '{
    "amount": 15000,
    "currency": "KRW",
    "order_id": "order_1024",
    "order_name": "프리미엄 원두 200g",
    "payment_method": "card_test_visa_success",
    "confirm": true
  }'
const payment = await paygrid.payments.create(
  {
    amount: 15000,
    currency: "KRW",
    order_id: "order_1024",
    order_name: "프리미엄 원두 200g",
    payment_method: "card_test_visa_success",
    confirm: true,
  },
  { idempotencyKey: "order_1024_try1" }
);

console.log(payment.id, payment.status); // pay_8Kd2... "succeeded"
payment = paygrid.Payment.create(
    amount=15000,
    currency="KRW",
    order_id="order_1024",
    order_name="프리미엄 원두 200g",
    payment_method="card_test_visa_success",
    confirm=True,
    idempotency_key="order_1024_try1",
)

print(payment.id, payment.status)  # pay_8Kd2... "succeeded"
파라미터타입설명
amountinteger필수결제 금액. KRW는 원 단위(소수점 없음)
currencystring필수ISO 4217 통화 코드. 예: KRW, USD
order_idstring필수가맹점 주문 번호. 6~64자, 가맹점 안에서 고유해야 함
order_namestring선택결제창과 영수증에 표시될 상품명
payment_methodstring선택결제 수단 ID. 생략하면 결제창 URL이 반환됨
confirmboolean선택true면 생성과 동시에 승인 시도. 기본값 false

테스트 결제 수단

아래 값을 payment_method에 넣으면 원하는 결과를 재현할 수 있습니다.

결제 수단 ID결과
card_test_visa_success승인 성공 (succeeded)
card_test_insufficient_funds잔액 부족으로 실패 (failed)
card_test_3ds_required추가 인증 필요 (requires_action)
멱등성 키로 중복 결제를 막으세요 네트워크 오류로 재시도할 때 같은 Idempotency-Key를 보내면, 결제가 두 번 생성되지 않고 첫 번째 결과가 그대로 반환됩니다. 키는 24시간 동안 유효합니다.

웹훅 설정

약 8분

결제 결과는 API 응답만 믿지 말고 웹훅으로 한 번 더 확인하세요. 고객이 결제 도중 창을 닫거나, 카드사 승인이 늦게 오는 경우에도 웹훅은 최종 상태를 알려줍니다.

엔드포인트 등록

  1. 대시보드에서 개발자 → 웹훅 → 엔드포인트 추가를 누릅니다.
  2. 이벤트를 받을 URL을 입력합니다. 예: https://example.com/webhooks/paygrid
  3. 받을 이벤트를 고르고 저장합니다. 처음에는 payment.succeeded와 payment.failed면 충분합니다.
  4. 생성된 서명 시크릿(whsec_로 시작)을 복사해 환경 변수 PAYGRID_WEBHOOK_SECRET에 저장합니다.
payment.succeeded
결제 승인 완료
payment.failed
결제 승인 실패
payment.canceled
결제 취소 또는 전액 환불
refund.created
부분 환불 발생

서명 검증하고 이벤트 처리하기

모든 요청에는 Paygrid-Signature 헤더가 붙습니다. 원본 요청 본문(raw body)으로 서명을 검증한 뒤 처리하세요. 검증에 실패하면 400을 반환합니다.

import express from "express";
import Paygrid from "@paygrid/node";

const app = express();
const paygrid = new Paygrid(process.env.PAYGRID_SECRET_KEY);

// 서명 검증에는 파싱 전 원본 본문이 필요합니다
app.post("/webhooks/paygrid", express.raw({ type: "application/json" }), (req, res) => {
  let event;
  try {
    event = paygrid.webhooks.verify(
      req.body,
      req.headers["paygrid-signature"],
      process.env.PAYGRID_WEBHOOK_SECRET
    );
  } catch (err) {
    return res.status(400).send("invalid signature");
  }

  switch (event.type) {
    case "payment.succeeded":
      markOrderPaid(event.data.order_id);   // 주문 상태 업데이트
      break;
    case "payment.failed":
      notifyCustomer(event.data.order_id);
      break;
  }

  res.sendStatus(200);  // 10초 안에 2xx로 응답
});

app.listen(3000);
import os, paygrid
from flask import Flask, request

app = Flask(__name__)

@app.post("/webhooks/paygrid")
def paygrid_webhook():
    try:
        event = paygrid.Webhook.verify(
            request.get_data(),  # 원본 본문
            request.headers["Paygrid-Signature"],
            os.environ["PAYGRID_WEBHOOK_SECRET"],
        )
    except paygrid.SignatureError:
        return "invalid signature", 400

    if event.type == "payment.succeeded":
        mark_order_paid(event.data["order_id"])
    elif event.type == "payment.failed":
        notify_customer(event.data["order_id"])

    return "", 200  # 10초 안에 2xx로 응답

로컬에서 테스트하기

Paygrid CLI로 로컬 서버에 이벤트를 전달하고, 테스트 이벤트를 직접 보낼 수 있습니다.

터미널
# 1. 웹훅을 로컬 서버로 전달 (임시 서명 시크릿이 출력됩니다)
paygrid listen --forward-to localhost:3000/webhooks/paygrid

# 2. 다른 터미널에서 테스트 이벤트 보내기
paygrid trigger payment.succeeded
같은 이벤트가 두 번 올 수 있습니다 2xx 응답을 받지 못하면 Paygrid는 최대 3일 동안 지수 백오프로 재전송합니다. event.id를 저장해 두고, 이미 처리한 이벤트는 건너뛰세요.
