1. Git과 SSH 키

git config --global user.name  "홍길동"
git config --global user.email "gildong@company.com"
git config --global pull.rebase true

ssh-keygen -t ed25519 -C "gildong@company.com"
cat ~/.ssh/id_ed25519.pub   # 출력된 값을 Git 서버 SSH Keys에 등록

회사 메일 주소를 써야 커밋이 본인 계정에 연결됩니다.

2. 저장소 클론과 실행

git clone git@git.company.com:team/main-app.git
cd main-app

nvm install && nvm use
cp .env.example .env        # 비밀 값은 팀 비밀번호 관리자에서 받기
docker compose up -d        # DB, 캐시 등 의존 서비스
npm ci
npm run dev                 # http://localhost:3000
npm test                    # 전부 통과해야 정상

3. 에디터 설정

  • ESLint, Prettier 확장을 설치하고 저장 시 자동 포맷을 켭니다.
  • 저장소의 .editorconfig와 .vscode/extensions.json 추천 목록을 따릅니다.
  • 커밋 전 훅(husky)이 린트와 테스트를 돌립니다. 우회(--no-verify)하지 마세요.

3. 코드 리뷰 규칙

리뷰는 코드를 함께 좋게 만드는 과정이며, 사람을 평가하는 자리가 아닙니다.

작성자(PR 올리는 사람)

  • 작게 올립니다. 변경 300줄 이내, 한 PR에는 한 가지 목적만 담습니다.
  • 설명에 무엇을, 왜 바꿨는지와 테스트 방법을 적습니다. UI 변경은 스크린샷을 첨부합니다.
  • 올리기 전에 직접 diff를 한 번 읽고, CI가 통과한 뒤 리뷰를 요청합니다.
  • 작업 중이면 Draft로 올립니다.
  • 피드백에는 24시간 안에 답하고, 반영했으면 해당 코멘트에 알려 줍니다.

## 스크린샷 (UI 변경 시)

리뷰어

  • 요청을 받으면 업무일 기준 1일 이내에 첫 응답을 합니다.
  • 코드에 대해 말하고, 사람에 대해 말하지 않습니다. “이 함수는”으로 시작하세요.
  • 취향 차이보다 정확성, 가독성, 테스트, 보안을 먼저 봅니다.
  • 이유와 대안을 함께 적습니다. 좋은 부분도 짚어 줍니다.

코멘트 접두어

접두어의미머지 전 반영
[must]버그, 보안, 요구사항 위반필수
[should]강하게 권장하는 개선가급적 반영, 안 하면 이유 설명
[nit]사소한 스타일 의견선택
[question]이해를 위한 질문답변만 하면 됨

머지 조건

신입 때는 리뷰어로도 참여해 보세요. 코드를 읽는 것이 팀 코드베이스를 가장 빨리 익히는 방법입니다. 이해가 안 되면 [question]으로 물어도 좋습니다.
