flowkit
시작하기 YAML 정의 스케줄링 CLI 기능
사내 데이터 파이프라인 도구

배치 작업을 YAML로 정의하고
스케줄에 맡기세요.

flowkit은 데이터 수집, 변환, 적재 작업을 선언형 YAML 파일로 작성하고, cron 표현식으로 실행 주기를 지정하는 배치 파이프라인 도구입니다. 코드를 줄이고, 실행 이력은 한곳에서 확인하세요.

시작하기

사내 패키지 저장소에서 CLI를 설치하고, 첫 작업 파일을 검증한 뒤 실행해 보세요.

  1. CLI 설치 사내 패키지 인덱스에서 flowkit을 설치합니다.
  2. 작업 파일 작성 jobs/ 디렉터리에 YAML 파일을 만듭니다.
  3. 검증 후 실행 validate로 문법을 확인하고 run으로 한 번 실행합니다.
  4. 스케줄 등록 schedule 명령으로 주기 실행을 등록합니다. 
# 설치 (사내 패키지 인덱스)
pip install flowkit

# 작업 파일 검증
flowkit validate jobs/daily_sales.yaml

# 한 번 실행
flowkit run jobs/daily_sales.yaml

YAML로 작업 정의

하나의 파일이 하나의 배치 작업입니다. 작업 이름, 실행 주기, 재시도 정책, 단계(step)와 단계 사이의 의존 관계를 한 파일에 선언합니다. 

name: daily_sales
description: "일별 매출 집계 및 적재"
owner: data-platform

schedule:
  cron: "0 2 * * *"      # 매일 02:00
  timezone: Asia/Seoul

retry:
  max_attempts: 3
  backoff_seconds: 60
timeout_minutes: 90

steps:
  - id: extract_orders
    type: sql
    connection: warehouse
    query: "SELECT * FROM orders WHERE dt = {{ ds }}"

  - id: aggregate
    type: python
    entry: transforms/sales.py:aggregate
    depends_on: [extract_orders]

  - id: load_mart
    type: sql
    connection: mart
    query: "INSERT INTO sales_daily SELECT * FROM staging_sales"
    depends_on: [aggregate]

alerts:
  on_failure: ["#data-alerts"]

depends_on으로 단계 간 순서를 정하면 flowkit이 방향 비순환 그래프(DAG)로 해석해 독립적인 단계는 병렬로 실행합니다. {{ ds }} 같은 템플릿 변수는 실행 날짜로 치환됩니다.

스케줄링

schedule.cron에 표준 cron 표현식을 쓰거나 아래 별칭을 사용합니다. 시간대를 지정하지 않으면 사내 기본 시간대(Asia/Seoul)로 해석됩니다.

표현식의미비고
0 2 * * *매일 02:00일 단위 배치의 기본형
*/15 * * * *15분마다준실시간 적재
0 9 * * 1-5평일 09:00영업일 리포트
0 1 1 * *매월 1일 01:00월간 집계
@hourly매시 정각0 * * * *과 동일
@daily매일 자정0 0 * * *과 동일
manual자동 실행 없음CLI 또는 API로만 실행
 

# 스케줄 등록: 파일의 schedule 설정을 읽어 주기 실행을 시작
flowkit schedule jobs/daily_sales.yaml

# 등록된 스케줄 목록과 다음 실행 시각
flowkit schedule list

# 일시 중지 / 재개
flowkit schedule pause daily_sales
flowkit schedule resume daily_sales

같은 작업의 이전 실행이 끝나지 않았다면 기본적으로 새 실행을 건너뜁니다(overlap: skip). 겹쳐 실행해야 하는 경우에만 overlap: allow를 지정하세요.

CLI 요약

자주 쓰는 명령어만 모았습니다. 전체 옵션은 flowkit --help로 확인할 수 있습니다.

명령설명
flowkit validate <file>YAML 스키마와 DAG 순환 여부를 검사합니다.
flowkit run <file>작업을 즉시 한 번 실행합니다. --date로 기준 날짜를 지정합니다.
flowkit schedule <file>스케줄을 등록합니다.
flowkit logs <job>최근 실행 이력과 단계별 로그를 조회합니다.
flowkit retry <job> --run-id <id>실패한 실행을 실패 단계부터 다시 시작합니다.

주요 기능

작업 정의와 운영에 필요한 기능을 한 도구에 담았습니다.

선언형 YAML

로직은 단계 스크립트에, 흐름과 설정은 YAML에 둡니다. 코드 리뷰 대상이 명확해집니다.

의존성 그래프

depends_on으로 DAG를 구성하고, 독립 단계는 자동으로 병렬 실행합니다.

cron 스케줄링

표준 cron 표현식과 시간대 지정을 지원합니다. 일시 중지와 재개가 가능합니다.

재시도와 타임아웃

단계별 재시도 횟수와 백오프, 작업 단위 타임아웃을 설정할 수 있습니다.

실행 이력과 알림

실행 결과와 단계별 로그를 보관하고, 실패 시 지정한 채널로 알림을 보냅니다.

템플릿 변수

{{ ds }} 같은 변수로 실행 날짜와 파라미터를 쿼리와 스크립트에 주입합니다.
