02

개발 환경 세팅

macOS 기준입니다. 리눅스는 패키지 매니저 명령만 바꾸면 같습니다. 단계마다 마지막 명령이 성공하면 다음으로 넘어가세요.

  1. 기본 도구 설치

    Homebrew와 Git, 터미널 도구를 설치합니다.

    /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
brew install git gh jq mise
git --version

  2. Git 설정과 SSH 키 등록

    커밋 작성자는 회사 메일로 맞춥니다. 생성한 공개 키를 GitHub에 등록하세요.

    git config --global user.name "홍길동"
git config --global user.email "gildong@company.com"
ssh-keygen -t ed25519 -C "gildong@company.com"
gh auth login   # SSH 선택, 방금 만든 키 업로드
ssh -T git@github.com

  3. 저장소 클론

    모든 저장소는 ~/work 아래에 둡니다.

    mkdir -p ~/work && cd ~/work
git clone git@github.com:company/main-service.git
cd main-service

  4. 런타임 버전 맞추기

    저장소의 .tool-versions에 적힌 Node, Python 버전을 그대로 설치합니다.

    mise install
node -v && python --version

  5. 로컬 의존 서비스 실행

    DB와 캐시는 Docker로 띄웁니다. Docker Desktop이 실행 중이어야 합니다.

    cp .env.example .env.local
docker compose up -d postgres redis
docker compose ps
    주의 .env.local은 절대 커밋하지 않습니다. 운영 키가 필요하면 시크릿 매니저 권한을 요청하세요.

  6. 실행과 테스트

    브라우저에서 localhost:3000이 열리고 테스트가 모두 통과하면 세팅 완료입니다.

    npm ci
npm run db:migrate
npm run dev
npm test

03

코드 리뷰 규칙

리뷰는 코드를 평가하는 자리이지 사람을 평가하는 자리가 아닙니다. 아래 규칙은 모든 저장소에 똑같이 적용됩니다.

PR 작성자

리뷰하기 쉬운 PR 만들기

  • 변경은 400줄 이하로. 넘으면 PR을 나눕니다.
  • PR 하나에 목적 하나. 리팩터링과 기능 변경을 섞지 않습니다.
  • 템플릿의 "왜", "어떻게 테스트했나"를 꼭 채웁니다.
  • UI 변경은 전후 스크린샷을 첨부합니다.
  • CI가 통과한 뒤에 리뷰를 요청합니다.
리뷰어

도움이 되는 리뷰 남기기

  • 문제만 짚지 말고 이유와 대안을 같이 적습니다.
  • 댓글 앞에 아래 말머리를 붙여 중요도를 표시합니다.
  • 스타일 문제는 린터가 잡게 두고 직접 지적하지 않습니다.
  • 좋은 코드에는 좋다고 말합니다.
  • 세 번 넘게 댓글이 오가면 대화로 전환합니다.

댓글 말머리

말머리의미머지 전 처리
must:버그, 보안, 데이터 손실 위험. 반드시 수정필수
should:강하게 권장. 안 고치면 이유를 답글로 설명답변 필수
question:의도를 몰라서 묻는 질문답변 필수
nit:사소한 취향. 작성자가 판단선택
praise:잘한 부분 칭찬없음

머지 조건과 응답 시간

1영업일리뷰 요청 후 첫 응답까지
