흘러가는 로그에서
필요한 것만 바로 집계

logpipe는 로그 파일을 실시간으로 따라가며 필터링하고, 키별로 묶어 세고, 결과를 터미널에 바로 보여주는 CLI 도구입니다. tail | grep | awk | sort | uniq -c를 명령 하나로.

go install github.com/your-org/logpipe@latest
예제 보기 GitHub에서 보기 →
~/app — logpipe
$ logpipe tail app.log --where 'level=ERROR' --count-by path
path0 errors

작고 빠르고, 파이프라인에 잘 맞게

단일 바이너리 하나로, 서버에 올려두고 바로 씁니다.

tail -f

실시간 스트리밍

파일을 따라가며 새 줄을 즉시 처리합니다. 로그 로테이션도 자동으로 따라갑니다.

--where

구조 인식 필터

JSON, logfmt, 일반 텍스트를 자동 감지하고 필드 단위로 조건을 겁니다. 정규식도 지원합니다.

--count-by

즉석 집계

키별 카운트, 합계, 백분위수(p50/p95/p99)를 슬라이딩 윈도우로 계산합니다.

stdin

유닉스 친화적

stdin을 읽고 stdout으로 씁니다. kubectl logs, journalctl 뒤에 그대로 붙이세요.

-o json

여러 출력 형식

사람이 보는 표, 기계가 읽는 JSON·CSV 중 골라 다른 도구로 넘길 수 있습니다.

1 binary

의존성 없음

Go로 작성된 정적 바이너리입니다. 런타임 설치 없이 Linux·macOS·Windows에서 동작합니다.

예제

자주 쓰는 패턴 몇 가지.

ERROR 레벨 로그만 골라 엔드포인트별로 개수를 셉니다.

$ logpipe tail app.log --where 'level=ERROR' --count-by path

PATH                 COUNT
/api/orders            142
/api/payments           87
/api/users              23

최근 1분 동안의 응답 시간 백분위수를 엔드포인트별로 봅니다.

$ logpipe tail access.log --group-by path --pct latency_ms --window 1m

PATH            P50     P95     P99
/api/orders     42ms    180ms   410ms
/api/search     18ms     65ms   120ms

다른 명령의 출력을 그대로 받아서 처리합니다.

$ kubectl logs -f deploy/api | logpipe --match 'timeout|refused' --count-by host

$ journalctl -fu nginx | logpipe --where 'status>=500'

결과를 JSON으로 내보내 다른 도구에 넘깁니다.

$ logpipe app.log --where 'level=WARN' --count-by service -o json | jq .

[
  { "service": "billing", "count": 31 },
  { "service": "auth",    "count": 12 }
]

동작 방식

한 줄이 들어와서 결과가 나가기까지.

01 · read

입력

파일을 따라가거나 stdin을 읽습니다.

02 · parse

파싱

JSON·logfmt·텍스트를 필드로 나눕니다.

03 · filter

필터

조건에 맞지 않는 줄은 버립니다.

04 · aggregate

집계

키별로 세고, 합하고, 백분위를 구합니다.

05 · output

출력

표, JSON, CSV로 계속 갱신합니다.
