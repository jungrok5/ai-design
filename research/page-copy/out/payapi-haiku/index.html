빠른 시작

약 15분이면 테스트 환경에서 첫 결제를 완료하고, 결제 결과를 서버로 받아볼 수 있습니다. 아래 순서대로 진행하세요.

1 API 키 발급 테스트용 secret key 받기 2 첫 결제 요청 결제를 만들고 checkout 열기 3 웹훅 설정 결제 결과를 서버로 받기
시작 전에 준비할 것 PayAPI 계정 (가입 후 이메일 인증), 서버에서 HTTPS 요청을 보낼 수 있는 개발 환경, 그리고 예제를 실행할 Node.js 18+ 또는 Python 3.9+.
1

API 키 발급

약 3분

API 키는 PayAPI 서버에 요청할 때 본인을 증명하는 값입니다. 키는 두 종류가 있고, 처음에는 테스트 키만 사용합니다.

  1. 대시보드에 로그인한 뒤 개발자 > API 키 메뉴로 이동합니다.
  2. 테스트 모드가 켜져 있는지 확인합니다. 화면 상단에 주황색 배너가 보이면 테스트 모드입니다.
  3. Secret key 생성 버튼을 누릅니다. sk_test_로 시작하는 키가 발급됩니다.
  4. 키는 생성 직후 한 번만 전체가 표시됩니다. 바로 안전한 곳(비밀 관리자, 환경 변수 파일 등)에 저장하세요.
Secret key는 서버에서만 사용하세요 브라우저 코드, 모바일 앱, 공개 저장소에 넣으면 누구나 결제를 만들거나 환불할 수 있습니다. 키가 노출됐다면 대시보드에서 즉시 폐기(Roll)하고 새 키를 발급받으세요.

환경 변수로 저장하기

예제 코드는 키를 환경 변수 PAYAPI_SECRET_KEY에서 읽습니다. 터미널에서 한 번 설정하세요.

shell 
export PAYAPI_SECRET_KEY="sk_test_EXAMPLE"

키가 올바른지 확인하려면 계정 정보를 조회해 보세요. 200 OK가 오면 준비가 끝났습니다.

shell 
curl https://api.payapi.example/v1/account \
  -H "Authorization: Bearer $PAYAPI_SECRET_KEY"
2

첫 결제 요청

약 5분

서버에서 POST /v1/payments를 호출하면 결제 객체가 만들어지고, 응답으로 받은 checkout_url로 고객을 보내 결제를 진행합니다. 카드 번호 같은 민감한 정보는 우리 서버 대신 PayAPI의 checkout 페이지에서 입력받으므로, 가맹점 서버는 카드 정보를 다루지 않습니다.

요청 보내기

언어를 선택해 예제를 확인하세요.

curl https://api.payapi.example/v1/payments \
  -H "Authorization: Bearer $PAYAPI_SECRET_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: order_1001-attempt-1" \
  -d '{
    "amount": 15000,
    "currency": "KRW",
    "order_id": "order_1001",
    "description": "프리미엄 플랜 1개월",
    "return_url": "https://shop.example.com/checkout/done"
  }'
const res = await fetch("https://api.payapi.example/v1/payments", {
  method: "POST",
  headers: {
    "Authorization": `Bearer ${process.env.PAYAPI_SECRET_KEY}`,
    "Content-Type": "application/json",
    "Idempotency-Key": "order_1001-attempt-1",
  },
  body: JSON.stringify({
    amount: 15000,
    currency: "KRW",
    order_id: "order_1001",
    description: "프리미엄 플랜 1개월",
    return_url: "https://shop.example.com/checkout/done",
  }),
});

if (!res.ok) throw new Error(`결제 생성 실패: ${res.status}`);

const payment = await res.json();
console.log(payment.checkout_url);
import os
import requests

res = requests.post(
    "https://api.payapi.example/v1/payments",
    headers={
        "Authorization": f"Bearer {os.environ['PAYAPI_SECRET_KEY']}",
        "Idempotency-Key": "order_1001-attempt-1",
    },
    json={
        "amount": 15000,
        "currency": "KRW",
        "order_id": "order_1001",
        "description": "프리미엄 플랜 1개월",
        "return_url": "https://shop.example.com/checkout/done",
    },
    timeout=10,
)
res.raise_for_status()
print(res.json()["checkout_url"])

응답 예시

json 
{
  "id": "pay_01HZX8K3Q9",
  "object": "payment",
  "status": "requires_action",
  "amount": 15000,
  "currency": "KRW",
  "order_id": "order_1001",
  "checkout_url": "https://checkout.payapi.example/pay_01HZX8K3Q9",
  "created_at": "2026-10-22T09:00:00Z"
}

요청 파라미터

필드타입설명
amount 필수 integer 결제 금액. KRW는 원 단위 정수입니다 (예: 15000 = 15,000원).
currency 필수 string ISO 4217 통화 코드. 현재 KRW만 지원합니다.
order_id 필수 string 가맹점의 주문 번호. 같은 주문을 식별하는 값으로, 웹훅과 조회에 사용됩니다.
return_url string 결제가 끝난 뒤 고객을 돌려보낼 주소. HTTPS여야 합니다.
description string checkout 화면과 명세서에 표시되는 설명 (최대 100자).
Idempotency-Key 헤더를 붙이세요 네트워크 오류로 응답을 받지 못해 같은 요청을 다시 보내도 결제가 두 번 생성되지 않도록 막아 줍니다. 같은 키로 보낸 요청은 처음 결과를 그대로 돌려줍니다. 키는 주문 시도마다 고유한 값을 쓰세요.

고객을 checkout으로 보내기

응답의 checkout_url로 고객을 이동시키면 결제 화면이 열립니다. 결제가 끝나면 고객은 return_url로 돌아오지만, 주문 완료 처리는 이 페이지를 믿지 말고 웹훅으로 하세요. 고객이 창을 닫거나 네트워크가 끊기면 돌아오지 않을 수 있습니다.

결제 상태 흐름

requires_action → succeeded or failed or canceled

결제 객체의 status는 위 순서로 바뀝니다. 최종 상태는 웹훅 이벤트로 확인하세요.

테스트 결제 테스트 키로 만든 결제는 실제로 청구되지 않습니다. checkout에서 카드 번호로 4242 4242 4242 4242, 만료일은 미래 날짜, CVC는 아무 숫자 3자리를 입력하면 성공합니다. 실패 시나리오는 테스트 카드 목록을 참고하세요.
3

웹훅 설정

약 5분

웹훅은 결제 상태가 바뀔 때 PayAPI가 가맹점 서버의 주소로 보내는 HTTP 요청입니다. 고객이 결제 화면을 닫아도, 은행 승인이 늦게 떨어져도, 서버는 최종 결과를 받을 수 있습니다.

1) 엔드포인트 등록

개발자 > 웹훅에서 엔드포인트 추가를 눌러 주소를 등록하거나, API로 등록할 수도 있습니다. 주소는 반드시 HTTPS여야 합니다.

shell 
curl https://api.payapi.example/v1/webhook_endpoints \
  -H "Authorization: Bearer $PAYAPI_SECRET_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://shop.example.com/webhooks/payapi",
    "events": ["payment.succeeded", "payment.failed", "payment.canceled"]
  }'

응답에 포함된 secret(whsec_로 시작)은 서명 검증에 쓰는 값입니다. 이 값도 환경 변수 PAYAPI_WEBHOOK_SECRET에 저장하세요.

2) 받을 이벤트 선택

payment.succeeded 결제가 승인되어 완료됨. 주문을 "결제 완료"로 바꾸는 기준 이벤트입니다.
payment.failed 카드 거절, 한도 초과 등으로 결제가 실패함. 고객에게 재시도를 안내하세요.
payment.canceled 결제가 취소됨. 고객이 checkout을 닫았거나 가맹점이 취소한 경우입니다.

3) 서명 검증 후 처리하기

누구나 이 주소로 요청을 보낼 수 있으므로, 모든 요청은 PayAPI-Signature 헤더로 진위를 확인해야 합니다. 헤더 형식은 t=타임스탬프,v1=서명이며, 서명은 타임스탬프.원본 본문을 HMAC-SHA256으로 계산한 값입니다. JSON을 파싱하기 전의 원본 본문으로 계산해야 합니다.

Node.js (Express) 
import crypto from "node:crypto";
import express from "express";

const app = express();
// JSON 파서보다 먼저, 원본 본문을 Buffer로 받습니다.
app.post("/webhooks/payapi", express.raw({ type: "application/json" }), (req, res) => {
  const header = req.get("PayAPI-Signature") ?? "";
  const parts = Object.fromEntries(header.split(",").map(p => p.split("=")));

  // 5분 이상 지난 요청은 재전송 공격일 수 있으니 거부합니다.
  const age = Math.abs(Date.now() / 1000 - Number(parts.t));
  if (!parts.t || age > 300) return res.sendStatus(400);

  const expected = crypto
    .createHmac("sha256", process.env.PAYAPI_WEBHOOK_SECRET)
    .update(`${parts.t}.${req.body.toString("utf8")}`)
    .digest("hex");

  const a = Buffer.from(expected);
  const b = Buffer.from(parts.v1 ?? "");
  if (a.length !== b.length || !crypto.timingSafeEqual(a, b)) {
    return res.sendStatus(400);
  }

  const event = JSON.parse(req.body.toString("utf8"));

  // 같은 이벤트가 여러 번 올 수 있으므로 event.id 기준으로 멱등하게 처리하세요.
  if (event.type === "payment.succeeded") {
    markOrderPaid(event.data.order_id, event.id);
  }

  // 처리 시간이 길면 먼저 200을 응답하고 큐에서 처리하는 편이 안전합니다.
  res.sendStatus(200);
});
응답은 빠르게, 처리는 멱등하게 웹훅 수신 측은 2xx 응답을 10초 안에 돌려줘야 합니다. 그렇지 않으면 실패로 간주해 재전송합니다. 같은 event.id가 두 번 와도 주문이 두 번 결제 처리되지 않도록 DB에 처리 이력을 남기세요.

4) 재시도 정책

2xx가 아닌 응답이나 시간 초과가 발생하면 PayAPI는 다음 간격으로 최대 3일 동안 재시도합니다.

  • 1분 → 5분 → 30분 → 2시간 → 이후 매 2시간 간격
  • 대시보드 > 웹훅 > 전송 로그에서 개별 이벤트를 다시 보내거나 상태를 확인할 수 있습니다.

5) 로컬에서 테스트하기

개발 중인 로컬 서버는 외부에서 접근할 수 없습니다. 터널링 도구(예: ngrok, Cloudflare Tunnel)로 공개 HTTPS 주소를 만든 뒤, 그 주소를 웹훅 엔드포인트로 등록하세요. 테스트 키로 결제를 한 번 완료하면 payment.succeeded 요청이 도착하는지 전송 로그에서 확인할 수 있습니다.

마무리 체크리스트

  • 테스트 키(sk_test_)를 환경 변수로 저장했다
  • 서버에서 결제를 생성하고 checkout_url을 받았다
  • 테스트 카드로 결제를 완료했다
  • 웹훅 엔드포인트를 등록하고 서명을 검증한다
  • payment.succeeded 수신 시 주문 상태를 변경한다 (중복 처리 방지 포함)
