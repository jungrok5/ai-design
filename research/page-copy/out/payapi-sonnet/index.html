15분 만에 첫 결제 받기

API 키를 발급받고, 테스트 결제를 만들고, 결제 결과를 웹훅으로 받는 데까지 필요한 모든 과정을 한 페이지에 담았습니다.

⏱ 예상 소요 15분 🧰 필요한 것 가입한 계정, 터미널 💳 실제 결제는 발생하지 않습니다

1API 키 발급

모든 API 요청은 시크릿 키로 인증합니다. 처음에는 실제 돈이 오가지 않는 테스트 키로 시작하세요.

  1. 대시보드에 로그인한 뒤 개발자 → API 키 메뉴로 이동합니다.
  2. 상단 토글이 테스트 모드인지 확인합니다.
  3. 새 키 만들기를 누르고 이름(예: local-dev)을 입력합니다.
  4. 발급된 두 개의 키를 안전한 곳에 복사합니다.
키형식용도
공개 키pk_test_…브라우저·앱에서 결제창을 열 때 사용. 노출되어도 안전합니다.
시크릿 키sk_test_…서버에서 API를 호출할 때 사용. 절대 클라이언트에 넣지 마세요.
⚠ 주의

시크릿 키는 발급 직후 한 번만 전체가 표시됩니다. 코드나 Git 저장소에 직접 넣지 말고 환경 변수로 관리하세요.

.env
# 서버 환경 변수
PAYAPI_SECRET_KEY=sk_test_EXAMPLE
PAYAPI_WEBHOOK_SECRET=whsec_EXAMPLE

2첫 결제 요청

결제는 POST /v2/payments 한 번의 호출로 생성됩니다. 금액은 통화의 최소 단위(원화는 원)로 보내며, 같은 요청이 중복 처리되지 않도록 Idempotency-Key 헤더를 함께 보내는 것을 권장합니다.

curl https://api.payapi.example/v2/payments \
  -u $PAYAPI_SECRET_KEY: \
  -H "Idempotency-Key: order_20261022_0001" \
  -d amount=12900 \
  -d currency=krw \
  -d order_id=order_20261022_0001 \
  -d method=card \
  -d card[number]=4242424242424242 \
  -d card[exp]=12/30 \
  -d card[cvc]=123
import PayAPI from "@payapi/node";

const payapi = new PayAPI(process.env.PAYAPI_SECRET_KEY);

const payment = await payapi.payments.create(
  {
    amount: 12900,
    currency: "krw",
    order_id: "order_20261022_0001",
    method: "card",
    card: { number: "4242424242424242", exp: "12/30", cvc: "123" },
  },
  { idempotencyKey: "order_20261022_0001" }
);

console.log(payment.status); // "succeeded"

3웹훅 설정

가상계좌 입금, 취소, 비동기 승인처럼 요청 시점 이후에 일어나는 일은 웹훅으로 전달됩니다. 주문 상태의 기준은 API 응답이 아닌 웹훅 이벤트로 삼는 것을 권장합니다.

엔드포인트 등록

  1. 개발자 → 웹훅 → 엔드포인트 추가를 엽니다.
  2. HTTPS URL을 입력합니다. (예: https://example.com/webhooks/payapi)
  3. 수신할 이벤트를 고릅니다: payment.succeeded, payment.failed, payment.canceled
  4. 생성된 whsec_… 서명 비밀값을 PAYAPI_WEBHOOK_SECRET에 저장합니다.
💡 팁

로컬 개발 중이라면 ngrok http 3000 같은 터널링 도구로 공개 URL을 만들어 등록하세요.

서명 검증하고 이벤트 처리하기

모든 웹훅에는 PayAPI-Signature 헤더가 포함됩니다. 형식은 t=타임스탬프,v1=HMAC이며, {타임스탬프}.{원본 본문}을 비밀값으로 HMAC-SHA256 한 값과 비교해 검증합니다. 반드시 파싱 전의 원본 본문(raw body)을 사용해야 합니다.

import express from "express";
import crypto from "node:crypto";

const app = express();

// 서명 검증을 위해 raw body 유지
app.post("/webhooks/payapi", express.raw({ type: "application/json" }), (req, res) => {
  const header = req.headers["payapi-signature"] ?? "";
  const { t, v1 } = Object.fromEntries(header.split(",").map(p => p.split("=")));

  const expected = crypto
    .createHmac("sha256", process.env.PAYAPI_WEBHOOK_SECRET)
    .update(`${t}.${req.body}`)
    .digest("hex");

  const ok = v1 && v1.length === expected.length &&
    crypto.timingSafeEqual(Buffer.from(v1), Buffer.from(expected));
  // 5분 이상 지난 요청은 재전송 공격으로 간주
  const fresh = Math.abs(Date.now() / 1000 - Number(t)) < 300;
  if (!ok || !fresh) return res.sendStatus(400);

  const event = JSON.parse(req.body);
  switch (event.type) {
    case "payment.succeeded": /* 주문을 '결제 완료'로 변경 */ break;
    case "payment.failed":    /* 고객에게 재시도 안내 */ break;
  }
  res.sendStatus(200); // 2xx를 빠르게 반환
});

app.listen(3000);
import hmac, hashlib, json, os, time
from flask import Flask, request, abort

app = Flask(__name__)

@app.post("/webhooks/payapi")
def payapi_webhook():
    body = request.get_data()  # 파싱 전 원본 본문
    parts = dict(p.split("=", 1) for p in request.headers.get("PayAPI-Signature", "").split(",") if "=" in p)
    t, v1 = parts.get("t", "0"), parts.get("v1", "")

    expected = hmac.new(
        os.environ["PAYAPI_WEBHOOK_SECRET"].encode(),
        t.encode() + b"." + body,
        hashlib.sha256,
    ).hexdigest()

    if not hmac.compare_digest(v1, expected) or abs(time.time() - int(t)) > 300:
        abort(400)

    event = json.loads(body)
    if event["type"] == "payment.succeeded":
        # 주문을 '결제 완료'로 변경
        pass
    return "", 200

동작 확인과 재시도

  • 대시보드의 웹훅 → 테스트 이벤트 보내기로 즉시 전송해 볼 수 있습니다.
  • 2xx 이외의 응답이나 10초 초과 시 실패로 간주하며, 최대 24시간 동안 지수 백오프로 재전송합니다.
  • 같은 이벤트가 두 번 올 수 있으니 event.id로 중복 처리를 막으세요.

라이브 전환 체크리스트

테스트에서 모든 흐름이 확인되면 아래 항목을 점검하고 라이브 키로 교체하세요.

  • 대시보드에서 사업자 심사를 완료하고 라이브 모드를 활성화했다
  • 환경 변수의 키를 sk_live_…로 교체했고 저장소에 키가 남아 있지 않다
  • 웹훅 엔드포인트를 라이브 모드에서 다시 등록하고 새 서명 비밀값을 적용했다
  • 웹훅에서 서명·타임스탬프 검증과 event.id 중복 처리를 한다
  • 결제 요청마다 Idempotency-Key를 사용한다
